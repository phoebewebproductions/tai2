🗃️ 1.2. MODELOS Y SISTEMAS DE GESTIÓN DE BASES DE DATOS

Las bases de datos son elementos de almacenamiento de la información que representan o modelan una parte de la realidad. De esa forma, dependiendo de la orientación de esos mecanismos se tienen diferentes tipos de modelos de bases de datos.

🏗️ 1.2.1. PRINCIPALES MODELOS DE BASES DE DATOS

🌲 Modelo jerárquico

Se trata de un modelo que representa las relaciones entre las entidades involucradas de una forma similar a un árbol, es decir, de una manera basada en jerarquía tal y como su propio nombre indica.

Modelo de estructura jerárquica

Tal y como se puede observar se trata de un modelo de representación sencillo pero que presenta limitaciones en cuanto a su rigidez y capacidad de representación, dado que sólo permite representación de relaciones con cardinalidad 1 a N (un padre con varios hijos), pero no la inversa, por ejemplo (un hijo con varios padres).

Actualmente los ejemplos más significativos de bases de datos jerárquicas que pueden citarse son IMS de IBM o el Registro del sistema operativo Windows de Microsoft.

🕸️ Modelo en red

Se trata de un modelo que permite la representación de relaciones más complejas que el modelo jerárquico anterior. Las entidades se relacionan entre ellas mediante diferentes conexiones -para alcanzar un determinado nodo desde otro pueden existir varios caminos -, lo que equivale a la representación de relaciones N a M.

Modelo de estructura en red

Este modelo fue propuesto por Charles Bachman, y el estándar relacionado fue publicado en 1969 por CODASYL.

📊 Modelo relacional

La estructura relacional es, con mucha diferencia, la más extendida hoy en día. Se basa en la representación de las entidades mediante tablas que se componen de filas (tuplas) y columnas (atributos). Adicionalmente, los atributos que actúan como claves en cada una de las tablas actúa como mecanismo de relación entre ellas.

Modelo de estructura relacional

Fue concebido por el trabajador de la empresa IBM, E. F. Codd en el año 1972, basándose en conceptos de la teoría de conjuntos y la lógica de predicados.

🧊 Modelo multidimensional

Su representación es similar a la del modelo relacional, pero en lugar de las dos dimensiones mencionadas de dicho modelo filas -tuplas - y columnas -atributos-, amplía hasta N dimensiones.

Modelo de estructura multidimensional

Dadas sus altas prestaciones para casos de análisis y minería de datos han hecho de este tipo de modelo de base de datos el más popular y adecuado para el proceso analítico de transacciones en línea (OLAP: OnLine Analytical Process).

🧩 Modelo orientado a objetos

Se basa en la representación mediante objetos de las entidades propias del universo modelado. De esa forma, dichos objetos incluyen tanto los datos propiamente dichos, como capacidades computacionales a los propios objetos. Es una aproximación similar a los lenguajes de programación orientados a objetos.

Modelo de estructura orientada a objetos

⚙️ 1.2.2. SISTEMAS DE GESTIÓN DE BASES DE DATOS

En cualquier caso, con independencia del modelo de base de datos de que se trate, en todos los casos resulta necesaria la realización de una serie de tareas sobre las bases de datos. La herramienta que se encarga de realizar esas funciones es el sistema de gestión de bases de datos o SGBD.

De esa forma, como decimos, dependiendo del modelo de base de datos de que se trate, se hablará de sistema gestor de base de datos relacional, jerárquico, en red, etc., aunque en todos los casos debe incluir una serie de componentes y funcionalidades:

Administración de la base de datos y su entorno

El subsistema de administración aporta soporte para la gestión de la base de datos, en cuanto a funcionalidades tales como almacenamiento y recuperación, gestión de la seguridad (permisos, roles, etc.), optimización de consultas, control de concurrencia y gestión de cambios.

Definición y manipulación de los datos de la base de datos
  • El subsistema de definición de datos debe permitir crear y mantener el diccionario de datos y definir la estructura del fichero que soporta la base de datos.
  • El subsistema de manipulación de datos permite realizar operaciones para añadir, cambiar y borrar información de la base de datos, junto con la consulta para extraer información. El subsistema de manipulación de datos suele ser la interfaz principal del usuario con la base de datos.
  • El motor de la base de datos se encarga de recibir las peticiones de operaciones lógicas sobre la base de datos –definición y manipulación-, las convierte en un lenguaje operacional físico y accede a la base de datos y diccionario de datos en el dispositivo de almacenamiento.
Apoyo al desarrollo de aplicaciones

El subsistema de generación de aplicaciones contiene utilidades para ayudar a los usuarios en el desarrollo de aplicaciones. Usualmente proporciona pantallas de entrada de datos, lenguajes de programación e interfaces.
