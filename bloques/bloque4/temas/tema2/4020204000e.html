2.4. LENGUAJE DEL MODELO RELACIONAL

El Structured Query Language o SQL es un lenguaje declarativo de acceso a bases de datos que combina construcciones del álgebra relacional y el cálculo relacional. Actualmente es el estándar de facto de los SGBD comerciales y cumple con la anterior regla 5 de Codd.

Fue originalmente desarrollado en los años 70 del siglo pasado por IBM en su Research Laboratory de San José, a partir del cálculo de predicados creado por Codd.

Durante este tiempo sus principales hitos de desarrollo y estándares han sido los siguientes:

  • SEQUEL (Structured English QUEry Language). Creación por IBM en el año 1976.
  • SQL-86 (ANSI SQL). Versión de la American National Standards Institute. (1986).
  • SQL-89 (SQL1). Revisión del estándar el año 1989.
  • SQL-92 (SQL2). Se realiza una revisión profunda del estándar (1992).
  • SQL:1999 (SQL3). Añade disparadores junto con funcionalidad de la orientación a objetos.
  • SQL:2003. Incorpora el lenguaje XML, junto a secuencias y columnas auto-numéricas.

Las operaciones o sentencias de SQL se engloban en los diferentes tipos:

  • DDL. Sentencias de definición de datos o Data Definition Language. Engloba las operaciones de CREATE, ALTER, DROP, TRUNCATE y RENAME.
  • DML. Sentencias de manipulación de datos o Data Manipulation Language. Engloba las operaciones de SELECT, INSERT, UPDATE y DELETE.
  • DCL. Sentencias de control de la seguridad e integridad de los datos o Data Control Language. Engloba las operaciones de GRANT y REVOKE.
  • TCL. Sentencias de control de las transacciones o Transaction Control Language. Engloba las operaciones de COMMIT y ROLLBACK.

Sentencias del lenguaje SQL: Statement Query Language

2.4.1. LENGUAJES DE DEFINICIÓN DE DATOS O DDL

Los comandos del lenguaje de definición de datos -Data Definition Language o DDL- se utilizan para definir o modificar la estructura de los objetos del modelo de la base de datos:

  • CREATE. Permite la creación de nuevos objetos, tales como bases de datos, tablas, vistas o procedimientos almacenados.

    Ejemplo de creación de una base de datos: CREATE DATABASE db_curso o de creación una tabla: CREATE TABLE alumnos

  • ALTER. Permite modificar (alterar) la estructura de un cierto objeto.

    Ejemplo: Agregación de campos a una tabla: ALTER TABLE alumnos ADD edad INT, o modificación de un trigger -disparador--: ALTER TRIGGER matricula ENABLE.

  • DROP. Elimina un objeto (tabla, vista, índice, trigger, función, procedimiento o cualquier otro objeto) de la base de datos.

    Ejemplo: Eliminación de una tabla: DROP TABLE alumnos.

  • TRUNCATE. Sólo aplica a tablas y su función es borrar el contenido completo de la tabla especificada. En comparación con DELETE:
    • Es mucho más rápido, especialmente si la tabla es muy grande.
    • Sólo sirve cuando se quiere eliminar absolutamente todos los registros, ya que TRUNCATE no permite la cláusula WHERE.

    Pese a parecer una sentencia DML es DDL, ya que internamente, el comando TRUNCATE borra la tabla y la vuelve a crear, sin ejecutar ninguna transacción.

    Ejemplo: TRUNCATE TABLE alumnos.

2.4.2. LENGUAJES DE MODIFICACIÓN DE DATOS O DML

Los comandos del lenguaje de manipulación de los datos o Data Manipulation Language -DML- se utilizan para manipular los datos del modelo de la base de datos:

  • SELECT. Permite consultar los datos almacenados en una tabla de la base de datos. Su estructura básica es la siguiente: 
    SELECT [{ALL|DISTINCT}]
<nombre_campo>[, <nombre_campo>...]
FROM {<nombre_tabla>|<nombre_vista>}[,
{<nombre_tabla>|<nombre_vista>}...]
[WHERE <condición> [{AND|OR} <condición>...]]
[GROUP BY <nombre_campo>[, <nombre_campo>...]]
[HAVING <condición> [{AND|OR} <condición>...]]
[ORDER BY {<nombre_campo>|<indice_campo>} [{ASC|DESC}][,
{<nombre_campo>|<indice_campo>} [{ASC|DESC}]]];
    • SELECT. Palabra clave que identifica la sentencia de SQL de selección.
    • ALL. Indica que se seleccionarán todos los valores (por defecto, no suele incluirse).
    • DISTINCT. Indica que queremos seleccionar solo los valores distintos.
    • FROM Indica la tabla (o tablas) de las que se recuperarán los datos.
    • WHERE. Especifica la condición a cumplir por los datos a recuperar por la consulta. Admite los operadores lógicos AND y OR.
    • GROUP BY. Especifica la agrupación que se da a los datos. Se usa siempre en combinación con funciones agregadas.
    • HAVING. Especifica una condición que debe cumplirse para el conjunto de los datos devueltos por la consulta. Debe aplicarse siempre junto a GROUP BY y la condición debe estar referida a los campos contenidos en ella.
    • ORDER BY. Ordena (ascendente ASC o descendente DESC) el resultado de la consulta las columnas indicadas. El valor predeterminado es ASC.

    Ejemplo:

    SELECT nombre, apellidos, direccion, edad
FROM alumnos
WHERE edad > 20
ORDER BY edad DESC
  • INSERT. Agrega uno o más registros a una tabla en una base de datos relacional. En un comando INSERT la agregación se hará sobre una única tabla. Su estructura básica es la siguiente: 
    INSERT INTO tabla(columnaA, [columnaB, ...])
VALUES ('valor1', ['valor2', ...]);
    • INSERT. Palabra clave que identifica la sentencia de SQL de inserción.
    • VALUES. Especifica los valores que se insertarán.
    • El número de columnas y valores en la sentencia debe ser el mismo.

    Ejemplo:

    INSERT INTO alumnos (nombre, apellido1, apellidos2, edad)
VALUES ('pepito','perez','gonzalez', 22);
  • UPDATE. Modifica los valores de un conjunto de registros existentes en una tabla. Su estructura básica es la siguiente: 
    UPDATE table SET field1 = 'updated value' WHERE field2 = 'N';
    • UPDATE. Palabra clave que identifica la sentencia de SQL de actualización.
    • SET. Establece los campos a modificar junto con los nuevos valores para ellos.
    • WHERE. Condición que selecciona las tuplas que se modificarán con la sentencia.

    Ejemplo: UPDATE alumnos SET edad = 23 WHERE nombre='Pepito';

  • DELETE. Borra uno o más registros existentes en una tabla. Su estructura básica es la siguiente: 
    DELETE FROM tabla WHERE columna1 = 'valor1';
    • DELETE. Palabra clave que identifica la sentencia de SQL de borrado.
    • FROM. Indica la tabla (o tablas) de las que se borrarán los datos.
    • WHERE. Condición que selecciona las tuplas que se borrarán con la sentencia.

    Ejemplo: DELETE FROM alumnos WHERE edad < 18;

  • RENAME. Permite cambiar de nombre un objeto de la base de datos. Su estructura básica es la siguiente: 
    RENAME OBJECT `current_table_name` TO` new_table_name`
    • RENAME. Palabra clave que identifica la sentencia de SQL de renombrado.
    • OBJECT. Indica el tipo de objeto que se renombrará, pudiendo ser TABLE, DATABASE, COLUMN, INDEX, TRIGGER, etc.
    • TO. Establece el nuevo nombre que tomará el objeto afectado por el cambio.

    Ejemplo: RENAME TABLE `current_table_name` TO` new_table_name`;

2.4.3. LENGUAJES DE CONTROL DE DATOS O DCL

Los comandos del lenguaje de control de los datos o Data Control Language -DCL- se utilizan para manipular los datos del modelo de la base de datos:

  • GRANT. Asigna permisos a uno o varios usuarios o roles sobre para realizar ciertas operaciones sobre una base de datos. Su estructura básica es la siguiente: 
    GRANT <derecho1>, <derecho2>…
ON TABLE <nombre tabla>
TO <usuario1>, <usuario2> ...;
    • GRANT. Palabra clave que identifica la sentencia SQL de asignación de permisos.
    • ALL/CREATE/INSERT/UPDATE/SELECT. Tipo de permiso que se asignará.
    • ON. Identifica el objeto de la base de datos sobre el que se asignarán los permisos.
    • TO. Identifica el usuario de la base de datos al que se asignarán los permisos.

    Ejemplo: GRANT ALL/INSERT/UPDATE/SELECT ON alumnos TO user_administrator;

  • REVOKE. Retira los permisos a uno o varios usuarios o roles sobre para realizar ciertas operaciones sobre una base de datos. Su estructura básica es la siguiente: 
    REVOKE <derecho1>, <derecho2>, ...
ON TABLE <nombre tabla>
FROM <usuario1>, <usuario2> ...;
    • REVOKE. Palabra clave que identifica la sentencia SQL de retirada de permisos.
    • ALL/CREATE/INSERT/UPDATE/SELECT. Tipo de permiso que se asignará.
    • ON. Identifica el objeto de la base de datos sobre el que se asignarán los permisos.
    • TO. Identifica el usuario de la base de datos al que se asignarán los permisos.

    Ejemplo: REVOKE ALL/INSERT/UPDATE/SELECT ON alumnos TO user_administrator;

2.4.4. LENGUAJES DE CONTROL DE LAS TRANSACCIONES O TCL

Los comandos del lenguaje de control de las transacciones o Transaction Control Language -TCL- se utilizan para gestionar el estado de las transacciones que se ejecutan sobre la base de datos.

  • COMMIT. Finaliza una transacción sobre una base de datos, haciendo permanentes sus cambios sobre ella.
  • ROLLBACK. Realiza una reversión de los cambios efectuados por una transacción sobre una base de datos hasta el momento del último COMMIT. De esa forma, los cambios revertidos quedan sin efecto sobre la base de datos.
