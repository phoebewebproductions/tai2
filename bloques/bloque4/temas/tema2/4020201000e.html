📊 2.1. EL MODELO DE BASE DE DATOS RELACIONAL

🏛️ 2.1.1. ANTECEDENTES Y UN POCO DE HISTORIA

Como ya se ha comentado, el modelo relacional es, con mucha diferencia el más utilizado en la actualidad para modelar y administrar bases de datos. Fue propuesto en el año 1970 por el ingeniero Edgar Frank Codd en los laboratorios IBM en San José (California), basándose en conceptos de la teoría de conjuntos y la lógica de predicados. No tardó en consolidarse como el paradigma de referencia para los modelos y sistemas de gestión de base de datos.

Como veremos su idea fundamental se basa en el uso de relaciones, que podrían considerarse en forma lógica como conjuntos de datos llamados "tuplas". En cualquier caso, cada relación puede equipararse con una tabla cuyas filas o registros, representarían tales tuplas, compuestas por atributos o campos -que serían la visión de las columnas de la tabla-.

De esa forma, en este modelo, frente a otros como el jerárquico o el de red, el lugar y la forma en que se almacenen los datos no tienen relevancia, lo que aporta ciertas ventajas.

Finalmente, la información puede ser recuperada o almacenada mediante consultas que ofrecen una amplia flexibilidad y operatividad para administrar la información contenida en la base de datos. Para ello, el lenguaje más habitual para construir estas operaciones o consultas sobre las bases de datos relacionales es el SQL -Structured Query Language- cuyas principales características veremos.

🧩 2.1.2. PRINCIPALES ELEMENTOS Y CONCEPTOS DEL MODELO RELACIONAL

📋 2.1.2.1. ELEMENTOS BÁSICOS DEL MODELO RELACIONAL

Los principales elementos del modelo relacional son los que se presentan a continuación.

Elementos básicos del modelo relacional

Relación

Se trata de la estructura básica del modelo y representa cada una de las entidades del universo del discurso de la información de que se trate. Se modela mediante una tabla de dos dimensiones (filas y columnas). En la imagen de ejemplo anterior tenemos la relación (o tabla) PELICULA.

Atributo

Representa cada una de las propiedades de la relación y se equipara con las columnas de la tabla que representa la relación. El número de atributos que tiene una relación, o lo que es lo mismo, el número de columnas de la tabla correspondiente, recibe el nombre de grado. En la imagen de ejemplo anterior tenemos que la relación (o tabla) PELICULA tiene grado 3, contando con los atributos TÍTULO, AÑO y DURACIÓN.

Tupla

Se trata de cada una de las ocurrencias de los atributos de una relación y se identifica con cada una de las filas de la tabla que representa la relación. El número de tuplas que contiene una tabla, o de ocurrencias de los atributos de una relación, recibe el nombre de cardinalidad de dicha relación. En la imagen de ejemplo anterior tenemos que la relación (o tabla) PELICULA tiene cardinalidad 4, contando con 4 las ocurrencias.

Dominio

Define el espacio para los posibles valores que puede tomar un determinado atributo. En la imagen de ejemplo anterior tenemos que los atributos de la relación (o tabla) PELICULA tienen diferentes dominios: texto para el TÍTULO, valores de años para el atributo AÑO o un valor numérico entero para el campo DURACIÓN.

⚠️ 2.1.2.2. EL VALOR NULO (NULL) EN EL MODELO RELACIONAL

Con independencia del dominio del atributo de que se trate, en el modelo relacional debe existir un valor de uso especial, se trata del valor nulo o null. Este valor, no debe equipararse con un cero ni con un blanco, sino que significa que el valor particular para un determinado atributo es desconocido o no está disponible en ese momento dado.

De esa forma, como veremos, una de las 13 reglas de Codd, la regla del tratamiento sistemático de valores nulos establece que el sistema de gestión de base de datos debe permitir la existencia de campos con valores nulos, como representación de información que no disponible o inaplicable que sea sistemática y distinta de todos los valores regulares (no son valores blancos o ceros).

Finalmente, como también se verá, las reglas de integridad que buscan asegurar la corrección, consistencia y coherencia de los datos del modelo, harán que este valor no resulte admisible en algunas situaciones (en las claves primarias).

🔑 2.1.2.3. ATRIBUTOS CLAVE EN EL MODELO RELACIONAL: IDENTIFICACIÓN DE TUPLAS

Adicionalmente, las relaciones cuentan con claves o identificadores, que identifican las tuplas, marcando una dependencia funcional del resto de los atributos con ellas.

Clave candidata

Cada uno de los conjuntos de atributos (ya sean formados por uno sólo o una concatenación de varios de ellos) que identifica de manera unívoca y mínima a cada una de las tuplas de una relación. Lógicamente, las claves candidatas, para poder identificar unívocamente una relación, no pueden contener valores nulos.

Por ejemplo, en la siguiente relación Empleados_Centros que almacena los empleados de cada centro, el atributo único Id_Empleado es clave candidata, puesto que identifica a cada una de las tuplas.

Relación que incluye redundancia de datos

Superclave

Es aquel atributo o conjunto de atributos concatenados que identifican de manera única a las tuplas de una relación.

Clave primaria (o primary key)

Es la clave elegida entre las llaves candidatas. El criterio de selección marca elegir aquella que sea más sencilla, contando con el menor número de atributos posible.

Clave secundaria

Se trata del resto de las llaves candidatas, en caso de existir, que no son elegidas como clave principal de la relación.

Clave foránea (o foreign key)

Se trata de un atributo, ya sea simple o compuesto, de una relación que está definido en el mismo dominio que la clave primaria de otra relación.
