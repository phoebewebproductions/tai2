2.1.2 SERVICIOS DE INTERNET

Internet ofrece toda una variedad de servicios a los usuarios, tales como el correo electrónico, la web, los grupos de noticias o la transferencia de ficheros. Todos estos servicios permiten la publicación e intercambio de información entre los ordenadores conectados a la red y entre los usuarios que los utilizan.

Además de los dos protocolos básicos de Internet comentados anteriormente, TCP/IP, cada servicio de Internet tiene asociado uno o varios protocolos que utilizan los ordenadores para intercambiar la información asociada al mismo. De esta forma es posible diferenciar en la red el tipo de servicio transmitido.

En este apartado trataremos: Formas de acceso a Internet, la arquitectura cliente-servidor típica de aplicaciones web, el sistema DNS que hace posible la resolución de nombres de dominio en direcciones IP y los principales servicios de Internet.

2.1.5 DOMAIN NAME SYSTEM (DNS)

En este apartado veremos: Objetivo del DNS, identificadores URI, TLD y dominio in-addr.arpa, nombres DNS (FQDN y CNAME), clientes dns, servidores dns, funcionamiento dns.

2.1.5.1 Objetivo

En Internet, los datagramas viajan gracias al protocolo IP. Dicho protocolo funciona mediante direcciones IP, esto es, un conjunto de números que especifican de forma unívoca el destino al que deseamos enviar el datagrama. Sin embargo y de forma general, todos estamos acostumbrados a utilizar nombres para identificar a los destinos (www.google.es, www.netflix.com etc.)

Estos nombres, dominios en el argot técnicos, son sencillos de recordar pero deben ser convertidos en las direcciones IP que es lo que reconocen los dispositivo de enrutamiento (router de nivel 3). Para cumplir con esta función se desarrolló el servicio de nombres de dominio (Domain Name Server). El DNS es un servicio de tipo cliente-servidor situado en el nivel de aplicación de la pila TCP/IP que permite convertir el nombre de cualquier ordenador en su dirección IP y viceversa.

El DNS se basa en tres componentes fundamentales:
Un plan de atribución de nombres con estructura de árbol invertido (dominios del DNS)
Un protocolo basado en TCP y UDP (DNS usa TCP para la transferencia de zona y UDP para el nombre, y consulta normal y/o inversa). Puerto 53.
Un conjunto de servidores conectados a Internet que cooperan proporcionando un servicio ininterrumpido.

Estos fundamentos están descritos en las RFC 1034 y 1035.

2.1.5.2 Atribución de nombres
2.1.5.2.1 URI

En Internet, para que un recurso esté accesible (páginas web, imágenes, servicios etc) se tiene que identificar mediante:

URI
Uniform Resource Identifier es una cadena de caracteres que identifica los recursos de una red de forma unívoca. Un URI puede tener tres sabores: Puede ser un localizador de recursos uniforme (URL), un uniform resource name (URN) o ambos. En el argot cotidiano solemos (mal)denominarlo "URL".
URL
Uniform Resoure Locator es una cadena de caracteres que identifica dónde está un recurso y puede variar en el tiempo. Es un subtipo de URI.
URN
Uniform Resource Name es una cadena de caracteres que designa un recurso de forma permanente y es independiente de la ubicación. Es un subtipo de URI.
Composición de un URI:
https://www.ejemplo.com:8080/ruta/pagina.html?parametro=valor#seccion
Esquema
https://
Nombre que se refiere a una especificación para asignar los identificadores, e.g. urn:, tag:, cid:. En algunos casos también identifica el protocolo de acceso al recurso, por ejemplo http:, mailto:, ftp:, etc.
Autoridad
www.ejemplo.com:8080
Elemento jerárquico que identifica la autoridad de nombres (por ejemplo www.google.com).
Ruta
/ruta/pagina.html
Información organizada en forma jerárquica, que identifica al recurso en el ámbito del esquema URI y la autoridad de nombres (e.g. /domains/example).
Consulta
?parametro=valor
Información con estructura no jerárquica (usualmente pares "clave=valor") que identifica al recurso en el ámbito del esquema URI y la autoridad de nombres. El comienzo de este componente se indica mediante el carácter '?'.
Fragmento
#seccion
Permite identificar una parte del recurso principal, o vista de una representación del mismo. El comienzo de este componente se indica mediante el carácter '#'.
2.1.5.2.2 Principios básicos de los dominios DNS
La jerarquía DNS tiene forma de árbol invertido. El nodo raíz se denomina dominio raíz y se representa con punto al final de una URI (ej, www.terra.es.)
Los nodos de cada uno de los niveles inferiores recibe el nombre de dominio si nos referimos a él de forma independiente o subdominio si nos referimos de forma relativa al dominio de nivel superior, existiendo una relación parental entre ellos. Si bien el nombre de un dominio debe ser único entre los hijos de un mismo padre, no necesita serlo entre los demás.
Para fijar la posición del dominio en el árbol, añadimos a la derecha de su nombre los sucesivos nombres que vamos encontrando recorriendo el árbol hacia arriba, separados por el carácter ".", hasta llegar a la raíz, dominio que recibe el nombre de ".". Dentro de la jerarquía, los nodos finales del árbol corresponden a los nombres de las máquinas.
El nombre completo de un cliente DNS (Full Qualified Domain Name), comienza con el nombre del ordenador, luego el subdominio y dominio para terminar con el dominio de nivel superior. Todos separados por puntos. Muchas veces los nombres no se ponen completos, solamente el nombre del ordenador o el alias (CNAME). En ese caso, el sistema añade el nombre de dominio por defecto al nombre de host que hemos puesto.
Bajo el dominio raíz, se encuentran los dominios de alto nivel o TLD (Top Level Domain). Todas los demás dominios cuelgan de éstos. La resolución de los dominios de alto nivel (gTLD y ccTLD) se realiza mediante los servidores raíz. Hay 13 repartidos mundialmente. Se identifican por una letra, comenzando por la "A" hasta la "M". En realidad, cada letra, no es un servidor, sino un grupo de ellos, que actúan como uno solo. Uno de los nodos se encuentra en Madrid, y es el que utilizamos si estamos ubicados aquí.
gTLD

Generic Top Level Domain: Nombres de dominio de uso general, de uso específico o instituciones (desde el 2010 ICANN tiene un proyecto para llevar los gTLD a más de 1000). Originalmente tenían 3 letras, pero actualmente se admiten más.

Tipos:

  • gTLD sin restricciones: Cualquier propósito y por cualquiera. Ej: .com, .net y .org
  • gTLD con restricciones: Cualquier propósito, pero uso restringido a un colectivo determinado. Ej: .biz, .name
  • gTLD genéricos patrocinados: Propósito determinado, y para un colectivo determinado. Ej:.edu, .cat, .gob
ccTLD / tTLD

Country Code Top Level Domain: Nombres de dominios reservados a países. Compuestos de 2 a 3 caracteres. Son elegibles. No tienen que estar escritos necesariamente en latín.

Test TLD: Para experimentación y testeo. Ejemplos test., example.org, localhost.

in-addr.arpa

Dominio de resolución inversa: Dentro de la jerarquía de árbol invertido se resuelve el problema de encontrar una dirección IP a partir de un nombre, pero ¿cómo se puede encontrar el nombre que corresponde a una dirección IP?.

Para resolverlo, se creo el TLD "in­addr.arpa", llamado dominio inverso y cuya jerarquía se forma desglosando la dirección IP en 4 bytes (o sea su representación decimal) para formar una "representación in-addr.arpa".

Ejemplo de resolución inversa:

192.168.1.1
→
1.1.168.192.in-addr.arpa
2.1.5.3 Cliente DNS

Un cliente DNS es la parte que envía una consulta a un servidor DNS. Hay de dos tipos:

Usuarios iniciales
Aquellos que lanzan consultas recursivas (aquellas que exigen una respuesta completa)
"Resolver"
Son servidores DNS que actúan como clientes DNS de otros servidores. Lanzan consultas iterativas (aquellas que esperan "la mejor respuesta").
Principios de funcionamiento del cliente DNS:

En sistemas UNIX, el funcionamiento del cliente DNS se basa en tres ficheros, hosts, host.conf y resolv.conf:

/etc/hosts
Hace las veces de hosts.
/etc/host.conf
Indica, entre otros valores, el orden en que deben utilizarse las posibilidades disponibles para la resolución de los nombres.
/etc/resolv.conf
Indica el dominio al que pertenece el ordenador en el que está alojado y las direcciones IP de los servidores de nombres a los que pueden efectuarse las consultas.
2.1.5.4 Servidor DNS

El servidor DNS es el que se encarga de dar respuesta a las consultas lanzadas por el cliente DNS.

El servidor más común que se emplea para DNS es BIND (Berkeley Internet Name Domain, anteriormente: Berkeley Internet Name Daemon), especialmente en sistemas Unix, en los cuales es un estándar de facto. La versión actual es BIND9.

Las RFC 1034 y 1996 definen 3 tipos de servidores DNS según su naturaleza:

Servidores maestros o primarios (master servers)

Son servidores de autoridad de zona (esto significa que se puede confiar en la información almacenada para la zona a diferencia de los servidores caché) y mantienen los archivos originales de los archivos de zonas que se envían a otros servidores (esclavos) mediante las llamadas "transferencias de zonas".

Es el servidor sobre el que se realizan los cambios en los registros DNS.

Mediante el procedimiento NOTIFY se informa a los "esclavos" de que se ha producido un cambio. Entonces, los esclavos deben hacer una solicitud al primario para "descargarse" los cambios.

Servidores secundarios o esclavos (slave servers)

Son servidores de autoridad de zona y actúan como "espejos" de los primarios.

Tanto primario como secundarios se reparten el trabajo de atender las solicitudes DNS.

Cuando recibien un NOTIFY de cambios por parte de los primarios solicitan recuperar estos cambios para actualizar sus archivos de zona porque no está permitido reescribir directamente sobre los mismos.

Servidores caché

No son servidores de autoridad de zona.

Su cometido es el almacenamiento de conjuntos de registros de distintas zonas/dominios que obtiene consultando a los correspondientes servidores de autoridad tras búsquedas recursivas.

La información conseguida se almacena localmente de forma temporal (caché) y se renueva periódicamente.

El parámetro TTL (Time To Live) define por cuánto tiempo el caché guarda la respuesta del DNS. TTL puede variar de segundos a días o hasta semanas.

2.1.5.5 Zonas DNS

Según el IETF: "Una zona DNS es la base de datos completa de un área concreta del espacio de nombres de dominio. Estos datos se denominan autoritativos."

Una zona DNS es una parte del espacio de nombres de DNS que gestiona una organización concreta o una persona específica.

2.1.5.6 Funcionamiento servicio DNS
Proceso de resolución DNS
1
El cliente solicita la resolución de un nombre de dominio
2
El resolver DNS local busca en su caché
3
Si no está en caché, consulta a los servidores raíz
4
Los servidores raíz indican los servidores TLD
5
El resolver consulta a los servidores TLD
6
Los servidores TLD indican los servidores autoritativos
7
El resolver consulta a los servidores autoritativos
8
Los servidores autoritativos devuelven la dirección IP
9
El resolver almacena la respuesta en caché y la devuelve al cliente

Seguridad en las consultas DNS:

DNS no se concibió sobre un principio de refuerzo de la seguridad. El proceso de comunicación entre cliente y servidor se lleva a cabo sin cifrar. Para mejorar la seguridad de las comunicaciones, el IETF ha impulsado la definición de nuevos protocolos DNS más seguros:

DoT (DNS mediante TLS)
Es un protocolo de seguridad para cifrar y ajustar las consultas y respuestas del sistema de nombres de dominio (DNS) a través del protocolo de seguridad de la capa de transporte (TLS). Aumentar la privacidad y la seguridad del usuario mediante la prevención de escuchas ilegales y la manipulación de los datos del DNS a través de ataques de intermediario ("man in the middle"). Puerto TCP 853.
DoH (DNS mediante HTTPS)
Es un protocolo de seguridad para realizar una resolución remota del sistema de nombres de dominio (DNS) a través del protocolo HTTPS. Puerto TCP 443.
2.1.6 PRINCIPALES SERVICIOS DE INTERNET

Se puede entender Internet como un conjunto de servicios de acceso a la información. Las siguientes imágenes condensan los principales servicios, para qué sirven, a qué tipo de información permiten acceder y qué protocolo subyace como mecanismo de funcionamiento:

World Wide Web (WWW)
Sistema de distribución de documentos de hipertexto interconectados y accesibles a través de Internet.
Protocolo: HTTP/HTTPS
Puerto: 80/443
Correo Electrónico
Servicio que permite el intercambio de mensajes entre usuarios.
Protocolos: SMTP, POP3, IMAP
Puertos: 25 (SMTP), 110 (POP3), 143 (IMAP)
FTP (File Transfer Protocol)
Protocolo de red para la transferencia de archivos entre sistemas conectados a una red TCP.
Protocolo: FTP/FTPS/SFTP
Puerto: 21 (control), 20 (datos)
DNS (Domain Name System)
Sistema de nomenclatura jerárquico descentralizado para dispositivos conectados a redes IP.
Protocolo: DNS
Puerto: 53
Streaming
Distribución digital de contenido multimedia a través de una red de computadoras.
Protocolos: RTMP, HLS, DASH
Puertos: Varios
VoIP (Voice over IP)
Grupo de recursos que hacen posible que la señal de voz viaje a través de Internet.
Protocolos: SIP, H.323
Puertos: 5060 (SIP), 1720 (H.323)
P2P (Peer-to-Peer)
Red de ordenadores en la que todos o algunos aspectos funcionan sin clientes ni servidores fijos.
Protocolos: BitTorrent, eDonkey
Puertos: Varios
Chat y Mensajería Instantánea
Comunicación en tiempo real entre dos o más usuarios a través de Internet.
Protocolos: XMPP, IRC
Puertos: 5222 (XMPP), 6667 (IRC)
2.1.7 DESIGNACIONES DE LOS PROTOCOLOS DE INTERNET

IANA, en cooperación con la Internet Engineering Task Force (IETF), gestiona los números y las designaciones para los protocolos de Internet. Los protocolos de red y sus parámetros definen el lenguaje que permite a los ordenadores comunicarse entre sí y con otros dispositivos. A este conjunto de parámetros pertenecen:

Números de puerto

El uso de puertos permite asignar paquetes de datos de Internet a una aplicación concreta. Con ellos se efectúa el intercambio de datos a través de los protocolos UDP (User Datagram Protocol) y Transmission Control Protocol (TCP). Cada ordenador dispone de 65536 puertos. A los puertos que la IANA reconoce se les asigna un número del 0 al 65535 y se dividen en diferentes categorías.

0-1023
IANA reserva los primeros puertos, del 0 al 1023, para determinados servicios y fines. Si, por ejemplo, recibes un correo, este llegará a través del puerto reservado para los correos, este es, el 25. Para navegar en Internet se usa el puerto 80.
1024-49151
IANA también se encarga de gestionar los puertos con números del 1024 al 49151, que pueden ser usados libremente por programas.
49152-65535
Puertos dinámicos o privados, utilizados temporalmente por aplicaciones cliente cuando se comunican con servidores.
