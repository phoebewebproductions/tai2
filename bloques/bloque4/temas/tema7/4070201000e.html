2.1 EL MODELO TCP/IP

TCP/IP es un conjunto de protocolos que permiten la comunicación entre los ordenadores pertenecientes a una red.

Fue creado por Vinton Cerf y Robert E. Kahn (conocidos como los "Padres de Internet") en la década de 1970 y fue adoptado como protocolo de comunicaciones provisional (mientras se acababa de definir el modelo OSI) en la red ARPANET.

El Departamento de Defensa de EEUU exigió el uso de TCP/IP en todas sus adquisiciones de software. Teniendo en cuenta que en aquella época, el DOD era el mayor consumidor de software del mundo, la imposición de TCP/IP creó un mercado enorme potenciando un ecosistema de aplicaciones, instituciones y empresas que debían implementarlo para poder trabajar con el DOD.

La necesidad apremiante de comunicación junto con la operatividad contrastada, robustez y madurez demostrada por el modelo TCP/IP hizo que se expandiera rápidamente.

Cuando finalmente la especificación definitiva OSI salió a la luz, muchas empresas se plantearon la disyuntiva entre dejar el modelo TCP/IP probado de forma satisfactoria durante años y adoptar el nuevo modelo OSI que prácticamente sólo existía en papel (su penetración en el mercado era ínfima). Está bastante claro a favor de qué modelo se decantaron las empresas….

Estructura del Modelo TCP/IP

El modelo TCP/IP también reconoce que la tarea de comunicación es muy compleja como para realizarla en una unidad, por lo que la descompone en varios módulos o entidades.

Otro de los motivos que beneficia a TCP/IP frente a OSI es que TCP/IP es más flexible. OSI si requiere que se implementen todas las capas (aunque no sean necesarias), TCP/IP no obliga a implementar todas las capas. Por ejemplo hay protocolos de aplicación que operan directamente sobre IP.

No hay un modelo de protocolos TCP/IP oficial por lo que a veces se habla del Modelo del DoD para referirse al modelo comúnmente aceptado. Aunque el modelo DoD establece 4 capas suele ser útil considerar que el modelo está dividido en 5 (incluyendo una capa física separada de la capa de acceso al medio).

3.3 CAPA DE INTERNET

Encargada de encaminar los datos desde el equipo origen al equipo destino a través de una o más redes conectadas por dispositivos de enrutamiento.

Los protocolos de ésta capa son IP, ICMP y GRE

Protocolos principales:
IP (Internet Protocol)
Protocolo de enrutamiento de paquetes
IPv4
Direcciones de 32 bits (ej. 192.168.1.1)
IPv6
Direcciones de 128 bits (ej. 2001:0db8:85a3:0000:0000:8a2e:0370:7334)
ICMP (Internet Control Message Protocol)
Protocolo para enviar mensajes de error y control
GRE (Generic Routing Encapsulation)
Protocolo para encapsular paquetes de un protocolo dentro de paquetes de otro protocolo
3.4 CAPA DE ACCESO A LA RED

Define la interfaz lógica en un sistema final y una subred. Protocolos en la capa acceso a la red/física son PPP, ARP, Ethernet

Protocolos principales:
Ethernet
Tecnología de redes de área local
PPP (Point-to-Point Protocol)
Protocolo para establecer conexión directa entre dos nodos
ARP (Address Resolution Protocol)
Protocolo para encontrar la dirección física (MAC) que corresponde a una dirección IP

3.6 FUNCIONAMIENTO DE TCP/IP

El funcionamiento se realiza típicamente a través de los dos protocolos principales (aunque no los únicos):

TCP

Define cómo las aplicaciones crean canales de comunicación a través de una red. Gestiona cómo los datos son divididos en paquetes/datagramas más pequeños antes de transmitirse por la red, y cómo unirlos de nuevo cuando son recibidos por el otro extremo.

TCP sólo se implementa en los sistemas finales.

IP

Define cómo direccionar y enrutar cada paquete a través de la red para llegar al dispositivo de destino. Los routers o gateways intermedios revisan la dirección destino de cada paquete, para enrutarlo por el enlace adecuado. Cada equipo en internet tiene que tener una dirección ip única para poder recibir y transmitir información y a su vez, cada proceso dentro de un equipo tiene que tener una dirección única (dirección de puerto).

Esto permite al protocolo extremo-a-extremo entregar los datos al proceso adecuado. IP se implementa en todos los sistemas finales y dispositivos de encaminamiento.
