4.1 PROTOCOLO TCP (TRANSMISSION CONTROL PROTOCOL)

Protocolo estandarizado de transmisión de datos entre distintos participantes de una red informática.

La primera versión fue publicada en el año 1973 por los informáticos Robert E. Kahn y Vinton G. Cerf.

En 1981 se estandarizó con el RFC 793.

Se ha ido ampliando y mejorando aunque el núcleo del protocolo se mantiene sin cambios.

La versión actual, publicada en el RFC 7323 es del año 2014.

Características Principales
Orientado a la conexión
Establece una conexión antes de transmitir datos, garantizando que ambos extremos estén preparados.
Comunicación recíproca
Permite una comunicación bidireccional entre dos puntos terminales mediante el denominado triple apretón de manos.
Fiable
El protocolo garantiza que se transmiten todos los datos de forma íntegra y que el receptor pueda recomponerlos en el orden correcto. Detecta y resuelve la pérdida de datos.
Segmentación
Envía los datos en segmentos individuales con un tamaño máximo de 1500 bytes (incluidos los encabezados).
Capa de transporte
Clasificado en la capa de transporte (capa 4) del modelo OSI.
Conjunto TCP/IP
En la mayoría de los casos, el protocolo se utiliza junto al protocolo de Internet (IP), por lo que a menudo se habla del conjunto de protocolos TCP/IP.
Tamaño de cabecera
El encabezado TCP cuenta con un tamaño por defecto de 20 bytes y pueden llegar a sumarse hasta 40 bytes de opciones adicionales.

4.1.1 TRIPLE APRETÓN DE MANOS (3-WAY HANDSHAKE)

Para poder establecer una conexión TCP válida los dos equipos deben contar con una dirección IP unívoca (IPv4 o IPv6), deben haber declarado y habilitado el puerto deseado para la transmisión de datos.

  • La dirección IP funciona como característica de identificación.
  • El puerto sirve para que el sistema operativo pueda asignar las conexiones a las aplicaciones de servidor y de cliente.

La secuencia específica para establecer una conexión con el protocolo TCP, denominada 3-Way Handshake, se compone de tres pasos:

Datos
Puerto de origen (16 bits)
Número de puerto del emisor.
Puerto de destino (16 bits)
Número de puerto del receptor.
Número de secuencia (32 bits)
Indica el primer byte de los datos de uso anexos o se envía en el contexto del establecimiento o la interrupción de la conexión. Sirve para la validación y clasificación (después de la transmisión) de los segmentos.
Número de confirmación (32 bits)
Indica el número de confirmación que espera el emisor en siguiente lugar.
Offset (4 bits)
Indica la longitud del encabezado en bloques de 32 bits para destacar el punto de inicio de los datos de uso. Dicho punto varía de segmento a segmento debido al campo variable de opciones.
Reservado (6 bits)
Según RFC 793, reservado para un uso futuro. Este campo siempre debe tener un valor igual a "0".
Flags (6 bits)
Permite activar las siguientes acciones TCP para organizar la comunicación y el procesamiento de datos:
URG
Urgente señaliza a la aplicación TCP que los datos de uso hasta el Urgent-Pointer fijado se deben procesar inmediatamente.
ACK
Junto con el número de confirmación, ACK sirve para confirmar la recepción de paquetes TCP. Si no se ha ajustado la etiqueta, el número de confirmación se convierte en inválido de forma automática.
PSH
Push sirve para facilitar un segmento TCP inmediatamente sin tener que pasar por el buffer de datos del emisor y el receptor.
RST
Reset, sirve para reestablecer la comunicación en caso de surgir algún durante la transmisión.
SYN
Mensaje de sincronización. Representa el primer paso del triple apretón de manos iniciando el establecimiento de conexión.
FIN
Finish señaliza a la contraparte que uno de los interlocutores de la comunicación ha finalizado la transmisión.
Tamaño de ventana (16 bits)
En este campo se le transmite al interlocutor de comunicación el número de bytes que el emisor está dispuesto a recibir.
Suma de comprobación (16 bits)
El protocolo es capaz de reconocer errores de transmisión de manera fiable. En este contexto, se usa la suma de comprobación, que se calcula a partir del encabezado, los datos de uso y el denominado seudoencabezado.
Urgent-Pointer (16 bits)
Urgente indica la posición del primer byte después de los datos de uso que deben tratarse con carácter urgente. Éste campo solo es válido y relevante si tiene una etiqueta URG.
Opciones (0-320 bits)
Facilita el uso de funciones TCP no pertenecientes al encabezado general. Por ejemplo permite la definición del tamaño máximo de segmento. La longitud de las opciones siempre debe ser un múltiplo de 32 bits, en caso contrario, hay que rellenar con bits cero (padding).
