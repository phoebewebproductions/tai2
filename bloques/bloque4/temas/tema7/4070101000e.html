1.1 EL MODELO OSI

El Modelo de interconexión de sistemas abiertos (ISO/IEC 7498-1) es el modelo de referencia (y teórico) creado por la Organización Internacional de Normalización (ISO) en 1980 con el objetivo de poner orden en el complejo proceso de las comunicaciones.

Durante la década de los 70 y 80 del siglo XX, cuando las redes informáticas empezaron a experimentar un enorme crecimiento tanto en tamaño como en número. En éste periodo cada fabricante creaba sus propios protocolos de conexión incompatibles con los de la competencia. La Organización Internacional de Normalización (ISO) se dio cuenta que debía crear un modelo de red estándar que pudiera ayudar a los diseñadores de red a implementar redes que pudieran comunicarse y trabajar en conjunto.

Su desarrollo comenzó en 1977 reuniendo a un subcomité para desarrollar la arquitectura. Aunque los elementos esenciales del modelo se definieron rápidamente multitud de debates y discusiones hicieron que la especificación final no estuviera disponible hasta 1984 cuando se publicó bajo el nombre de ISO 7498.

Estructura del Modelo OSI

Una de las primeras cuestiones que quedaron claras es que el proceso de comunicación es lo suficientemente complejo como para no poder abarcarlo como un todo de forma monolítica. Por lo tanto, el modelo OSI estableció dividir la comunicación en siete capas o niveles de abstracción jerarquizadas. De esta forma, el problema de la comunicación se descompone en varios subproblemas más pequeños.

Cada capa se concentra en una de las fases de la comunicación agrupando funciones comunes dentro de la misma capa para proporcionar unos servicios determinados.

Cada capa se sustenta de los servicios más primitivos ofrecidos por su capa inferior y, a su vez, ofrece sus servicios a su capa superior.

Las capas están definidas para que los cambios en una capa no impliquen cambios en otras capas.

Primitivas de Servicio

Los servicios entre capas son ofrecidos a través de las llamadas Primitivas de Servicio:

Request (Petición)
Primitiva enviada por la capa N+1 a la capa N para solicitar un servicio pasando los parámetros requeridos.
Indication (Indicación)
Primitiva devuelta a N+1 por la capa N para advertir de la activación de un servicio requerido o para indicar alguna acción iniciada por el servicio de la capa N.
Response (Respuesta)
Primitiva enviada por la capa N+1 en respuesta de una primitiva de Indicación de la capa N.
Confirm (Confirmación)
Primitiva devuelta por la capa N a la capa N+1 para reconocer o completar alguna primitiva de Petición invocada previamente.

Encapsulamiento de Datos

Cuando el dispositivo A tiene que enviar un mensaje al dispositivo B, solicita enviar el mensaje a la capa superior.

Cada capa del emisor encapsula el mensaje agregando una cabecera y, a veces, una cola hasta llegar a la capa física donde el mensaje es finalmente enviado.

Las unidades de datos que genera cada capa se denomina PDU (Protocol Data Unit: Unidad de Datos de Protocolo).

En el receptor se realiza la operación contraria, cada capa del receptor va desencapsulando el mensaje extrayendo la cabecera y cola.

Las comunicaciones entre emisor y receptor se hacen capa a capa aunque sólo la capa física tiene comunicación directa con su homóloga en el destino.

2.1 CAPA FÍSICA

Establece la interfaz física entre dispositivos y las reglas de comunicación de los bits.

Incluye los dispositivos físicos que participan en la transferencia de datos: conectores, cables, señales eléctricas, etc.

Es la capa en la que los datos se convierten en una secuencia de bits siguiendo una especificación determinada (pulsos de luz en redes de fibra, señales de radio en redes wifi, pulsos eléctricos….)

La capa física de ambos dispositivos debe consensuar además una convención de señales que permita distinguir los unos de los ceros en ambos dispositivos.

Se encarga de definir las siguientes características:
Mecánicas
Eléctricas
Funcionales: Establece la función de cada circuito de interfaz
De Procedimiento: Establece la secuencia de eventos en el intercambio del flujo de bits
Ejemplos de tecnologías y estándares:
Ethernet (IEEE 802.3)
USB
Bluetooth
WiFi
2.2 CAPA DE ENLACE DE DATOS

La capa de enlace de datos es muy similar a la capa de red, salvo que lo que hace es facilitar la transferencia de datos entre dos dispositivos ubicados en la misma red.

Se encarga de:
Descomponer los paquetes que recibe de la capa de red en paquetes mas pequeños (Tramas) si es necesario para su transmisión.
Intenta que el enlace físico sea seguro.
Proporciona los medios para activar, mantener y desactivar el enlace.
Detección y control de errores.
Ejemplos de tecnologías y protocolos:
Ethernet (MAC)
PPP
HDLC
WiFi (802.11 MAC)
2.3 CAPA DE RED

La capa de red es la responsable de posibilitar las transferencias de datos entre dos redes diferentes. Si los dos dispositivos que se comunican están en la misma red, entonces no hará falta esta capa de red. La capa de red lo que hace es fragmentar, en el dispositivo emisor, los datos de la capa de transporte en unidades más pequeñas llamadas paquetes y rearmarlos después en el dispositivo receptor.

Funciones principales:
Enrutamiento: Encaminar los datos por una ruta determinada para que lleguen a su destino.
Gestiona las prioridades
Establece la dirección de destino de un paquete.
Ejemplos de protocolos:
IP (Internet Protocol)
ICMP
OSPF
BGP
2.4 CAPA DE TRANSPORTE

Responsable de las comunicaciones de extremo a extremo entre dos dispositivos.

El servicio de transporte orientado a conexión asegura de:

Los datos se entreguen libres de errores
En orden
Sin pérdidas ni duplicaciones
Optimizar el uso de los servicios de red, proporcionando la calidad de servicio solicitada.
Ejemplos de protocolos:
TCP (Transmission Control Protocol)
UDP (User Datagram Protocol)
SCTP
2.5 CAPA DE SESIÓN

La capa de sesión es la responsable de la apertura y cierre de comunicaciones entre dos dispositivos. Ese tiempo que transcurre entre la apertura de la comunicación y el cierre de esta se conoce como sesión. La capa de sesión garantiza que la sesión permanezca abierta el tiempo suficiente como para transferir todos los datos que se están intercambiando; tras esto, cerrará sin demora la sesión para evitar desperdicio de recursos.

Proporciona los siguientes servicios:
Control del diálogo: Full Duplex, Half Duplex.
Agrupamiento: El flujo de datos se puede marcar para definir grupos de datos.
Recuperación: Estableciendo puntos de comprobación para que si ocurre algún fallo poder volver al último punto de recuperación y proseguir desde allí.
Ejemplos de protocolos:
NetBIOS
RPC
SOCKS
2.6 CAPA DE PRESENTACIÓN

Esta capa es principalmente responsable de preparar los datos para que los pueda usar la capa de aplicación definiendo el formato de los datos que se van a intercambiar con las aplicaciones.

Entre los servicios que ofrece tenemos:
Traducción (codificación) de datos
Cifrado de datos
Compresión de datos.
Ejemplos de formatos y protocolos:
SSL/TLS
JPEG, GIF, PNG
ASCII, EBCDIC
2.7 CAPA DE APLICACIÓN

Esta es la única capa que interactúa directamente con los datos del usuario. Proporciona a los programas un medio para que accedan al modelo OSI.

Las aplicaciones de software dependen de la capa de aplicación para iniciar comunicaciones. Sin embargo, las aplicaciones de software cliente no forman parte de la capa de aplicación.

Ejemplos de protocolos:
HTTP/HTTPS
FTP
SMTP
DNS

Con fines didácticos puesto que la distinción de capas ayuda a comprender los conceptos implicados en la comunicación.
