🔑 7.1. CONTROL DE LICENCIAS DE SOFTWARE

El control de licencias de software es otra de las labores fundamentales de la administración de sistemas. Consiste en asegurarse de que todo el software instalado en la empresa es legal y su uso es conforme a la licencia correspondiente.

🔐 7.1.1. SERVICIO DE ADMINISTRACIÓN DE CLAVES (KMS)

KMS (Key Management System) es un servicio utilizado para la activación de claves de volumen en la red local.

Los clientes KMS se conectan al servidor KMS (denominado host de KMS) para realizar la activación.

El host KMS debe residir en la red local y no tiene por qué ser un servidor dedicado. Normalmente es un servicio que se añade a un servidor existente que aloje otros servicios.

Un host de KMS necesita una clave que active/autentique el host de KMS ante Microsoft. Ésta clave se denomina Clave de licencia por volumen específica de cliente de Microsoft ( Ésta clave se denomina Clave de licencia por volumen específica de cliente de Microsoft (CSVLK) pero comúnmente se conoce como clave host de KMS.

Los clientes pueden ser físicos o virtuales pero para ser calificados para la activación de KMS, la red debe tener un número mínimo de equipos (denominado umbral de activaciones). Los clientes de KMS se activan solo cuando se cumple este umbral. El host de KMS cuenta el número de equipos que está solicitando activación en la red.

Cuando un cliente o servidor se pone en contacto con el host de KMS, el host agrega el identificador del equipo a su cuenta y, después, devuelve el valor de recuento actual en su respuesta. Si el recuento es bastante alto, se activará el cliente o servidor:

  • Los clientes se activarán si el recuento es de 25 o superior.
  • Los servidores y las ediciones de volumen de productos de Microsoft Office se activarán si el recuento es de 5 o superior.

KMS solo cuenta conexiones únicas de los últimos 30 días y solo almacena los 50 contactos más recientes.

Las activaciones de KMS son válidas durante 180 días (intervalo de validez de activación)

Los clientes de KMS deben renovar sus activaciones al conectarse al host de KMS al menos una vez cada 180 días para permanecer activados. Por defecto los equipos cliente de KMS intentan renovar sus activaciones cada siete días. Una vez que se renueva la activación de un cliente, el intervalo de validez de la activación vuelve a comenzar.

  • Un host de KMS instalado en un Windows Server puede activar equipos que ejecuten sistemas operativos de cliente y servidor.
  • Un host de KMS instalado en un sistema operativo de cliente Windows solo puede activar equipos que también ejecuten sistemas operativos de cliente.

La versión de Windows que usa para el host de KMS determina la versión de Windows que puede activar para los clientes de KMS.

🔑 7.1.2. CLAVES MAK (MULTIPLE ACTIVATION KEY)

Permiten activar con la misma clave un número determinado de máquinas, dependiendo de cuantas licencias hayamos comprado a Microsoft.

Necesitan ser validadas y activadas contra un servidor de activación de Microsoft, por lo que para la activación es necesario conectar el equipo a Internet. Una vez activada por primera vez, ya no es necesario volverse a conectar.

Atención con las licencias que se encuentran en Internet por precios irrisorios. Es posible que sean ilegales (pueden ser robadas o pertenecer a licencias originales destinadas a Ayuntamientos, Ministerios, colegios o cualquier otra asociación que tenga un convenio con Microsoft a través de una empresa privada y que las haya comprado por volumen). Suelen ser claves MAK pertenecientes a una misma licencia.

Microsoft es consciente del problema y puede adoptar en cualquier momento una medida para desactivarlas.

🔧 7.1.3. VAMT (VOLUME ACTIVATION MANAGEMENT TOOL)

Herramienta GUI para administrar y automatizar de forma centralizada la activación de los diferentes productos Microsoft, tanto ediciones de servidor como de cliente, así como la suite Office.

  • Es una herramienta perteneciente al Windows Assessment and Deployment Kit (Kit de evaluación e implementación de Windows).
  • Se instala en Windows Server, se descarga de forma independiente y necesita una base de datos SQL.
  • Permite utilizar claves KMS o MAK.
