5.1. DISTRIBUCIÓN DE SOFTWARE Y ADMINISTRACIÓN DE HARDWARE

5.1.1. PXE (PREBOOT EXECUTION ENVIROMENT)

Entorno para arrancar e instalar el sistema operativo en computadoras a través de una red, de manera independiente de los dispositivos de almacenamiento de datos disponibles (como discos duros) o de los sistemas operativos instalados.

Un cliente PXE puede ser un servidor, una computadora de mesa, portátil o cualquier otra máquina que esté equipada con código de arranque PXE.

El firmware del cliente trata de encontrar un servicio de redirección PXE en la red para recabar información sobre los servidores de arranque PXE disponibles. Tras analizar la respuesta, el firmware solicitará al servidor de arranque apropiado la ruta de un network bootstrap program (NBP), lo descargará en la memoria RAM del computador mediante TFTP, lo verificará, y finalmente lo ejecutará.

Si se utiliza un único NBP para todos los clientes PXE se puede especificar mediante BOOTP sin necesidad de un proxy DHCP, pero aún será necesario un servidor TFTP.

5.1.2. WDS (WINDOWS DEPLOYMENT SERVICES)

Es la versión revisada de Servicios de instalación remota (RIS: Remote Installation Services). WDS permite la implementación y configuración de sistemas operativos Windows en los nuevos clientes con una instalación basada en red sin necesidad de que los administradores visiten cada equipo o se instalen directamente desde medios de CD o DVD.

Permite un despliegue de los clientes de Windows de forma automatizada y personalizada a través de la utilización de archivos de secuencias de comandos (scripts) de instalación desatendida.

Puede realizar tareas automáticas como asignar un nombre a las máquinas de forma automática, unirlas a un dominio, agregar o quitar programas y características e instalar funciones o roles de servidor en sistemas operativos de servidor.

WDS se expande después de la instalación con guion sencillo al dar al técnico la posibilidad de capturar, almacenar y distribuir los paquetes de instalación basados en imágenes.

Es compatible con despliegues IP Multicast permitiendo a los nuevos clientes unirse a una implementación multicast ya iniciada, el propio servidor WDS ajustará la multidifusión para que cualquier cliente pueda recibir los datos que se ha "perdido" por unirse tarde.

WDS multicast usa el Protocolo Internet Estándar IGMP. WDS cuenta con soporte para sistemas x64 basados en EFI.

WDS tiene la capacidad de desplegar otros sistemas operativos, como Windows PE, Windows XP y Windows 2000, pero la instalación de estos sistemas operativos no se puede realizar con los archivos de origen o controlada con vigilancia de scripts.

WDS trabaja junto con el Preboot Execution Environment (PXE) de las máquinas cliente cargando una versión en miniatura de Windows (Windows PE) para las tareas de instalación y mantenimiento.

WDS almacena tanto las imágenes de arranque de red PXE como las imágenes del sistema operativo real que se instalarán en el equipo de destino.

Cuando hay varias imágenes de arranque disponibles, el arranque PXE a través de WDS presenta un menú de arranque para seleccionar la imagen que desee cargar.

5.1.3. WINDOWS SERVER UPDATE SERVICES (WSUS)

Rol de servidor que permite administrar de forma centralizada la distribución e instalación de actualizaciones que se publican a través de Microsoft Update a los equipos de la red.

El servidor WSUS permite controlar la distribución. Puede ser un mero controlador, ser el origen de las actualizaciones o formar parte de una cadena de distribución de actualizaciones.

La principal ventaja del WSUS es que ahorra tiempo, ancho de banda y espacio de almacenamiento porque evita que los ordenadores se tengan que conectar individualmente a servidores externos de a la organización, sino que se conectan a servidores locales.

El administrador puede determinar, en función de la configuración y seguridad de red, la cantidad de servidores WSUS que quiere que se conecten directamente a Microsoft Update.

  • Administración centralizada de actualizaciones
  • Automatización de administración de actualizaciones

El funcionamiento general de un servidor WSUS es el siguiente:

  • El administrador divide los equipos de la red en distintos grupos. Por ejemplo, servidores, equipos de desarrollo, equipos de ofimática, equipos de prueba, etc.
  • A continuación selecciona el tipo de actualizaciones a descargar en función del parque informático de la red (sistemas operativos instalados, paquetes ofimáticos, paquetes de desarrollo, servidores, etc)
  • El servidor WSUS procederá a descargar las actualizaciones y las marcará como disponibles.
  • El administrador (idealmente) evalúa las actualizaciones aprobándolas para un grupo restringido de equipos de prueba. Si todo funciona correctamente aprueba las actualizaciones para ser descargadas e instaladas en el resto de grupos de equipos de la red.
  • También se pueden configurar reglas de aprobación automática (para actualizaciones de seguridad críticas) y revisar en todo momento las actualizaciones instaladas mediante los informes generados por el WSUS.

Un paso fundamental es que los equipos cliente del WSUS deben ser configurados para que busquen las actualizaciones en el servidor WSUS de la organización en lugar de en los servidores de Microsoft Update.

Esto se hace a través de una directiva de grupo que se suele aplicar a todo el Dominio (excepto a los servidores WSUS)
