1.2 TIPOLOGÍA DE REDES LOCALES

Podemos dividir las redes locales en dos tipos: De paso de testigo y de tipo broadcast.

🔄

Redes de paso de testigo

En este tipo de redes, se controla quién tiene acceso a la red para transmitir mediante la utilización de un testigo o token electrónico, de modo que cuando un host tiene el token en su posesión, puede realizar transmisión de información.

Este token viaja de manera secuencial por todos los nodos de la red, siendo retenido por un nodo mientras realiza el envío de información, y liberado a continuación. En caso de que no tenga datos para transmitir, el host debe remitir inmediatamente el token al siguiente nodo.

✓ Acceso controlado
✓ Sin colisiones
✓ Transmisión secuencial
✓ Orden predeterminado
📢

Redes de tipo broadcast

En este tipo de redes, la información que envía cada host es recibido por todos los demás nodos, y no existe un orden determinado para el uso de la red.

✓ Acceso no controlado
✓ Posibles colisiones
✓ Transmisión a todos los nodos
✓ Sin orden predeterminado

Las soluciones más extendidas para la implementación de redes LAN son Token Ring, Arcnet y Ethernet.

1.2.1. TOKEN RING

🔄

Token Ring

La tecnología Token Ring, introducida por IBM en 1984, y posteriormente estandarizada por el IEEE como el estándar 802.5, permite la implementación de redes de área local basadas en paso de testigo con una estructura basada en anillo ("ring").

El uso de este testigo o token permite eliminar las colisiones, asegurando que sólo uno de los nodos puede transmitir en un momento dado. No obstante, en Token Ring se pueden implementar mecanismos de prioridad de acceso ("access priority") de modo que algunos nodos tengan prioridad a la hora de hacerse con el token.

Al contrario que en tecnologías broadcast tales como Ethernet, en las redes Token Ring puede darse el caso de que dos dispositivos tengan la misma dirección de nivel 2 (dirección MAC).

Componentes principales
MAU
Multistation Access Unit - Funciona de manera similar a un hub o concentrador
Lobe Cables
Cables que conectan las estaciones al MAU
Conectores
IBM Type 1, DB-9 o RJ-45

Proceso de transmisión en Token Ring

1
El token se encuentra circulando libremente por la red
2
Un host tiene datos que enviar, por tanto captura el token
3
El host envía la trama con la información (token+datos)
4
Los hosts escuchan el tráfico y el nodo destino copia el mensaje y deja pasar el token marcando el campo "Frame Status"
5
El nodo origen ve que el token ha sido marcado como leído y elimina los datos de la trama, liberando de nuevo un token para transmitir

1.2.2. ARCNET

🌟

ARCnet

ARCnet es otra tecnología LAN similar a Token Ring, que usa también la técnica de paso de testigo, y se implementa a nivel físico mediante una topología en estrella pero funciona como un anillo lógico.

ARCnet fue diseñado en 1977 por la empresa Datapoint Corporation, con la idea de establecer un protocolo LAN de propósito general, y fue el primer sistema que tuvo una amplia difusión, aunque posteriormente fue desplazado por Token Ring, y finalmente por Ethernet.

📊
Implementación

Basada en cable coaxial junto con hubs que convertían la estrella física en un anillo lógico

📏
Limitaciones

Distancia máxima de segmentos: 2000 pies (aprox. 600 metros)

🔌
Conexiones

Permitía utilizar hubs pasivos para hasta 4 conexiones

Topología lógica (anillo)

1.2.3 ETHERNET

🌐

Ethernet

Ethernet es uno de los estándares de redes más extendidos, en especial en los ámbitos de las redes de área local. Consiste en una familia de tecnologías definidas dentro de los estándares IEEE 802.2 (para la descripción del Control de Enlace Lógico o LLC) y principalmente el 802.3 (Especificaciones de Ethernet incluyendo el medio físico), y que abarcan protocolos de capa 2 y tecnologías de capa 1.

LLC (Control de Enlace Lógico)

LLC o Logical Link Control (Control de Enlace Lógico) es una subcapa perteneciente al nivel de enlace que se encarga del control del enlace lógico, lo que incluye funcionalidades de:

  • Detección y corrección de errores en la transmisión
  • Composición de las tramas
  • Gestión del direccionamiento de nivel de enlace basado en direcciones MAC
  • Control del proceso de diálogo entre los extremos

Su cabecera se compone de los campos DSAP (Destination Service Access Point) y SSAP (Source Service Access Point), que permiten la multiplexación de distintos servicios en las capas superiores, y un campo de Control de Flujo.

Preámbulo

Patrón único de unos y ceros que indica al receptor si la trama pertenece al estándar Ethernet o al 802.3.

Inicio de trama (SOF)

Sirve de apoyo para que los distintos receptores se puedan sincronizar.

Direcciones destino y origen

Direcciones MAC de la máquina que envía la trama y de la máquina destino. La de destino puede ser de broadcast y remitirse a más de un nodo.

Tipo

Describe el protocolo de capa superior que recibirá la información.

Longitud

Cantidad de bytes de datos que se incluyen a continuación.

Datos

Incluye el payload o datos a enviar. Si los datos no son suficientes para completar una trama mínima de 64 bytes, se insertan bytes de relleno hasta completarlos.

Secuencia de verificación de trama (FCS)

Valor de verificación CRC (Control de Redundancia Cíclica) de 4 bytes, que se calcula por el dispositivo emisor y se recalcula por el dispositivo receptor, y sirve para detectar tramas dañadas durante la transmisión.

Direcciones MAC

Las direcciones MAC son únicas y se componen de 48 bits, tanto para destino como para origen. Los primeros 24 bits se denominan OUI u Organizationally Unique Identifier (Identificador Único de Organización), que asigna el IEEE y es único para cada organización que quiera fabricar interfaces de red o NICs.
