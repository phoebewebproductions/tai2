4.2.2. CMIP (COMMON MANAGEMENT INFORMATION PROTOCOL)

El Protocolo de administración de información común (CMIP) es un protocolo de gestión de red que se basa en el modelo OSI (Open Systems Interconnection) y es definido en la recomendación ITU-X.711. Proporciona una implementación para los servicios definidos en CMIS (Common Management Information Service, ITU-X.710), que define el intercambio de información entre las aplicaciones de gestión de red y los agentes de gestión. CMIP/CMIS se definen en las series ITU-X.700.

CMIP funciona con otros dos protocolos de capa 7 OSI, ACSE (Association Control Service Element) y ROSE (Remote Operation Service Element). El primero gestiona asociaciones entre aplicaciones de gestión, es decir, conexiones entre agentes CMIP, y el último maneja todas las operaciones de intercambio de datos.

CMIP define la información de la gestión en términos de objetos administrados y permite tanto la modificación como las acciones sobre objetos gestionados. Se describen usando ASN.1 y los objetos son identificados por un nombre distinguido (DN), similar en concepto al directorio X.500.

Servicios de Operación en CMIP

Al igual que en el caso de SNMP, las redes gestionadas con CMIP disponen de sistemas administradores de red (NMS). Siguiendo el estándar CMIS los NMS´s disponen de los siguientes servicios de operación:

a) Create
Crear una instancia de un objeto gestionado.
➕
b) Delete
Suprimir una instancia de un objeto gestionado.
➖
c) Get
Solicitar el valor de un atributo de una instancia de un objeto gestionado.
📋
d) Cancel_Get
Cancelar una petición de GET en curso.
🚫
e) Set
Fijar el valor de un atributo de una instancia de un objeto gestionado.
✏️
f) Action
Solicitar una acción para ocurrir según lo definido por el objeto gestionado.
▶️

El agente en el dispositivo administrado puede realizar esta operación de notificación:

a) Event_Report
Enviar notificaciones o alarmas a los NMS.
🔔

CMIP también proporciona buena seguridad (autorización de la ayuda, control de acceso y registros de la seguridad) y un reporte flexible de las condiciones inusuales de la red.

4.2.3. CMOT (CMIP OVER TCP/IP)

CMOT describe una arquitectura de gestión de red usando los protocolos CMIS/CMIP del modelo OSI sobre la familia de protocolos de Internet (TPC/IP). Esta arquitectura proporciona un canal para que un gestor y una entidad de red remota intercambien información de control y monitorización.

CMOT permite utilizar los servicios avanzados de gestión de CMIP/CMIS en redes basadas en TCP/IP, combinando lo mejor de ambos mundos: la robustez del modelo OSI para gestión de red y la amplia adopción de la pila de protocolos TCP/IP.

4.2.4. NETCONF

NETCONF es un protocolo de administración de red desarrollado y estandarizado por el IETF, publicado en los estándares RFC 4741 y RFC 6241. Pertenece al grupo de estándares de Internet y proporciona mecanismos para instalar, manipular y eliminar la configuración de dispositivos de red.

Las operaciones de NETCONF se ejecutan sobre una capa sencilla de Llamada de Procedimiento Remota (RPC). El protocolo NETCONF utiliza codificación de datos basados en Extensible Markup Language (XML) para la configuración de datos así como el protocolo de mensajes. Los mensajes de protocolo se intercambian sobre un protocolo de transporte seguro.

↓

Conjunto de operaciones base para recuperar y editar los datos de configuración
↓
Capa de Mensajes

↓
Capa de Transporte Segura
Transporte seguro y confiable de los mensajes entre un cliente y un servidor (normalmente SSH)

El protocolo NETCONF puede ser conceptualmente separado en cuatro capas:

  • a) La capa de Contenido consta de datos de configuración y datos de notificación.
  • b) La capa de Operaciones define un conjunto de operaciones base para recuperar y editar los datos de configuración.
  • c) La capa de Mensajes proporciona un mecanismo para codificar llamadas de procedimiento remoto (RPCs) y notificaciones.
  • d) La capa de Transporte Segura proporciona un transporte seguro y confiable de los mensajes entre un cliente y un servidor. Normalmente esta capa se implementa con SSH.

El protocolo NETCONF ha sido implementado en dispositivos de red como routers y switches por algunos fabricantes. Una fortaleza particular de NETCONF es su soporte para cambios de configuración que utilizan transacciones que implican una elevada cantidad de dispositivos.

Operaciones de NETCONF

El protocolo define las siguientes operaciones:

<get>
Recupera configuración e información del estado del dispositivo.
<get-config>
Recupera todo o parte de los datos de una configuración especificada.
<edit-config>
Edita una configuración de datos al crear, eliminar, fusionar o reemplazar contenido.
<copy-config>
Copia una configuración entera a otra configuración.
<delete-config>
Eliminar los datos de una configuración.
<lock>
Bloquea los datos de una configuración entera de un dispositivo.
<unlock>
Libera los datos de configuración anteriormente obtenidos con la operación <lock>.
<close-session>
Pide la terminación correcta de una sesión NETCONF.
<kill-session>
Fuerza la terminación de una sesión NETCONF.
Ejemplo de Operación NETCONF
<rpc message-id="101" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <get-config>
    <source>
      <running/>
    </source>
    <filter type="subtree">
      <interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces"/>
    </filter>
  </get-config>
</rpc>

Este ejemplo muestra una solicitud NETCONF para obtener la configuración de todas las interfaces del dispositivo desde la configuración en ejecución (running).
