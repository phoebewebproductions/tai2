2.1 GESTIÓN DE USUARIOS

La gestión de usuarios es un componente fundamental en la administración de redes y sistemas informáticos. Comprende la creación, modificación y eliminación de cuentas de usuario, así como la asignación de derechos y privilegios que determinan qué operaciones pueden realizar los usuarios y a qué recursos pueden acceder.

La gestión de usuarios implica administrar las cuentas, definir los derechos sobre operaciones y asignar privilegios sobre recursos, garantizando un acceso seguro y controlado a la red.

3.1. CUENTAS DE USUARIO

Las cuentas de usuario son el modo usual de personalizar el acceso a la red. Toda persona que utilice la red debe tener una cuenta de usuario. Para que el control de este acceso sea suficientemente bueno, las cuentas deben ser personales, esto es, cada usuario debe tener su propia cuenta, que no debe compartir con otro.

La cuenta proporciona el acceso a la red y lleva asociado el perfil del usuario, con los datos necesarios para su identificación y localización. Cada sistema de gestión de red tiene unos parámetros concretos en sus cuentas de usuario, aunque forma genérica podemos destacar los siguientes:

a) Nombre o login

Es el nombre único atribuido al usuario que le sirve para identificarse en la red. Suele ser una cadena corta de caracteres.

Ejemplos de nombres de usuario
jsmith
maria.garcia
user42

b) Contraseña, clave o password

Es la cadena de caracteres que codifica una clave secreta de acceso a la red para cada usuario. La contraseña va ligada al nombre del usuario.

El usuario y la contraseña, un certificado digital o cualquier forma de autenticación en la red es lo que se conoce como credenciales de usuario.

Características de una contraseña segura
Longitud mínima (8+ caracteres)
Combinación de mayúsculas y minúsculas
Inclusión de números y símbolos
No usar información personal

c) Nombre completo del usuario

Que es una o varias cadenas de caracteres que contiene el nombre, y normalmente también los apellidos. A veces, también otros datos, como el alias, extensión telefónica, correo electrónico, puesto en la organización u oficina donde está físicamente ubicado.

Describe la fecha en que la contraseña expirará. Como norma general se recomienda establecer una clave con caducidad limitada, y se obliga a que el usuario la cambie cada cierto tiempo, como medida de seguridad para evitar accesos no deseados por robo de contraseñas.

Parte del sistema de ficheros y directorios que el usuario puede usar para almacenar sus documentos. Normalmente es la parte de la red donde el usuario accede por defecto al identificarse.

Conjunto de aplicaciones o programas que se ejecutarán cuando el usuario acceda a la red. También puede figurar aquí sus preferencias de escritorio, impresoras predeterminadas o su carpeta por defecto.

Políticas de usuario generales

Además de lo anterior, el administrador puede establecer condiciones o políticas de usuario generales, que afectan a todos los usuarios de una red. Algunas de las más usadas son:

  • Cambio de la contraseña en el siguiente inicio de sesión.
  • La contraseña no caducará nunca.
  • El usuario no puede cambiar su contraseña.
  • Desactivación de la cuenta tras un periodo de tiempo.
  • Bloqueo de la cuenta tras varios intentos fallidos de inicio de la sesión.
  • Acceso a determinadas opciones de configuración del equipo o de conexión de la red.
Ejemplo de política de bloqueo de cuenta

3 intentos

15 minutos después del último intento

Sistema Operativo Unix

En el caso del sistema operativo Unix, los argumentos de línea de comandos que se pasan al crear un usuario son:

  • -d Directorio home del usuario
  • -s Shell del usuario
  • -p Password

Ejemplo de creación de usuario en Unix
useradd -m -d /home/jsmith -s /bin/bash -g users -G wheel,developers jsmith

Usuarios especiales

Los sistemas operativos de red incluyen unos usuarios especiales con funcionalidades específicas, que normalmente no pueden ser borrados, aunque si desactivados o modificados. Entre estas cuentas se encuentran:

a) El supervisor (en Novell), administrador (en Microsoft Windows) o root (en UNIX o Linux)

Es la cuenta privilegiada por excelencia y que suele ser utilizada por el administrador del sistema.

Es una cuenta a la que normalmente no se le asocia contraseña y que carece de privilegios. Sirve para que aquellos usuarios sin cuenta en el sistema puedan acceder a los recursos mínimos. Integración con dominios o servicios de directorio

En sistemas integrados con dominios o servicios de directorio, como es el caso del Directorio Activo de Microsoft Windows, es posible crear cuentas de usuario tanto en los equipos locales como en el dominio. De forma que algunos usuarios puedan acceder sólo a recursos de la estación de trabajo local y otros a los recursos de todo el dominio. Asimismo, un mismo usuario puede disponer de cuentas tanto a nivel local como en el dominio.

Identificadores únicos de usuario

En el núcleo del sistema operativo cada usuario tiene un identificador único, normalmente numérico. En el caso de Linux es el UID (User ID). Para Microsoft Windows es el SID (Secure Identificator). Este identificador no cambia incluso si cambian las credenciales del usuario.

UID en Linux

El UID (User ID) es un número entero que identifica de manera única a cada usuario en un sistema Linux. Los UIDs por debajo de 1000 suelen estar reservados para usuarios del sistema.

Ejemplo de UIDs en Linux
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
jsmith:x:1001:1001:Juan Smith:/home/jsmith:/bin/bash
mgarcia:x:1002:1002:Maria Garcia:/home/mgarcia:/bin/bash
SID en Windows

El SID (Security Identifier) es una cadena alfanumérica única que identifica a cada usuario en un sistema Windows. El SID incluye información sobre el dominio y es más complejo que el UID de Linux.

Ejemplo de SID en Windows
S-1-5-21-3623811015-3361044348-30300820-1013

Archivos de configuración de usuarios en Unix

En el sistema Unix, la configuración de los usuarios permanece en los siguientes archivos:

a) /etc/passwd

Todas las cuentas se encuentran definidas en el archivo de configuración 'passwd', ubicado dentro del directorio /etc. Este archivo es de texto tipo ASCII, se crea al momento de la instalación con el usuario root (que tiene UID=0) y las cuentas especiales, más las cuentas de usuarios normales que se hayan indicado al momento de la instalación.

Estructura del archivo /etc/passwd
username:password:UID:GID:comment:home_directory:shell

Ejemplo:
jsmith:x:1001:1001:Juan Smith:/home/jsmith:/bin/bash
b) /etc/shadow

Anteriormente las contraseñas cifradas se almacenaban en el mismo /etc/passwd. El problema es que 'passwd' es un archivo que puede ser leído por cualquier usuario del sistema, aunque solo puede ser modificado por root. El archivo 'shadow', resuelve el problema ya que solo puede ser leído por root. Considérese a 'shadow' como una extensión de 'passwd' ya que no solo almacena la contraseña encriptada, sino que tiene otros campos de control de contraseñas.

Estructura del archivo /etc/shadow
username:encrypted_password:lastchange:min:max:warn:inactive:expire:flag

Ejemplo:
jsmith:$6$salt$hash:18144:0:99999:7:::

3.2. DERECHOS DE LOS USUARIOS Y PRIVILEGIOS

Con la determinación de los derechos de los usuarios, el administrador de la red configura las operaciones que cada usuario puede hacer en la red. Algunas de estas operaciones son el acceso remoto a equipos en la red, apagar de manera remota algún equipo, cambiar la fecha y la hora del sistema, etc.

Con los permisos o privilegios, el administrador de la red puede determinar el acceso de los usuarios a determinados recursos de la red. A diferencia de los derechos de los usuarios, que se refieren a las operaciones, los permisos están asociados a los recursos y forman parte de las propiedades de seguridad de los mismos.

Diferencia entre derechos y privilegios

Ejemplo práctico

Un operador de consola puede tener derecho a hacer una copia de seguridad sobre un disco, pero puede tener el acceso restringido a ciertos directorios porque no tiene privilegios de lectura o escritura sobre ellos.

Asignación de derechos y privilegios

Normalmente, en primer lugar se asignan los derechos sobre las operaciones que puede efectuar un determinado usuario, y a continuación se configuran los privilegios que va a tener ese usuario sobre los recursos (carpetas, directorios) en los que va a realizar estas operaciones.

1
Asignación de derechos

Se determinan las operaciones que el usuario puede realizar en el sistema.

↓
2
Asignación de privilegios

Se configuran los permisos sobre los recursos a los que el usuario puede acceder.

Configuración de privilegios

Los privilegios o permisos se configuran usando marcas sobre cada objeto, que dependen del sistema operativo, pero en general son:

  • Lectura (r): Permite ver el contenido de un archivo o directorio.
  • Escritura (w): Permite modificar o crear archivos o directorios.
  • Ejecución (x): Permite ejecutar un archivo o acceder a un directorio.
  • Borrado: Permite eliminar archivos o directorios.
  • Modificación de permisos: Permite cambiar los permisos de un archivo o directorio.
  • Toma de posesión: Permite cambiar el propietario de un archivo o directorio.
Ejemplo de permisos en Linux
Listado de directorio con permisos
drwxr-xr-x 2 jsmith users 4096 Mar 15 10:30 Documentos
-rw-r--r-- 1 jsmith users 2048 Mar 14 15:45 informe.txt
-rwxr-xr-x 1 jsmith users 8192 Mar 13 09:20 programa.sh

En el ejemplo anterior:

  • d: Indica que es un directorio
  • rwx: Permisos del propietario (lectura, escritura, ejecución)
  • r-x: Permisos del grupo (lectura, ejecución)
  • r-x: Permisos de otros usuarios (lectura, ejecución)
