2.2 PROTOCOLOS SEGUROS

2.2.1 IPSEC (INTERNET PROTOCOL SECURITY)

Se trata de un conjunto de protocolos que opera en la capa 3 del modelo OSI y cuya función es asegurar las comunicaciones sobre el Protocolo de Internet (IP) autenticando y/o cifrando cada paquete IP en un flujo de datos.

🔒

IPsec

Conjunto de protocolos que opera en la capa 3 del modelo OSI para asegurar las comunicaciones sobre IP autenticando y/o cifrando cada paquete IP en un flujo de datos.

IPsec consta de tres protocolos que han sido desarrollados para proporcionar seguridad a nivel de paquete, tanto para IPv4 como para IPv6:

Internet Key Exchange (IKE)

IKE emplea un intercambio secreto de claves de tipo Diffie-Hellman para establecer el secreto compartido de la sesión. El objetivo es generar la asociación de seguridad (SA), con el conjunto de algoritmos y parámetros necesarios para AH y ESP. IKE opera en dos fases:

1
Fase 1

Los dos extremos negocian aspectos como la función hash (MD5 o SHA1), el mecanismo de autenticación (certificados o claves compartidas), el grupo Diffie-Hellman y el algoritmo de cifrado (DES, 3DES o AES). Se intercambian las claves usando Diffie-Hellman y se autentican para finalizar estableciendo un canal seguro (túnel ISAKMP). Esta fase puede ejecutarse en modo normal o en modo agresivo.

2
Fase 2

Se usa el canal seguro anterior para establecer dos asociaciones de seguridad (SA) unidireccionales de IPSec en las que se basará la comunicación, negociando dentro del canal seguro los parámetros para cada una de ellas:

  • • Protocolo IPSec (AH o ESP)
  • • Modo de operación (transporte o túnel)
  • • Claves criptográficas
  • • Algoritmos criptográficos (DES, 3DES o AES)
  • • Tiempo de vida de las claves

Una vez finalizado IKE, se usan los protocolos AH o ESP, en sus modos de transporte o túnel, según se haya establecido en las SA.

IKEv2 - Mejoras

En la segunda versión, IKEv2, el proceso de negociación se simplifica, y además:

🔄
Necesita sólo de cuatro mensajes en la fase 1, en la versión inicial se necesitaban 8.
🧱
Incorpora mejoras para el NAT transversal, lo que permite facilitar la comunicación y traspasar firewalls en general.
📱
Hay una extensión estándar para IKEv2 llamada MOBIKE, que es utilizada para soportar movilidad y multiorigen (multihoming en inglés), especialmente para túneles IPsec. Mediante esta extensión IKEv2 e IPsec pueden ser utilizados por dispositivos móviles.
🔊
Permite el uso de SCTP para VoIP.
🔐
Tiene menos mecanismos criptográficos que IKEv1 permitiendo solamente los más seguros.

Authentication Header (AH)

Está dirigido a garantizar integridad, sin conexión y autenticación de los datos de origen de los datagramas IP. Para ello, calcula un Hash Message Authentication Code (HMAC) a través de algún algoritmo hash operando sobre una clave secreta compartida, el contenido del paquete IP y las partes inmutables del datagrama. No garantiza la confidencialidad, ya que no cifra los datos.

⚠️

Un problema con este protocolo es que no funciona bien con NAT, ya que hace el hash de la dirección IP y el número de puerto del paquete, y como estos pueden cambiar con NAT, la comprobación del hash fallará. Para que funcione es necesario habilitar un NAT transversal.

Encapsulating Security Payload (ESP)

El protocolo ESP proporciona autenticidad de origen, integridad y protección de confidencialidad de un paquete, ya que al contrario que AH sí puede cifrar los datos. ESP también soporta configuraciones de solo cifrado y solo autenticación. Al contrario que con AH, la cabecera del paquete IP no está protegida por ESP.

📝

Los protocolos AH y ESP pueden usarse conjuntamente en el mismo paquete.

Modos de funcionamiento de IPSec

IPSec dispone de dos modos de funcionamiento, que pueden ser usados en los protocolos AH o ESP:

Modo transporte

Solo la carga útil del paquete IP es cifrada o autenticada. El enrutamiento permanece intacto, ya que no se modifica ni se cifra la cabecera IP. Las capas de transporte y aplicación están siempre aseguradas por un hash, de forma que no pueden ser modificadas de ninguna manera, y no se puede traducir el número de puerto TCP o UDP. El modo transporte se utiliza para comunicaciones ordenador a ordenador.

Modo túnel

Todo el paquete IP (datos más cabeceras del mensaje) es cifrado o autenticado. Debe ser entonces encapsulado en un nuevo paquete IP para que funcione el enrutamiento. El modo túnel se utiliza para comunicaciones red a red (túneles seguros entre routers).

Los algoritmos criptográficos definidos para usar con IPSec incluyen HMAC-SHA-1 para protección de la integridad, y Triple DES-CBC y AES-CBC para la confidencialidad.

2.2.2 SSL Y TLS

SSL (Secure Sockets Layer) es un protocolo que opera en el nivel 4 del modelo OSI que proporciona autenticación y privacidad de la información entre extremos sobre Internet mediante el uso de criptografía. Normalmente funciona sobre TCP, pero también puede funcionar sobre UDP.

🔒

SSL/TLS

Protocolos que operan en el nivel 4 del modelo OSI para proporcionar autenticación y privacidad de la información entre extremos sobre Internet mediante el uso de criptografía.

El protocolo SSL intercambia registros. Opcionalmente, cada registro puede ser comprimido, cifrado y empaquetado con un código de autenticación del mensaje (MAC).

Funcionamiento de SSL

El funcionamiento de SSL implica una serie de fases básicas:

1
Opcionalmente el servidor anuncia su disponibilidad con el mensaje HelloRequest.
2
Comienza la negociación entre el cliente y el servidor, mediante un protocolo handshake, en el que el cliente (ClientHello) envía al servidor las diferentes opciones criptográficas y el servidor (ServerHello) responde con los parámetros escogidos.
3
Obtención de una clave maestra (master secret o premaster secret).
4
Todos los datos de claves restantes son derivados a partir de este master secret, y son pasados a través una función pseudoaleatoria, que los divide en dos mitades y las procesa con algoritmos hash diferentes (MD5 y SHA), después realiza sobre ellos una operación XOR.
5
Cifrado del tráfico basado en cifrado simétrico con los datos anteriores.

Durante la primera fase, el cliente y el servidor negocian qué algoritmos criptográficos se van a usar. Las implementaciones actuales proporcionan las siguientes opciones:

🔑
Criptografía de clave pública
RSA, Diffie-Hellman, DSA o Fortezza
🔒
Cifrado simétrico
RC2, RC4, IDEA, DES, TDES y AES
🔄
Funciones hash
MD5 o de la familia SHA

Incluye una serie de medidas adicionales de seguridad:

🔢
Numeración de todos los registros y uso de ese número de secuencia en el MAC.
🔐
Uso de un resumen de mensaje mejorado con una clave (de forma que solo con dicha clave se pueda comprobar el MAC).
🛡️
Protección contra varios ataques conocidos (incluyendo ataques man-in-the-middle).
✅
El mensaje que finaliza el protocolo handshake (Finished) envía un hash de todos los datos intercambiados y vistos por ambas partes.

TLS (Transport Layer Security)

TLS (Transport Layer Security) fue definido en la RFC 2246 y es una actualización de SSL versión 3. La versión actual es TLS 1.3 (RFC 8446). Introduce algunas mejoras sobre SSL, usa una nueva función pseudoaleatoria, y HMAC en vez de MAC, introduce nuevas versiones de los algoritmos de cifrado y parches contra vulnerabilidades descubiertas en SSL, particularmente:

🛡️
Defensa contra ataques CBC (ataque Poodle)
🛡️
Defensa contra ataques Beast, a partir de TLS 1.1

2.2.3 HTTPS

El protocolo seguro de transferencia de hipertexto (Hypertext Transfer Protocol Secure o HTTPS) es un protocolo de aplicación basado en el protocolo HTTP, destinado a la transferencia segura de datos de hipertexto, es decir, es la versión segura de HTTP (RFC 2818).

🔒

HTTPS

Protocolo de aplicación basado en HTTP, destinado a la transferencia segura de datos de hipertexto mediante el uso de SSL/TLS.

HTTPS usa SSL/TLS para crear un canal cuyo nivel de cifrado depende del servidor remoto y del navegador utilizado por el cliente. Es más apropiado para el tráfico de información sensible que el protocolo HTTP. De este modo se consigue que la información sensible (usuario y claves de paso normalmente) no pueda ser usada por un atacante que haya conseguido interceptar la transferencia de datos de la conexión, ya que lo único que obtendrá será un flujo de datos cifrados que le resultará imposible de descifrar.

HTTPS opera en el nivel de aplicación, por encima de SSL o TLS, que se sitúa entre HTTPS y el nivel de transporte. El puerto estándar para este protocolo es el 443.

HTTP Strict Transport Security (HSTS)

HTTP Strict Transport Security o HTTP con Seguridad de Transporte Estricta (HSTS), es una política de seguridad web establecida para evitar ataques que puedan interceptar comunicaciones, cookies, etc. Según este mecanismo un servidor web declara que los agentes de usuario compatibles (es decir, los navegadores), solamente pueden interactuar con ellos mediante conexiones HTTP seguras (es decir, en HTTP sobre TLS/SSL). HSTS es un estándar del IETF y se especifica en el RFC 6797.

2.2.4 SSTP (SECURE SOCKETS TUNNEL PROTOCOL)

El Protocolo de túnel de sockets seguros (SSTP) es una forma de túnel de red privada virtual (VPN) que proporciona un mecanismo para transportar el tráfico PPP a través de un canal SSL/TLS. SSL/TLS proporciona seguridad a nivel de transporte con negociación de claves, cifrado y comprobación de la integridad del tráfico. El uso de SSL/TLS sobre el puerto TCP 443 (de forma predeterminada, el puerto se puede cambiar) permite que SSTP pase a través de prácticamente todos los firewalls y servidores proxy, excepto los proxies web autenticados.

🔒

SSTP

Protocolo de túnel de red privada virtual (VPN) que proporciona un mecanismo para transportar el tráfico PPP a través de un canal SSL/TLS.

Ventajas de SSTP

🔒
Atraviesa fácilmente firewalls que bloquean otros protocolos VPN
🛡️
Utiliza la seguridad de SSL/TLS para la autenticación y el cifrado
🌐
Funciona a través del puerto 443, que generalmente está abierto en la mayoría de las redes

2.2.5 SSH (SECURE SHELL)

SSH es el nombre de un protocolo y del programa que lo implementa cuya principal función es el acceso remoto a un servidor por medio de un canal seguro en el que toda la información está cifrada. Además de la conexión a otros dispositivos, SSH permite copiar datos de forma segura (tanto archivos sueltos como simular sesiones FTP cifradas), gestionar claves RSA para no escribir contraseñas al conectar a los dispositivos y pasar los datos de cualquier otra aplicación por un canal seguro tunelizado mediante SSH. El puerto TCP asignado es el 22.

🔒

SSH

Protocolo que permite el acceso remoto a un servidor por medio de un canal seguro en el que toda la información está cifrada.

Usos comunes de SSH

💻
Acceso remoto a servidores
📂
Transferencia segura de archivos (SCP, SFTP)
🔑
Gestión de claves RSA para autenticación sin contraseña
🔄
Túneles seguros para otras aplicaciones

2.2.6 S/MIME (SECURE MULTIPURPOSE INTERNET MAIL EXTENSIONS)

Se trata de un estándar para la transmisión segura de correo electrónico mediante el cifrado de los mensajes con criptografía asimétrica.

✉️

S/MIME

Estándar para la transmisión segura de correo electrónico mediante el cifrado de los mensajes con criptografía asimétrica.

S/MIME incluye dos funciones de seguridad:

🔒
Email Encryption (Encriptado de correo electrónico)

Cifra el contenido del correo electrónico enviado entre dos usuarios con S/MIME para que únicamente el destinatario original pueda leerlo.

✅
Digital Signature (Firma digital)

Firma digitalmente los correos electrónicos enviados entre dos usuarios con S/MIME para eliminar cualquier riesgo de suplantación de identidad.

Funcionamiento de S/MIME

1
El emisor obtiene un certificado digital que contiene su clave pública
2
Para cifrar un mensaje, el emisor usa la clave pública del destinatario
3
Para firmar un mensaje, el emisor usa su clave privada
4
El destinatario usa su clave privada para descifrar el mensaje
5
El destinatario usa la clave pública del emisor para verificar la firma
