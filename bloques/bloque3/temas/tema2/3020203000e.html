2.3 NORMALIZACIÓN

🗃️

La normalización es una técnica de diseño de base de datos que organiza las tablas de una manera que reduce la redundancia y la dependencia de los datos.

Para realizar la normalización de bases de datos y eliminar anomalías en las tablas, se utilizan lo que se llaman formas normales. Se dice que una tabla está en una determinada forma normal si satisface un conjunto de restricciones impuestas por esa regla.

Utilizando las diferentes formas normales, se dividen tablas grandes en otras de tamaño más pequeñas, vinculadas entre sí mediante relaciones. Utilizando técnicas de normalización, se obtienen estructuras de datos más simples, estables y fáciles de mantener, además de reducir problemas de redundancia y ambigedad.

📜

Existen diferentes formas normales para una base de datos. Edgar Codd, el inventor del modelo relacional, propuso la teoría de la normalización introduciendo la primera forma normal (1NF), y posteriormente extendió esta idea con la segunda y tercera forma normal (2NF y 3NF). Con la colaboración de Raymond F. Boyce, desarrollaron la forma normal de Boyce-Codd (BCNF). Existen formas normales más allá de la de Boyce-Codd, pero desde un punto de vista práctico, la normalización suele aplicarse hasta la tercera forma normal. Una forma normal de cierto nivel debe cumplir las reglas de las formas normales de niveles inferiores.

CONCEPTOS DE DEPENDENCIA

Para describir ciertos aspectos de las formas normales se utilizan diferentes conceptos de dependencia:

🔗

Dependencia funcional

Se dice que un atributo A depende funcionalmente de otro atributo B (B determina a A) si para cada valor de B le corresponde un único valor de A. En esta situación, el atributo B es el determinante.

🔑

Determinante

Un determinante es un atributo que depende de otro atributo.

🔄

Dependencia funcional completa

Se dice que un atributo A tiene una relación de dependencia funcional completa de un grupo de atributos B si depende funcionalmente de B, pero no de ningún subconjunto de B. Es decir, que si al eliminar un atributo de una relación, esta deja de existir.

⛓️

Dependencia funcional transitiva

Dados tres atributos, A, B y C, dentro de una misma tabla, y teniendo que B depende funcionalmente de A y C dependen funcionalmente de B, se dice que C depende transitivamente de A.

🔀

Dependencia multivaluada

Se dice que un atributo B multidetermina a un atributo A si a cada valor de B le corresponde un conjunto definido de valores de A.

PASOS PARA LA NORMALIZACIÓN

El proceso de normalización puede generalizarse en los siguientes pasos:

1

Descomponer todos los grupos de datos en registros bidimensionales.

2

Eliminar las relaciones donde los datos no son completamente dependientes de la clave primaria del registro.

3

Eliminar las relaciones que tienen dependencias transitivas.

PRIMERA FORMA NORMAL (1NF)

1NF

Primera Forma Normal

La primera forma normal requiere que cada tabla de una base de datos cumpla los siguientes requisitos:

  • • Todos los atributos clave están definidos.
  • • No hay registros con más de un valor por cada columna (no contiene grupos repetitivos). Cada fila o columna contiene un valor, no un conjunto de ellos.
  • • Todos los atributos son dependientes de la clave primaria.
  • • Todos los atributos son atómicos. Un atributo es atómico si los elementos del dominio son simples e indivisibles.
  • • No existe variación en el número de columnas para cada fila.

Para convertir una tabla a 1NF, se dividen las filas que tienen varios atributos en tantas filas como atributos tenga. En la tabla anterior, encontramos varios ejemplos de filas de la tabla con varios valores. Veamos ahora dicha tabla en 1NF:

SEGUNDA FORMA NORMAL (2NF)

2NF

Segunda Forma Normal

La segunda forma normal tiene los siguientes requisitos:

  • • La tabla debe estar en 1NF.
  • • Los atributos no principales tienen dependencia funcional completa respecto de las claves candidatas. Es decir, que si alguno de los atributos desaparece, la relación entre atributos y clave también se pierde.

Para convertir una tabla a 2NF, se separa la tabla en cuantas tablas sean necesarias para eliminar dichas dependencias. En el caso de la tabla anterior, el atributo Categoría no tiene una dependencia funcional completa de la clave, ya que depende funcionalmente de Película alquilada. Podemos conseguir 2NF separando en dos tablas, y relacionando mediante una clave foránea. Para facilitar la visualización, crearemos una columna ID en la tabla que sustituirá a la tupla Nombre completo y Dirección como clave principal de la tabla.

TERCERA FORMA NORMAL (3NF)

3NF

Tercera Forma Normal

La tercera forma normal tiene los siguientes requisitos:

  • • La tabla debe estar en 2NF.
  • • Los atributos no principales no deben depender transitivamente de la clave; o lo que es lo mismo, todos los atributos de la tabla dependen solo de la clave principal.

Para convertir la tabla con la que hemos estado trabajando a 3NF, separamos el Tratamiento, ya que es una dependencia que no depende directamente de la clave principal, sino de forma transitiva a través del Nombre completo del registro. Podemos separar una tabla de Tratamientos, asignando un ID a cada tratamiento, y enlazando cada tratamiento en el registro correspondiente de la tabla de usuarios. FORMA NORMAL DE BOYCE-CODD (BCNF)

BCNF

Forma Normal de Boyce-Codd

La forma normal de Boyce-Codd es muy similar a la 3NF, pero con una restricción adicional. Tiene los siguientes requisitos:

  • • La tabla debe estar en 3NF.
  • • Los atributos no determinantes son claves candidatas.

En el caso que hemos estado trabajando, podemos ver los atributos no determinantes son claves candidatas de cada una de sus tablas, por lo que se encuentra en BCNF.

4NF

Cuarta Forma Normal

Está basada en dependencias multivaluadas, y, además de hallarse la base de datos en BCNF, se ocupa de las relaciones muchos a muchos entre los diferentes atributos.

5NF

Quinta Forma Normal

Está basada en dependencias de combinación, y, además de hallarse la base de datos en 4NF, ocupa de la representación de las relaciones uno a muchos entre los atributos.

6NF

Sexta Forma Normal

Además de hallarse la base de datos en 5NF, se basa en el principio de que en tablas con más de dos claves candidatas en una tabla, se deben crear otras tablas que relacionen dichas claves.
