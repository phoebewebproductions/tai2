6.1. PROGRAMA DE GESTIÓN DE VERSIONES

Los programas de gestión de versiones (VCS, Versión Control Systems) son herramientas de software utilizadas para gestionar los cambios en los ficheros y código fuente a lo largo del tiempo. Entre las grandes virtudes de utilizar este tipo de software esta:

  • Mejora en la gestión de los elementos permitiendo recuperar versiones anteriores de los ficheros almacenados.
  • Mayor protección del código fuente frente a imprevistos.
  • Registro de un histórico de los cambios almacenados.
  • Favorecer la colaboración entre los distintos miembros de un equipo de trabajo.
  • Ayudar a propiciar un trabajo colaborativo de forma rápida e inteligente.

El uso principal de este tipo de herramientas es permitir la vuelta hacia atrás del código en el caso sea necesario (errores, mejoras…).

6.1.1. TÉRMINOS

Antes de empezar con las definiciones es importante explicar algunos términos utilizados cuando se habla de herramientas CVS:

  • Repositorio. Lugar en el que se almacenan los datos actualizados e históricos de cambios.
  • Tag. Etiqueta utilizada para identificar las versiones o revisiones de un proyecto.
  • Rama o branch. Copia de archivos de manera que se puedan ir desarrollando distintos aspectos de forma paralela. Normalmente se utilizan para gestiones nuevas tareas o resolución de bugs.
  • Confirmar o commit. Conjunto de cambios preparados para subir al repositorio central los cambios realizados.
  • Merge. Fusionar un cambio a otro conjunto de cambios.

6.1.2. TIPOS DE PROGRAMAS DE GESTIÓN DE VERSIONES

Los tipos de gestión de versiones se clasifican según la forma de almacenar los repositorios. De esta forma tenemos dos clasificaciones más importantes:

6.1.2.1. SISTEMAS DE GESTIÓN DE VERSIONES CENTRALIZADOS

Los sistemas de gestión de versiones centralizados se caracterizan por tener un único repositorio donde se almacenan toda la información. Se facilitan las tareas administrativas a cambio de reducir flexibilidad, pues todas las decisiones más importantes necesitan el visto bueno de los administradores.

Ejemplos de VCS centralizados:

  • CVS
  • Subversion

6.1.2.2. SISTEMAS DE GESTIÓN DE VERSIONES DISTRIBUIDOS

Cada usuario tiene su propio repositorio en su máquina y hay un repositorio común que se utiliza como sincronización entre los repositorios.

Ejemplos de VCS distribuidos:

Código abierto:

  • GIT
  • Mercurial
  • DCVS

Código propietario:

  • Plastic CSM

6.1.2.3. DISTRIBUIDOS VS CENTRALIZADOS

Aunque los centralizados se siguen utilizando, el gran ganador por ahora son los vcs distribuidos, especialmente con GIT. Algunas de las razones son:

  • No necesidad de conexión para guardar los cambios y poder seguir trabajando
  • Necesidad menos recursos para el repositorio remoto.
  • Más flexibles al permitir gestionar cada repositorio personal.

6.1.3. GIT

GIT es el programa de gestión de versiones distribuido en código abierto más utilizado. Creado por Linux Torvalds, se utiliza para gestionar el código de forma eficiente.

6.1.3.1. FUNCIONAMIENTO DE GIT

Git gestiona los cambios a través de estados. Tiene tres estados en los que puede estar sus archivos:

  • Confirmado (committed). Los datos están almacenados de manera segura en tu base de datos.
  • Modificado (modified). Se ha modificado el archivo pero no se ha confirmado.
  • Preparado (staged) Se ha seleccionado el archivo modificado vaya en tu próxima confirmación

Comando Descripción Ejemplo
git init Creación de un nuevo repositorio en local git init [Nombre]
git remote Para conectar con el escritorio remoto Git remote Nombre
git clone Copiar un repositorio Git clone [Nombre]
git add Agregar archivos al área de preparación Git add text.c
git commit Creará una instantánea de los cambios y la guardará en el directorio git Git commit -m "Este commit es de prueba"
git config Establecer una configuración específica de usuario Git config –local user.email email@email.com
git status Lista de los archivos que se han cambiado junto con los archivos que están por ser preparados o confirmados Git status
git push Enviar confirmaciones locales a la rama maestra del repositorio remoto Git push origin <master>
git checkout Crea ramas y te ayuda a navegar entre ellas Git checkout <rama>
git branch Listar, crear o borrar ramas Git branch
git rebase Aplicar cambios de una rama a otra Git rebase master
git archive Permite crear zip o –tar Git archive --format
git pull Fusionar los cambios que se han hecho en el repositorio remoto con el directorio de trabajo Git pull
git diff Lista la lista de conflictos entre dos ramas Git diff <rama1> <rama2>
git merge Fusionar una rama con otra rama activa Git merge <rama>
git tag Etiqueta commits Git tag 1.2.0 <CommitId>
git log Lista commits en una rama con los datos del creador Git log
git reset Resetea el índice al último directorio de trabajo Git reset – hard HEAD
git stash Salvar los cambios en una pila local temporalmente Git stash
git rm Borrar un fichero o directorio Git rm fichero
git fetch Listar los elementos que estén en el repositorio remoto y no en el local Git fetch
