🧪 5.1. PRUEBAS

Las pruebas son la forma más eficaz de garantizar la calidad de software.

📝 5.1.1. CONCEPTOS IMPORTANTES

A continuación, se describen una serie de conceptos importantes relacionados con las pruebas:

  • Caso de prueba. Prueba o comportamiento del código que se desea testear. Está compuesto por:
    • Descripción del requisito a probar y resultado esperado.
    • Flujo de comprobación.
    • Datos de entrada.
  • Cobertura. Porcentaje de código o requisitos que se han probado.
  • Verificación. Comprobación de que el funcionamiento es el descrito por los diferentes requisitos definidos por los clientes.
  • Validación. Comprobación de que la/s funcionalidades desarrolladas cumplen las características y necesidades últimos del cliente final.

🔍 5.1.2. TIPOS DE PRUEBAS

En función del objetivo que se pretende probar dentro del software, se pueden distinguir los siguientes tipos de pruebas:

Pruebas unitarias

Son consideradas una parte esencial que permite garantizar la calidad del código. Siendo puristas las pruebas unitarias son aquellas que verifican las unidades más pequeñas del código. Es decir trataríamos un procedimiento, función de una clase con un determinado comportamiento.

Pruebas de integración

Cómo su propio nombre indica las pruebas de integración son aquellas que testean la interconexión o comunicación de los distintos módulos.

Pruebas de regresión

El objetivo de las pruebas de regresión es certificar que los cambios de código no afectan a la funcionalidad ya desarrollada. Es decir verifica si el sistema a probar funciona correctamente después de los cambios.

Pruebas de aceptación

Pruebas realizadas por los usuarios finales para verificar y dar el visto bueno a las funcionalidades desarrolladas.

Pruebas de usabilidad (UX)

Tienen la finalidad de cuantificar determinar la experiencia de usuario. Lo que se pretende conseguir con este tipo de pruebas es la creación de soluciones intuitivas y fáciles de usar para todo tipo de usuarios.

Pruebas de accesibilidad

Se comprueban que las soluciones cumplen los requisitos de accesibilidad generalmente definidos en el WCAG (Web Content Accesibility Guideness).

Pruebas de rendimiento

Tienen la finalidad de evaluar el rendimiento en diversas vertientes. Se pueden medir tiempos de respuesta o número de usuarios soportados.

Pruebas de estrés

Se prueban la carga máxima soportada de un sistema en busca de los niveles críticos.

Pruebas de seguridad

Pruebas que tienen el objetivo de mejorar las diversas vulnerabilidades de sistemas midiendo la capacidad de evadir una intrusión. Este tipo de pruebas se pueden hacer ejecutando el sistema o sin ejecutarlo:

  • DAST (Dynamic Application Security Testing).
  • SAST (Static Application Security Testing).

Por otro lado, también podemos definir las pruebas que se definen dentro de Métrica 3:

  • Pruebas unitarias.
  • Pruebas de integración.
  • Pruebas del sistema.
  • Pruebas de implantación.
  • Pruebas de aceptación.
  • Pruebas de regresión.

⚙️ 5.1.3. TÉCNICAS PARA LA REALIZACIÓN DE PRUEBAS

Una vez explicados los diferentes tipos de pruebas, conviene saber los diferentes tipos de técnicas de realización de pruebas. Estas se pueden dividir entre técnicas estáticas y dinámicas:

◼️ Pruebas de Caja Negra

Es una técnica de pruebas del software en la que se verifica las funcionalidades sin tener en cuenta cómo se encuentra desarrollado. Se definen los datos de entrada y se comparan los resultados de salida con los esperados.

Tipos de técnicas de caja negra:

  • Partición de equivalencias
  • Análisis de valores borde
  • Tablas de decisión
  • Transición entre estados

⬜ Pruebas de Caja Blanca

Técnicas de pruebas de software en la que se verifica una codificación, estructura interna y diseño. Se utilizan para mejorar el diseño y la usabilidad del software.

Tipos de técnicas de caja blanca:

  • Pruebas unitarias.
  • Prueba de penetración.
  • Prueba de transformación

🔄 5.1.4. PRUEBAS EN METODOLOGÍAS ÁGILES

Como se ha comentado a lo largo del documento, las pruebas son una parte esencial para garantizar una correcta calidad del desarrollo. Como se dice en metodología ágiles "La calidad de un producto de software depende exclusivamente de la calidad del proceso con el que se construye". Para ello se debe tener en cuenta el concepto de prueba ágil.

Características del "agile testing" frente las características de un sistema de pruebas tradicional:

  • Las metodologías ágiles no consideran las pruebas como una fase separada sino como una parte integral del desarrollo del software.
  • Prueba ágil es un tipo dinámico de pruebas en los que se asume que los requerimientos están en continúo cambio. Este tipo de pruebas se basa en el concepto de Integrar y Probar.
  • Integrar y Probar. Concepto de iteraciones cortas de realización de pruebas en cada etapa de desarrollo, a modo continuo hasta que el requerimiento es finalmente aprobado por el cliente.

Teniendo en cuenta estos conceptos, cuando hablamos de metodologías tenemos en cuenta las siguientes tipos de pruebas:

  • Pruebas Unitarias. Parte técnica.
  • Pruebas funcionales centradas en el negocio.
  • Pruebas de usabilidad y aceptación. Encontrar mejorar de cara al negocio que se quiere estudiar.
  • Pruebas de desempeño, carga y seguridad.

🔄 5.1.4.1. PRÁCTICAS DE TESTING EN METODOLOGÍAS ÁGILES

🔄 Test Driven Development (TDD) o Desarrollo guiado por pruebas

Es una metodología de desarrollo cuyo objetivo es crear primero las pruebas y luego escribir el software. Por tanto se definen dos fases:

  • Escribir las pruebas primero
    • La prueba debe fallar.
    • Se genera el código y pasa la prueba.
  • Refactoring o mejora del código.

Ventajas del TDD:

  • Nos permiten hacer test completos
  • Claridad a la hora de leer el código al tener ejemplos de prueba.
  • Nos permiten mejorar la aplicación asegurándonos que nada de lo anterior se ha estropeado.
✅ Acceptance Test Driven Development (ATDD)

Es una dimensión del TDD aplicada al nivel de gestión de requerimientos de software, en el cual las pruebas escritas son a nivel de cliente, es decir, lo equivalente a una prueba de aceptación o test funcional.

🔄 Behaviour Driven Development (BDD)

Bajo este enfoque primero se desarrolla una prueba funcional o de historia de usuario automatizada, luego se ejecuta el desarrollo aplicando TDD hasta que la prueba es exitosa.
