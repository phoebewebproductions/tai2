👥 7.1. PLATAFORMA DE DESARROLLO COLABORATIVO DE SOFTWARE

El apartado de plataformas de desarrollo colaborativo de software incluye toda una amalgama de herramientas que permiten entre otras funciones, la cooperación entre distintas personas o equipos para el desarrollo de una actividad determinada, que en este punto es el desarrollo del software. Hay que destacar que el desarrollo de un software incluye:

  • Documentación inicial en la que se debe incluir el análisis, diseño y mantenimiento.
  • Manual de uso y los distintos manuales.
  • El código fuente.
  • Listado de tareas a realizar.
  • Listado de preguntas frecuentes
  • Etc.

Llegados a este punto del tema, es normal preguntarse si los sistemas de control de versiones, vistos anteriormente son considerados un tipo de plataformas de desarrollo colaborativo. He de confirmarte que así es, aunque en el próximo apartado entraremos en detalle de las distintas plataformas de desarrollo colaborativo.

🔄 7.1.1. TIPOS DE PLATAFORMAS DE DESARROLLO COLABORATIVO

Para los tipos de plataformas de desarrollo colaborativo se va a ser distinción entre adaptaciones que existían antes y después de la aparición de las metodologías ágiles.

🛠️ Plataformas de desarrollo colaborativo tradicionales

Foros

Espacio web donde los usuarios pueden compartir ideas, soluciones o ayudar en la resolución de problemas. Uno de los foros más utilizados por los programadores es Stackoverflow (https://es.stackoverflow.com/).

Wikis

Forma interactiva de incluir documentación. Permite gestionar un historial de cambios y pueden ser editadas por cualquier persona. Para asegurar que la información que se publique sea verídica muchas wikis están orientadas a ser solo editables por los miembros de un determinado proyecto. Las wikis pueden ayudar a:

  • Mejor el seguimiento de un proyecto gracias a la documentación del desarrollo del mismo y las incidencias surgidas.
  • Centralización de recursos como manuales de integración de una determinada herramienta.
Gestión de tareas

Herramientas que permiten:

  • gestionar las actividades pendientes
  • planificar el trabajo asignando o autoasignando a cada integrante del equipo las tareas a realizar en un periodo de tiempo
  • Ver el estado y el encargado de una determinada tarea
Gestión de incidencias

Los técnicos o representantes del servicio al cliente registran los detalles sobre el incidente o problema y revisan el problema. Las incidencias quedan registradas y asignadas de manera que el conocimiento puede ayudar a futuros desarrollos. Así mismo es normal tener una base de datos de incidencias.

Algunos ejemplos de gestores de incidencias son JIRA o Mantis Bug Trucker.

Sistemas de control de versiones

Como se ha indicado en el apartado anterior, este tipo de sistemas permiten que un equipo trabaje paralelamente sobre el mismo código fuente permitiendo tener un historial de los cambios realizados tanto en el código fuente como en la documentación. Algunos de los sistemas de gestión de versiones más utilizados son:

  • Github. Plataforma de desarrollo colaborativo para alojar proyectos usando GIT. Normalmente el código publicado es público pudiendo ser privado previo pago. Las funcionalidades de poder clonar otros repositorios lo hacen especialmente llamativo para el desarrollo colaborativo.
  • Gitlab. Herramienta de desarrollo colaborativo basada en GIT que permite repositorios privados gratuitos.
  • Bitbucket. Herramienta de desarrollo colaborativo que puede basarse en Mercurial o GIT. Permiten tanto la gestión de repositorios privados o públicos, con posibilidad de aumentar especificaciones previo pago.

Actualmente existen soluciones que abarcan uno o más de las características definidas anteriormente:

Azure Devops

Es el caso de Azure Devops que nos permite para un equipo, tener una serie de repositorios con su gestor de versiones, una wiki de los proyectos y un board con las tareas a realizar. Es una herramienta incluida en la suscripción de azure.

Redmine

Herramienta de código abierto que permite el seguimiento de incidentes, errores, calendario de actividades, diagramas de Gantt para representar visualmente la línea del tiempo de los proyectos, wiki, control basado en roles, integración con correo electrónico y un largo etcétera de características que nos resultarán muy útiles.

Apache Allura

Es un software de forja de código abierto para administrar repositorios de código fuente, informes de errores, discusiones, páginas wiki, blogs y más para cualquier cantidad de proyectos individuales.

Aunque lo hemos visto en el apartado de metodologías, es importante recordar ciertos aspectos de las metodologías ágiles que son una adaptación de las plataformas tradicionales.

  • SCRUM
    • Burn Down Chart. Nos permiten gestionar el trabajo pendiente.
  • Kanban
    • Tableros Kanban. Son una forma de gestionar las tareas e historias de usuarios
