🔄 4.2 XML

Extensible Markup Language (XML) es un subconjunto de SGML, con los mismos objetivos pero sin su complejidad.

Diseñado para ser compatible con SGML. Todo XML es un documento SGML pero no a la inversa.

XML es un estándar abierto del W3C: garantía de calidad del proceso de desarrollo.

Al igual que SGML es un metalenguaje. Se denomina extensible porque cada usuario puede crear su propio lenguaje para el formato de datos y documentos, su propio vocabulario, según sus necesidades, siguiendo las reglas de XML.

XML es potente, permite separar contenido y estructura: Un mismo documento puede tener diferentes presentaciones, MARCADO ESTRUCTURAL.

Se puede procesar de forma automática por ser de tipo estructural. (Parser XML).

🧩 Componentes de un documento XML:

Elementos

<nombre de elemento>elemento </nombre de elemento>

Un elemento puede contener subelementos. Es decir se agrupa la información en jerarquías.

Los elementos pueden contener atributos.

Un atributo es una pareja (nombre, valor) que permite dar cierta información sobre un elemento. Ejemplo: <libro edición="primera">

📋 La DTD (Document Type Definition)

Define cómo son los documentos XML utilizados en un cierto dominio de aplicación, etiquetas que se pueden utilizar, contenido de cada elemento, es decir, qué elementos pueden formar parte del contenido de una etiqueta y si el elemento puede contener texto o no, así como los atributos de cada elemento, opcionales u obligatorios.

Si el documento XML cumple las reglas de XML (sin DTD), -> documento XML es "bien formado".

Si además el doc. XML sigue las reglas definidas en un DTD-> documento XML es "válido".

🔄 Espacios de nombres

Objetivos:

  • Distinguir elementos y atributos de distintos vocabularios con distintos significados que pueden compartir el mismo nombre.
  • Agrupar todos los elementos y atributos relacionados con una sola aplicación XML para que el SW los reconozca con facilidad.

Se añade un prefijo a cada elementos y atributo. Cada prefijo se le asigna un URI (xmlns:prefijo), llamado nombre de espacio de nombres. Existen URI predeterminados para los elementos que no tengan un prefijo definido. Para esto se usa el atributo xmlns.

📝 XML Schema (XSD)

XSD (XML Schema Definition) contiene la descripción formal del contenido del documento XML válido. Es una recomendación del W3C (Recommendation on 2 May 2001)

Los esquemas solucionan las limitaciones de los DTDs:

  • Ampliables por ser notación XML
  • Herramientas maduras
  • Soporte DOM
  • Permite tipos de Datos
  • Permite Herencia
  • Múltiples vocabularios mediante espacio de nombres

XSL

Extensible StyleSheet Language (XSL) es de la familia de lenguajes basada en XML, para la presentación de documentos complejos. XSL está formado por:

XSLT (Extensible Style Sheet for Transformations)

Plantillas con una serie de reglas de transformación y formato que se disparan cuando los elementos coinciden con la plantilla. A través de árboles de transformación, puede convertir a otros formatos (PDF, Word, etc.)

XPath

Es una notación que permite hacer referencia a una o varias partes de un documento XML.

Formatting Objects (XSL-FO)

Es una aplicación XML cuya semántica define como presentar un documento XML que utilice los componentes definidos en XSL-FO.

🎨 CSS

Las Hojas de Estilo (o CSS, por Cascading StyleSheets) son un mecanismo que permiten aplicar formato a los documentos escritos en HTML ó XHTML (y en otros lenguajes estructurados, como XML) separando el contenido de las páginas de su apariencia.

La idea más importante detrás de las hojas de estilo CSS es separar el contenido de su presentación, es decir, de su aspecto visual.

El modo de funcionamiento de las CSS consiste en definir, mediante una sintaxis especial, la forma de presentación que le aplicaremos a:

  • Una web entera
  • Un documento HTML o página
  • Una porción del documento
  • Una etiqueta en concreto

Formas de declarar CSS

Podemos declarar un estilo CSS en varios lugares:

Enlazado en otro archivo: Crear un archivo .css y enlazarlo con <link rel="stylesheet" href="mi_hoja.css">
Interno en la cabecera: Usando la etiqueta <style> en el head
Dentro de la etiqueta: Usando el atributo style en elementos HTML

Preprocesadores CSS

Los preprocesadores CSS son herramientas que posibilitan traducir hojas de estilo comunes a un código estándar y reconocible por los navegadores.

Los preprocesadores más conocidos son:

SASS
LESS
STYLUS
POSTCSS

🌐 XHTML

El lenguaje XHTML (eXtensible HyperText Markup Language) es muy similar al lenguaje HTML, pero con algunas diferencias que lo hacen más robusto y aconsejable para la modelación de páginas web. De hecho, XHTML no es más que una adaptación de HTML al lenguaje XML.

Técnicamente, HTML es descendiente directo del lenguaje SGML, mientras que XHTML lo es del XML (que, a su vez, también es descendiente de SGML).

XHTML es un lenguaje semántico, lo que quiere decir que no definimos el aspecto de las cosas, sino lo que significan.

Estructura XHTML

Siempre debe llevar un DOCTYPE. El doctype se encarga de decirle al navegador qué contiene el archivo que está abriendo.

Después del DOCTYPE tenemos a la cabecera y al cuerpo encerrado entre las etiquetas <html>.

En la etiqueta html debemos indicar que nuestro documento es XHTML y qué lengua estamos usando.

XHTML trata de separar totalmente la forma del contenido, por ello se deben utilizar sólo las etiquetas y atributos que sirven para definir qué es cada cosa y no las que sirven para definir cómo se ha de ver cada cosa. Para dar formato en XHTML se utiliza CSS.
