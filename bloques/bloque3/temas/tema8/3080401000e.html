4.1 LENGUAJES DE MARCADO (SGML, HTML, XML)

Su origen es la Industria de la publicación electrónica. Inicialmente eran anotaciones de instrucciones de diseño para el tipógrafo, que maquetaba y componía las publicaciones.

Estas tecnologías presentan en común las siguientes características:

Tipos

Marcado procedural

Conlleva un procedimiento para el dispositivo de salida. El usuario identifica por separado cada elemento significativo, también se especifica la apariencia del texto (tipo de fuente, tamaño, posición), utilizando los comandos apropiados para producir el formato deseado para cada elemento. Es similar al tradicional, la única diferencia es que el marcado se almacena electrónicamente.

Desventajas:

  • Pérdida estructura
  • No es flexible. Cualquier cambio a las normas de formato implica cambiar de manera manual del documento
  • El procesado es lento y propenso a errores

Marcado estructural

Codificación genérica o estructurada. Las etiquetas se asocian a normas de formato, es decir un formateador procesa el texto y produce un documento de salida.

Ventajas:

  • El marcado describe únicamente la estructura lógica del documento
  • Es más flexible
  • Facilita el procesado automático de la información

4.1.1 SGML

Standard Generalized Markup Language, presenta las siguientes características generales:

  • Lenguaje de Marcado de Tipo estructural
  • Historia:
    • Se basa en los trabajos iniciales del Dr. Charles Goldfarb de IBM
    • Trataron de definir lenguaje de marcas universal para todo tipo de documentos
    • Finalmente acabaron con un Metalenguaje
  • Es un estándar internacional publicado por la ISO (Organización Internacional de Estándares). ISO 8879:1986

Características principales:

  • El marcado describe la estructura, no su apariencia
  • El marcado se ajusta a un modelo
  • El material que constituye un documento se puede distribuir en diferentes archivos (Un archivo para portada, introducción, etc.) que se denominan entidades

Las entidades pueden estar compartidas por distintos documentos. Un documento estará definido en función de la estructura de las entidades que lo conforman.

Las entidades se organizan en una estructura lógica de manera jerarquizada, en la que se definen conceptos como capítulos, tablas y párrafos. Cada entidad contiene elementos del documento.

Los Elementos y entidades pueden coincidir: un elemento lógico como tabla puede ser también una entidad en un archivo hoja de cálculo.

Los objetos SGML son principalmente dos:

  • Entidades, para caracteres especiales, texto almacenado y archivos externos
  • Elementos, insertados como etiquetas y sus atributos locales

Pensado para grandes sistemas de gestión de Documentos Muy potente pero también muy complicado.

Un documento SGML está compuesto de tres archivos que trabajan de manera conjunta:

  • El DTD (Document Type Definition o Definición del Tipo de Documento)
  • La declaración SGML
  • La Muestra de Documento

4.1.2 DTD

Es donde se define la Estructura del documento. Contiene las reglas de dichos elementos: el nombre, su significado, dónde pueden ser utilizados y qué pueden contener.

Se puede almacenar en un archivo separado. Sin el DTD (o una referencia a él), el documento SGML no será validado apropiadamente por el parser.

El parser es una herramienta que asegura la adecuada conformación de SGML dentro de las múltiples especificaciones que un documento SGML puede tener. Escribir el DTD es la tarea más compleja e importante.

El DTD permite a las aplicaciones como editores, motores de búsqueda y visualizadores interpretar los documentos SGML.

Declaración SGML

Es lo que indica en el documento qué puede y qué no puede estar contenido, qué caracteres serán usados, qué características específicas de SGML serán implementadas y qué sintaxis se utilizará en el documento.

La declaración SGML y el DTD trabajan juntos. Si la declaración SGML dice que una función en particular no podrá ser usada, el DTD debe respetarlo, de otra manera existirán errores en el documento. Ésta puede ser parte de la Muestra de Documento y es necesaria para cada documento SGML. Puede utilizarse desde cualquier ubicación considerada no local.

4.1.3 HTML

Aplicación de SGML, no de XML. Desarrollado originalmente por Tim Berners-Lee mientras estaba en el CERN (Centro Europeo de Investigaciones Nucleares), y fue popularizado por el navegador Mosaic desarrollado en el NCSA (Nacional Center of SuperComputing of Applications).

La primera web data de 1993: http://info.cern.ch/hypertext/WWW/TheProject.html

HTML no es un lenguaje de programación, sino un formato de representación. El formato HTML permite indicar a los navegadores como queremos que se visualice la información que hemos introducido en la página. Para ello utiliza etiquetas o elementos, que a su vez están configuradas o parametrizadas mediante atributos.

Características de HTML

Algunas de las características de HTML más importantes son:

  • Utiliza marcado estructural, procedural e hipertextual:
    • Estructural: <h1> Coche </h1> define que Coche es un contenido de tipo cabecera de primer nivel
    • Presentacional: <br> Casa</br> indica que este texto se debe presentar salto de línea
    • Hipertextual: <a href:"www.w3c.com"> Enlace a W3C </a> etiqueta ancla para enlazar
  • Lenguaje muy simple para la visualización de documentos hipermedia en navegadores
  • Gramática fija, es decir, NO ES UN METALENGUAJE
  • Formato mediante etiquetas (tags) que indican el comienzo y el final de los elementos
  • La gramática HTML no necesita de validación
  • Estructura monolítica, comienza con la etiqueta <html>, y termina con </html>

4.1.4 HTML 5

Aprobado el estándar W3C en Octubre de 2014, aunque ya se está usando por desarrolladores web desde hace años.

Pretende englobar y actualizar HTML4.01, XHTML1.1. Cuando se acabe, será la mayor actualización de una versión de HTML.

Resultado de la colaboración entre W3C y WHATWG (Web Hypertext Application Technology Working Group), comunidad de fabricantes y personas interesadas en el avance de HTML.

Se buscaba:

  • Nuevas características basadas en HTML, CSS, DOM y JavaScript
  • Reducir la necesidad de plugins externos
  • Mejor gestión de errores
  • Más etiquetas de marcado para reducir la necesidad de lenguajes de script

Novedades de HTML5

Como novedades frente a otros protocolos derivados de HTML, HTML5 aporta:

  • Reproducción de contenido multimedia sin necesidad de plugins
  • Visores: MathML y SVG
  • Drag & Drop
  • Avance en el desarrollo de la Web Semántica (Web 3.0)
  • Nuevas etiquetas semánticas: header, footer, article, nav, time, etc.
  • Novedades en API's y Javascript
