1.1 APLICACIONES WEB

En la Ingeniería de software se denomina aplicación web a aquellas aplicaciones que los usuarios pueden utilizar accediendo a un Servidor web a través de Internet o de una intranet mediante un navegador web. En resumen, es una aplicación software que se desarrolla en un lenguaje de programación que es soportado por los navegadores web.

Las aplicaciones web son muy comunes ya que es muy sencillo utilizarlas a través de un cliente ligero, en este caso un navegador web, así como a la independencia de la arquitectura del dispositivo donde se ejecuta, además es sencillo el poderla actualizar y mantener sin distribuir e instalar software a miles de usuarios potenciales.

Por ello podemos afirmar que es la arquitectura ideal para aplicaciones Internet/Intranet.

Las aplicaciones Web suelen ser descritas como multiplataforma, ya que, idealmente, se puede acceder desde cualquiera de los diversos navegadores web en diferentes sistemas operativos. Estas aplicaciones generalmente emplean una arquitectura de sistema cliente-servidor, y pueden variar ampliamente en complejidad y funcionalidad.

1.1.1 ARQUITECTURA DE APLICACIONES WEB

La arquitectura típica que siguen las aplicaciones web está basada en el patrón Modelo-Vista-Controlador, y en concreto siguen un modelo en tres capas, en donde está separada la parte de presentación, la lógica de negocio y la persistencia, o capa de datos.

1.1.3 CLIENTE WEB

El cliente Web dentro de la arquitectura de este tipo de aplicaciones Web, es el encargado de realizar las peticiones HTTP al servidor Web. A continuación, recibe las respuestas de éste, las procesa y las representa al cliente que hizo la petición. Además, se encarga de gestionar la interfaz con el usuario.

El cliente Web presenta las siguientes características:

  • Realiza peticiones HTTP al servidor Web.
  • Procesa y representa la respuesta del servidor.
  • Gestiona el interfaz con el usuario.

En cuanto a la arquitectura que presentan los clientes web, están compuestos por:

  • Java Virtual Machine, que ejecuta los applets.
  • Un Intérprete de scripting para validar datos antes de enviarlos al servidor.
  • Los scripts de clientes (embebidos dentro de la página web), se ejecutan ante la ejecución de un evento, hay que destacar que no son lo mismo que los componentes de cliente (applets o controles Active X) ya que éstos se ejecutan en el navegador.
  • Plug-ins, que son elementos que se instalan en el navegador e interactúan con él.
  • Objetos de servidor que están implementados en Java.
  • Páginas dinámicas (Java Server Pages).

El front-end o cliente es la parte del software que interactúa con los usuarios y el back-end es la parte que procesa la entrada desde el front-end.

La separación del sistema en front-ends y back-ends es un tipo de abstracción que ayuda a mantener las diferentes partes del sistema separadas.

El front-end es el responsable de recolectar los datos de entrada del usuario, que pueden ser de muchas y variadas formas, y los transforma ajustándolos a las especificaciones que demanda el back-end para poder procesarlos, devolviendo generalmente una respuesta que el front-end recibe y expone al usuario de una forma entendible para este. La conexión del front-end y el back-end es un tipo de interfaz.
