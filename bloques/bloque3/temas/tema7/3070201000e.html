2.1. SERVICIOS WEB

Definición de la W3C:

"Un servicio web es un sistema software diseñado para soportar la interacción máquina-a-máquina a través de una red y de forma interoperable"

Una de las tecnologías más destacadas y que con más éxito está llevando a la práctica el paradigma conceptual de SOA son los Web Services o Servicios Web.

Pero SOA y Web Services NO ES LO MISMO.

Una arquitectura SOA puede llegar a ser implementada, sin que para ello exista un solo Servicio Web.

De forma inversa, se pueden implementar Servicios Web sin que exista una plataforma o infraestructura SOA que los soporte por detrás.

La diferencia entre ambos términos es conceptual, mientras que SOA define el qué, los Servicios Web definen el cómo.

2.1.1. COMPONENTES DE LOS SERVICIOS WEB

Un servicio web cuenta con una interfaz descrita en WSDL (Web Service Definition Language) en lenguaje XML, a través de la que es posible interactuar con el mismo mediante el intercambio de mensajes SOAP, típicamente transmitidos usando serialización XML sobre HTTP conjuntamente con los estándares web.

Para conocer el formato, el consumidor del servicio consulta a un intermediador, un registro de servicios (UDDI), donde los proveedores de servicios web publican sus formatos y a los consumidores se les ofrece un servicio de consulta similar a unas "páginas amarillas".

Los principales estándares y protocolos usados con los Web Services son:

  • XML
  • SOAP
  • WSDL
  • UDDI

2.1.2. SOAP (SIMPLE OBJECT ACCESS PROTOCOL)

Se trata de un estándar de la W3C. Define una gramática XML, que describe el formato de los documentos XML a intercambiar entre el consumidor del servicio web y el propio servicio, en concreto, el formato en el que "envuelven" las peticiones y las respuestas entre el consumidor y el proveedor del servicio.

Permite que programas que se ejecutan en diferentes sistemas operativos se comuniquen.

La comunicación entre las diferentes entidades se realiza mediante mensajes que son enrutados en un sobre (envelope) SOAP.

Un mensaje SOAP se compone de un sobre (envelope) que contiene el cuerpo del mensaje y cualquier información de cabecera que se utiliza para describir el mensaje.

2.1.3. WSDL (WEB SERVICES DESCRIPTION LANGUAGE)

Se trata de un estándar de la W3C. Es realmente un protocolo que describe el servicio web.

Define una gramática XML que permite describir la interfaz de un servicio web, es decir, las funciones y parámetros de entrada y salida necesarios para la invocación del servicio.

2.1.4. UDDI (UNIVERSAL DESCRIPTION DISCOVERY AND INTEGRATION)

Perteneciente a OASIS (http://www.uddi.org). Configura un servicio de registro o servicio de directorio donde los proveedores de servicios web publican sus servicios web y los consumidores de éstos los buscan y encuentran, de forma parecida a cómo funciona un servicio de directorio.

UDDI es uno de los estándares básicos de los servicios Web cuyo objetivo es ser accedido por los mensajes SOAP y dar paso a documentos WSDL, en los que se describen los requisitos del protocolo y los formatos del mensaje solicitado para interactuar con los servicios Web del catálogo de registros.
