5.1. PROTOCOLOS ASOCIADOS A LAS ARQUITECTURAS

En este apartado vamos a describir los diferentes protocolos utilizados en las arquitecturas que hemos analizado durante el tema.

5.1.1. REST

REST (Representational State Transfer) surge ya que muchos desarrolladores de Servicios Web piensan que SOAP es demasiado complicado.

Como solución están comenzando a utilizar Servicios Web basados en REST para el tratamiento de cantidades de datos masivas.

Este es el caso de grandes empresas como eBay y Google.

Este nuevo estilo ha supuesto una nueva opción de estilo de uso de los Servicios Web.

Los servicios RESTful son la alternativa de los servicios Web SOAP. En la actualidad han experimentado un creciente uso por su simplicidad y ligereza.

Evitan la sobrecarga que supone el uso de XML y protocolos complejos de interacción entre aplicaciones.

Los servicios RESTful siguen el estilo de arquitectura denominado REST (REpresentational State Transfer).

Los servicios RESTful comparten varias características con los servicios web SOAP.

5.1.2. REST VS SOAP

REST

  • Las operaciones se definen en los mensajes.
  • Una dirección única para cada instancia del proceso.
  • Cada objeto soporta las operaciones estándares definidas.
  • Componentes débilmente acoplados.
  • No conserva el estado (stateless).

SOAP

  • Las operaciones son definidas como puertos WSDL.
  • Dirección única para todas las operaciones.
  • Múltiple instancias del proceso comparten la misma operación.
  • Componentes fuertemente acoplados.

REST Y SOAP

  • Son componentes software.
  • Permiten la interoperabilidad entre sistemas heterogéneos implementados con diferentes tecnologías y lenguajes.
  • Utilizan protocolos y estándares.

5.1.3. VENTAJAS E INCONVENIENTES

Ventajas

REST
  • Bajo consumo de recursos.
  • Las instancias del proceso son creadas explícitamente.
  • El cliente no necesita información de enrutamiento a partir de la URI inicial.
  • Los clientes pueden tener una interfaz "listener" (escuchadora) genérica para las notificaciones.
  • Generalmente fácil de construir y adoptar.
SOAP
  • Fácil (generalmente) de utilizar.
  • La depuración es posible.
  • Las operaciones complejas pueden ser escondidas detrás de una fachada.
  • Incrementa la privacidad.
  • Herramientas de desarrollo.

Inconvenientes

REST
  • Gran número de objetos.
  • Manejar el espacio de nombres (URIs) puede ser engorroso.
  • La descripción sintáctica/semántica muy informal (orientada al usuario).
  • Pocas herramientas de desarrollo.
SOAP
  • Los clientes necesitan saber las operaciones y su semántica antes del uso.
  • Los clientes necesitan puertos dedicados para diferentes tipos de notificaciones.
  • Las instancias del proceso son creadas implícitamente.

5.1.4. SERVICIOS WEB REST VS SERVICIOS WEB SOAP

Los servicios web SOAP y los servicios web RESTful se diferencian fundamentalmente en:

Su complejidad:

  • Los servicios web SOAP son muy complejos (adaptabilidad a cualquier necesidad, seguridad avanzada, transaccionalidad, QoS).
  • Los servicios web RESTful son extremadamente simples.

El tipo de interfaz:

  • Los servicios web SOAP están orientados a RPC (llamada a métodos remotos).
  • Los servicios web REST están dirigidos a recursos accesibles con identificadores (URIs) y manejados con acciones basadas en métodos HTTP.

5.1.5. HYPERTEXT TRANSFER PROTOCOL (HTTP)

Es un protocolo para el intercambio de información entre un cliente, que realiza una petición, y un servidor (identificado por una URL) que la responde. Los mensajes intercambiados están en texto plano.

Estructura:

  • Una parte inicial con:
    • Para la petición, la acción requerida (método de petición) y la URL del recurso.
    • Para la respuesta, el código con el resultado de la operación.
  • Una cabecera con metadatos.
  • Un cuerpo (opcional) con los datos transmitidos

5.1.6. JSON Y OPEN API COMO SUSTITUTO DE XML Y WSDL

Los servicios web RESTful se caracterizan, entre otras cosas, por su ligereza.

A ello contribuye el uso del formato JSON en lugar de XML (aunque también podría usarse XML).

Por su parte, la descripción del servicio web RESTful (equivalente a la especificación WSDL para los servicios web SOAP) puede hacerse utilizando la especificación OpenAPI.

También hay otra especificación WADL (Web Application Description Language) equivalente a WDSL pero no tiene versión definitiva mientras que OpenApi es un estándar de facto.
