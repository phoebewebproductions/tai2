🏗️ 1.1. PATRONES DE ARQUITECTURA

Los patrones arquitectónicos, o patrones de arquitectura, también llamados arquetipos ofrecen soluciones a problemas de arquitectura de software en ingeniería de software.

Dan una descripción de los elementos y el tipo de relación que tienen junto con un conjunto de restricciones sobre cómo pueden ser usados.

Un patrón arquitectónico expresa un esquema de organización estructural esencial para un sistema de software, que consta de subsistemas, sus responsabilidades e interrelaciones.

En comparación con los patrones de diseño, los patrones arquitectónicos tienen un nivel de abstracción mayor.

🧩 1.1.2. PROGRAMACIÓN POR CAPAS

La programación por capas tiene como objetivo fundamental la separación (desacoplamiento) de las partes que componen una aplicación software o también una arquitectura cliente-servidor. Esta separación se produce en las siguientes capas:

  • capa de presentación.
  • lógica de negocio.
  • capa de persistencia o datos.

El disponer de diferentes capas nos brinda una flexibilidad a la hora de mantener el sistema. Por ejemplo, podemos crear nuevas interfaces de usuario, para la capa de presentación, sin que se vean afectadas el resto de capas: negocio y datos.

Vamos ahora a describir las principales ventajas que nos aporta este modelo:

  • El desarrollo se puede llevar a cabo en varios niveles y, en caso de que sobrevenga algún cambio, solo afectará al nivel requerido sin tener que revisar entre el código fuente de otros módulos, dado que se habrá reducido el Acoplamiento informático hasta una interfaz de paso de mensajes.
  • Permite distribuir el trabajo de creación de una aplicación por capas; de este modo, cada equipo de desarrollo está totalmente independizado del resto de capas, de forma que basta con conocer la API que existe entre niveles.

🔄 1.1.3. CAPAS DE LA ARQUITECTURA

👁️ Capa de presentación:

La que ve el usuario (también se la denomina «capa de usuario»), presenta el sistema al usuario, le comunica la información y captura la información del usuario en un mínimo de proceso (realiza un filtrado previo para comprobar que no hay errores de formato). También es conocida como interfaz gráfica y debe tener la característica de ser «amigable» (entendible y fácil de usar) para el usuario. Esta capa se comunica únicamente con la capa de negocio.

⚙️ Capa de negocio:

Es donde residen los programas que se ejecutan, se reciben las peticiones del usuario y se envían las respuestas tras el proceso. Se denomina capa de negocio (e incluso de lógica del negocio) porque es aquí donde se establecen todas las reglas que deben cumplirse. Esta capa se comunica con la capa de presentación, para recibir las solicitudes y presentar los resultados, y con la capa de datos, para solicitar al gestor de base de datos almacenar o recuperar datos de él. También se consideran aquí los programas de aplicación.

💾 Capa de datos:

Es donde residen los datos y es la encargada de acceder a los mismos. Está formada por uno o más gestores de bases de datos que realizan todo el almacenamiento de datos, reciben solicitudes de almacenamiento o recuperación de información desde la capa de negocio.

Hay que indicar que todas estas capas pueden estar alojadas en una única máquina, aunque lo más común es que haya una arquitectura de máquinas en donde reside la capa de presentación.

Las capas de negocio y de datos pueden residir en la misma máquina, y si el crecimiento de las necesidades lo aconseja se pueden separar en dos o más máquinas.

En el caso de la capa de datos, si el tamaño o complejidad de ésta aumenta, se puede crear un clúster el cual recibirá las peticiones dirigidas desde la capa de negocio.

Puede ocurrir que necesitemos por complejidad o rendimiento el dividir la capa de negocio en varias instancias, en este caso todas ellas serían las que dirigirían las peticiones a una única instancia de base de datos.

En sistemas muy complejos y con grandes necesidades de disponibilidad y rendimiento, se llega a tener una serie de máquinas sobre los cuales se aloja la capa de negocio, y otra serie de máquinas sobre las cuales se despliega la base de datos.
