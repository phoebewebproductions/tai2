3.1 ARQUITECTURA DE UNA APLICACIÓN J2EE

La arquitectura J2EE se puede observar en el siguiente gráfico.

Como podemos observar, la arquitectura es multicapa en la que aparecen cuatro grandes bloques identificados por el contenedor en el que se ejecutan. Se definen dos tipos de contenedores que se encuentran en las máquinas cliente y dos tipos de contenedores que se encuadran en las máquinas servidores.

Ahora analizaremos cada uno de los componentes que componen la arquitectura. Servlets y JavaServer Pages (JSP) son los componentes del nivel de presentación.

3.1.1. Servlet

Es un componente de la capa de presentación, alojado en el contenedor web. Se utiliza para generar contenido dinámico: texto (HTML o XML), imágenes, sonido, animación, los cuales son invocados a través de una URL.

Su objetivo principal es generar contenido para que lo maquete otro, reseñar que lo hace de forma dinámica.

Características principales:

  • Se puede invocar desde una URL.
  • Java code: fácil controlar el flujo de acciones.
  • Forma de gestionar una petición.

Proceso de gestión de peticiones:

A la hora de gestionar una petición, el servidor web procesa la petición y la redirige hacia el contenedor web o de servlets, a continuación, el contenedor asocia la petición con el tipo de objeto de respuesta que ha de generar. Tras ello ejecuta el método doGet() o doPost(), dependiendo de la llamada, analiza la petición que llega con HttpServletRequest y se devuelve con HttpServletResponse, que, por último, genera la página HTML o XML devuelta al cliente.

Empaquetamiento:

La aplicación web se empaqueta en un fichero .war, que contendrá:

  • Un directorio WEB-INF/classes, que contiene los ficheros .class
  • Un directorio WEB-INF/lib, con los ficheros .jar de librerías
  • Un directorio WEB-INF/web.xml -> configuración estándar de la aplicación web

3.1.2. Java Server Pages (JSP)

Una página JSP es un documento de texto que contiene HTML y bloques de código Java embebido que se ejecuta en el servidor para generar el contenido dinámico de una página web. Representa la parte de Vista del modelo MVC.

Es un lenguaje de marcado basado en etiquetas, con el que es fácil representar información. La forma de invocarlo es una URL que termina en .jsp.

Flujo de ejecución:

  • El cliente hace una petición HTTP al servidor web de una página JSP
  • El servidor web identifica la petición como una URL que está asociada con algo que se debe ejecutar en el contenedor web y reenvía la petición al contenedor
  • El contenedor sabe que la petición de una página JSP es la petición del servlet generado a partir de la página -> busca la clase compilada y generada a partir del JSP
  • Si es la primera vez, el servidor de aplicaciones genera un servlet (implementa javax.servlet.jsp.HttpJspPage) a partir de la página JSP, lo compila y lo carga en memoria
  • Si no es la primera vez, le pasa la petición al servlet (ya compilado y creado en memoria)

3.1.3. EJB (Enterprise JavaBeans)

Son los componentes de servidor que encapsulan la lógica de negocio de una aplicación. Se pueden ejecutar de forma distribuida.

Fundamentalmente son servicios que proporciona por programas que residen en un servidor web a otros programas que residen en otro servidor web mediante http.

Se ejecutan en contenedores EJB.

Historia de los EJB:

  • EJB 1.0: la especificación original
  • EJB 1.1: la primera incluida dentro de J2EE
  • EJB 2.0: incluida en J2EE 1.3, añadía las interfaces locales y los Message-Driven beans
  • EJB 2.1: incluida en la última revisión de J2EE, la 1.4
  • EJB 3.0: Ahora con Clúster y está incluida en JEE 5.1
  • EJB 3.1: incluida en JavaEE 6 en diciembre de 2009
  • EJB 3.2: incluida en JavaEE 7 y JavaEE 8

Tipos de EJBs:

  • Session beans
    • Transacción en el lado del servidor
    • No persistentes
    • Tipos:
      • SLSB -> sin estado (no guardan información entre diferentes llamadas del cliente)
      • SFSB -> mantienen estado entre llamadas del cliente (muy pesados -> mantenerse en memoria)
  • Entity beans
    • Entidades del negocio que perduran en el tiempo (mapean una tabla de un SGBD para hacer de caché)
    • Tipos:
      • BMP -> la persistencia la gestiona el propio bean mediante instrucciones del desarrollador
      • CMP -> persistencia gestionada por el contenedor
  • Message-driven beans
    • Similares a los beans de sesión, pero trabajan de forma asíncrona
    • Útiles cuando las operaciones a realizar son muy costosas en tiempo

3.1.4. Contenedores

Es el software responsable de ofrecer servicios de ejecución a los componentes J2EE. Estos servicios se prestan a través del conjunto de APIs.

Las llamadas a las APIs se hacen a través de los contenedores.

Tipos de contenedores:

  • Contenedores de applets
  • Contenedores de aplicaciones Java en cliente
  • Contenedores de componentes web
  • Contenedores de EJBs: Lugar donde residen y se ejecutan los EJBs instalados en un servidor de aplicaciones

3.1.4.1. Contenedor Web

Un contenedor web es el encargado de ejecutar los componentes web (servlets y páginas web creadas con JSF o JSPs) y de proporcionarles los servicios necesarios de seguridad, concurrencia, transacciones, implantación, etc.

Es importante no confundir un contenedor web con un servidor web: un servidor web está optimizado fundamentalmente para servir páginas HTML estáticas, mientras que un contenedor web actúa como una capa intermedia de software entre el servidor web y el servlet.

Funcionamiento:

  1. El servidor web transmite la petición HTTP al contenedor, éste crea un objeto que implementa la interfaz HttpServletRequest y pasa la petición al servlet.
  2. El servlet ejecuta su lógica, haciendo las llamadas oportunas a la lógica de negocio y genera una respuesta que el contenedor transmite al servidor web.
  3. Por cada petición HTTP el contenedor es responsable de crear y gestionar un nuevo hilo de ejecución que sirva la petición.

3.1.4.2. Contenedor EJB

El contenedor de EJB es el lugar donde residen y se ejecutan los EJBs instalados en un servidor de aplicaciones Java EE. Proporciona a los EJB un conjunto de servicios como caché, concurrencia, persistencia de los objetos, seguridad, gestión de transacciones, bloqueos, etc.

Un contenedor de EJBs se arranca automáticamente cuando se arranca el servidor de aplicaciones. En un mismo contenedor pueden residir varios EJBs.
