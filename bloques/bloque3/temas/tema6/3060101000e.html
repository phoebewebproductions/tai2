Java es un lenguaje multiplataforma, concurrente y de propósito general. Se puede considerar un lenguaje Orientado a Objetos "puro" (algunos autores no consideran Java como puro, porque en Java todos los tipos, a excepción de los tipos fundamentales de variables (int, char, long...) son clases. Sin embargo, en los lenguajes orientados a objetos puros incluso estos tipos fundamentales son clases, por ejemplo, en Smalltalk).

En el cliente se necesita JRE (Java Runtime Environment) que aporta JVM (Java virtual machine).

Entorno de ejecución

Esquema de compilación:

  • Ficheros .java
  • Ficheros .class (bytecode) o .jar (bytecode comprimido)
  • Un .class por cada clase -> sólo clases concretas internas, las abstractas no
  • No genera código máquina para una CPU concreta, sino código binario intermedio que debe interpretar la JVM
  • No se compila para una máquina, sino para una máquina virtual, Cualquier bytecode se puede ejecutar en una máquina virtual, que se debe instalar en todos los equipos.
  • El intérprete, cada vez que ejecuta necesita una traducción previa
  • En la compilación, se compila una vez y se ejecuta una. El intérprete va línea a línea. El programa como un todo -> más eficiente

Fichero jar:

Fichero que reúne clases, imágenes, sonidos, etc. para la ejecución de un applet o aplicación java

Contiene:

  • Subdirectorio META-INF
  • Fichero MANIFEST.MF -> codificación utilizada, directorio donde instalar, etc.
  • Ficheros con extensión .sf -> información de la firma de clases y aplicaciones. Uno por cada fichero firmado
  • Firmas digitales de ficheros con extensión que depende del formato de firma

Compilación e Interpretación

Java es compilado por una parte e interpretado por otro.

JIT (just in time compilation)

  • Ahora Java trabaja así.
  • En el instante en el que se detecta el bytecode se obtiene un ejecutable, se puede reutilizar n veces. Compilación realizada durante la ejecución del programa.
  • Buena solución para tiempos de respuesta optimizados
  • Por defecto, ejecución en java y compilación de JIT -> aquí java sería compilado.

Java EE

Es una especificación detallada de cada una de las tecnologías dentro de la plataforma Java EE.

Es como si fueran un conjunto de reglas que dictan como debe desarrollarse ese producto de tal forma que se pueda garantizar que una aplicación desarrollada siguiendo las especificaciones de Java EE pueda desplegarse y ejecutarse.

Java Platform Enterprise Edition o Java EE. Anteriormente conocido como Java 2 Platform Enterprise Edition o J2EE hasta la versión 1.4., es una plataforma de programación para desarrollar y ejecutar software de aplicaciones en el lenguaje de programación Java. Nos permite utilizar arquitecturas de N capas distribuidas.

Java EE no es un producto de Sun (Oracle), es un conjunto de especificaciones que permiten soluciones para el desarrollo, despliegue y gestión de aplicaciones multicapa centradas en servidor. La plataforma Java EE está definida por una especificación, eso quiere decir que cualquier fabricante puede coger estas especificaciones y desarrollar un producto final que las cumpla.

Como ocurre con otras especificaciones del Java Community Process, Java EE es considerado informalmente como un estándar debido a que los proveedores deben cumplir ciertos requisitos de conformidad para declarar que sus productos son conformes a Java EE; estandarizado por The Java Community Process / JCP.
