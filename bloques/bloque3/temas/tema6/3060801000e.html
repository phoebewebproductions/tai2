8.1 ARQUITECTURA MICROSOFT .NET

La arquitectura .Net ha sido desarrollada por Microsoft para dar solución al cambio de paradigma cliente/servidor hacia el modelo Web.

El modelo Web se articula en un conjunto de capas que contienen conjuntos de información y de aplicaciones.

Características principales:

  • Presentan pocas dependencias entre capas ("loosely connected")
  • Las capas pueden residir en distintas plataformas hardware

8.1.1 Retos actuales del desarrollo de software

  • Desarrollo rápido de aplicaciones y su distribución
  • Administración y gestión de las plataformas:
    • No existe un estándar del navegador
    • El desarrollo de aplicaciones es más difícil
    • Gran número de publicadores de contenido
    • Servicio 24/7/365
  • Desarrollo de aplicaciones distribuidas para entornos móviles

8.1.2 Soluciones .NET

La arquitectura .NET ofrece:

  • Aplicaciones Web: ASP.NET
  • Servicios: ASP.NET y WCF (Windows Communication Foundation)
  • Aplicaciones en la nube: Azure
  • Aplicaciones para dispositivos móviles: SilverLight, XNA
  • Aplicaciones de escritorio: WinForms, WPF (Windows Presentation Foundation)

8.1.3 Arquitectura en capas

Capa de presentación:

  • Cliente pesado: Windows FORMS, Win 32 API
  • Cliente ligero: Navegador Web
    • Aplicaciones en ASP.NET o con XML WebServices
    • Mayor portabilidad entre diferentes plataformas

Capa de lógica de negocio:

  • Denominada capa empresarial en Microsoft
  • Compuesta por Workflows, Componentes, Entidades e interfaz de servicios
  • Se aloja en servidores de aplicaciones o Servicios
  • Servicios a través de Enterprise Services (Componentes COM+)

Capa de Acceso a datos:

  • ADO.NET: acceso fácil a los datos
  • OLE.DB: proveedor de datos universal en .NET
  • XML: lenguaje estándar para definir estructuras de datos

8.1.4 Políticas de la arquitectura

  • Políticas de Seguridad: Autenticación, Autorización, Manejo de Perfiles, Auditoría
  • Políticas de Administración: Gestión de Excepciones, Monitorización, Configuración, Publicación de Servicios
  • Políticas de Comunicación: elección de modelos de telecomunicaciones, síncrono/asíncrono, protocolos

Principios de diseño:

Objetivos del diseño de una aplicación distribuida:

  • Requisitos funcionales:
    • Funcionalidad
    • Flexibilidad
    • Accesibilidad
  • Requisitos operacionales:
    • Seguridad
    • Rendimiento (Performance)
    • Disponibilidad (24/7/365)
    • Fiabilidad
    • Escalabilidad
    • Administrable
    • Mantenibilidad
