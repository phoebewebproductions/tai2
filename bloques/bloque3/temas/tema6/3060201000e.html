2.1. Concepto de aplicación web

Antes de adentrarnos en el estudio de la arquitectura JavaEE, es necesario el conocer lo que es una aplicación web, ya que como ya veremos es una parte fundamental de la arquitectura JavaEE en la actualidad el grueso de aplicaciones que se desarrollan están orientadas hacia usuarios que interactúan con ellas a través de interfaces web.

La característica más importante que caracteriza a una aplicación web es que no es una aplicación monolítica, sino que es un conjunto de componentes que se ejecutan en diferentes capas ubicadas tanto en el cliente como en la parte servidora para que, conjuntamente, logren el objetivo para el cual han sido desarrolladas.

El cambio hacia esta nueva forma de desarrollar aplicaciones ha motivado que los equipos de desarrollo de aplicaciones tengan que especializarse en cada capa, de igual manera que los lenguajes de programación.

2.2. Arquitectura multicapa

El principio fundamental de este tipo de arquitectura radica en dividir el sistema a desarrollar en diferentes capas o niveles que se comunican entre sí para lograr la funcionalidad mediante el uso de interfaces.

Capas principales:

  • Capa de presentación: encargada de la interacción cliente-interfaz.
  • Capa de lógica de negocio: donde se recepcionan las peticiones dirigidas desde la capa de presentación y se ejecuta la lógica transaccional del sistema.
  • Capa de persistencia o datos: donde se almacenan los datos necesarios para mantener el sistema.

Características principales:

  • Escalabilidad y mayor rendimiento
  • Integridad transaccional
  • Robustez
  • Interoperabilidad
  • Seguridad

2.3. Patrón Modelo-Vista-Controlador (MVC)

El patrón de diseño MVC es un modelo que logra dividir la funcionalidad de un sistema o aplicación en diferentes componentes de forma lógica y ordenada.

Niveles del modelo:

  • Nivel "modelo": representa los componentes que implementan el acceso a los datos del sistema y las reglas funcionales del mismo (reglas de negocio). Es habitual el uso del patrón DAO (Data Access Object) para el desarrollo del modelo.
  • Nivel "vista": se encarga de la interfaz de usuario que se encargará de interactuar con él y presentar los resultados obtenidos por los componentes del nivel "modelo". Para implementarlo es habitual el uso de tecnología JSP, páginas ASP, XML/XSL.
  • Nivel "controlador": se encarga de dirigir qué resultados mostrar al nivel "vista" dependiendo del tipo de usuario que interactúa con el sistema.

Para terminar, mencionaremos que cada nivel es independiente del resto por lo que cualquier modificación en los componentes de cada uno de ellos no debería afectare al resto de componentes de otros niveles.
