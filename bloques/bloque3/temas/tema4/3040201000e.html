2. DML (LENGUAJE DE MANIPULACIÓN DE DATOS)

🔄

Lenguaje que permite la manipulación y recuperación de datos. El más popular es SQL.

2.1. COMENTARIOS

Como todo lenguaje que se precie, el ANSI SQL permite introducir comentarios dentro de los scripts.

  • • Los comentarios de una línea van precedidos por dos guiones "--".
  • • Los comentarios multi línea siguen el estándar de C++. Van encerrados entre /* Comentario */

Se permiten los comentarios anidados.

2.2. SELECT

🔍

Consulta de datos

Permite obtener datos de la base de datos. Los datos devueltos se almacenan en la tabla de resultados denominada result-set.

SELECT Columna1, Columna2, ... FROM tabla;
SELECT * FROM Tabla;

Si la sentencia SELECT contiene campos de más de una tabla deben tener un nombre único o usar la forma Tabla.Campo para evitar ambigüedades.

Los nombres de las columnas y de las tablas pueden ser renombrados mediante un alias con la cláusula AS.

SELECT Columna1 AS nombreNuevo1 FROM tabla
SELECT Columna1, Columna2 FROM tabla AS nombreTable

El uso de alias se utiliza principalmente para:

  • • Renombrar una columna con un nombre más descriptivo (o en otro idioma)
  • • Darle un nombre a una expresión generada sobre los campos
  • • Darle un nombre más "manejable" a una tabla que va a ser utilizada posteriormente en la consulta sql.

2.3. WHERE

🔎

Filtrado de datos

Permite filtrar los datos que se desean obtener o sobre los que se desea trabajar.

SELECT Columna1, Columna2, ... FROM Tabla WHERE condicion;

Condición puede ser cualquier condición lógica o aritmética

Condición: CAMPO operador VALOR

Por ejemplo, dada una tabla con un campo edad podríamos efectuar las siguientes consultas:

SELECT * FROM Clientes WHERE Edad = 18

2.5. LIKE

🔍

Búsqueda por patrones

El operador Like se utiliza junto a la cláusula WHERE para especificar un patrón de búsqueda.

Los caracteres comodín utilizados normalmente son:

  • • '%' representa una cadena de cero o más caracteres.
  • • '_' representa un único carácter.
  • • '\' carácter de escape. Se utiliza para poder usar los caracteres '%' y '_' como tal no como comodines ('\%', '\_', '\\').
LIKE Descripción
WHERE NOMBRE LIKE 'a%' Devuelve las filas cuyo nombre empieza con "a"
WHERE NOMBRE LIKE '%a' Devuelve las filas cuyo nombre termina con "a"
WHERE NOMBRE LIKE '%or%' Devuelve las filas cuyo nombre contienen "or" en cualquier posición
WHERE NOMBRE LIKE '_r%' Devuelve las filas cuyo nombre contiene una "r" en la segunda posición
WHERE NOMBRE LIKE 'a_%' Devuelve las filas cuyo nombre empieza con "a" y tiene al menos dos caracteres.
WHERE NOMBRE LIKE 'a__%' Devuelve las filas cuyo nombre empieza con "a" y tiene al menos tres caracteres.
WHERE NOMBRE LIKE 'a%o' Devuelve las filas cuyo nombre empieza con "a" y termina con una "o" (como "Antonio")

2.8. CASE

🔀

Evaluación condicional

Estructura parecida a un Switch o SELECT CASE de un lenguaje tradicional. Devuelve un valor cuando se cumple la condición indicada. Si varias condiciones se cumplen, devuelve el valor de la que primero se cumpla

CASE
    WHEN condicion1 THEN resultado1
    WHEN condicion2 THEN resultado2
    WHEN condicionN THEN resultadoN
    ELSE resultado
END

SELECT precio, cantidad,
CASE
    WHEN cantidad >= 20 THEN 0.10
    WHEN cantidad >= 10 THEN 0.5
    ELSE 0
END AS descuento
FROM pedidos;

2.9. SELECT DISTINCT

🔍

Selección de valores únicos

Permite filtrar las filas seleccionadas originalmente devolviendo sólo las que tienen valores diferentes en las columnas en las que se aplica el DISTINCT.

SELECT DISTINCT columna1, columna2… FROM table
SELECT DISTINCT provincia FROM pedidos

2.10. SELECT TOP

🔝

Limitación de resultados

Permite delimitar el número de registros que se devuelven que cumplen la condición.

SELECT TOP número|PERCENT FROM table WHERE condicion
SELECT TOP 50 PERCENT FROM clientes
SELECT TOP 50 FROM clientes

2.11. ORDER BY

↕️

Ordenación de resultados

Ordena el result-set obtenido por la columna especificada de forma ascendente o descendente.

SELECT DISTINCT columna1, columna2… FROM table ORDER BY
columna1, columna2…. [ASC|DESC]
SELECT * from alumnos order by nombre asc, ap1 asc, ap2 asc

La forma de ordenación predeterminada si se omite es ascendente

2.12. FUNCIONES DE AGREGADO

📊

Cálculos sobre conjuntos

Funciones que permiten trabajar sobre el resultado como un conjunto no como registros individuales. Devuelven un solo valor que es el resultado obtenido al aplicar la función de agregado sobre el conjunto seleccionado.

Las funciones de agregado más utilizadas son:

Función Uso
AVG(expresion) Media aritmética
COUNT(expression) Cuenta las filas cuyo valor es no nulo
COUNT(*) Cuenta todas las filas de una tabla
MIN(expression) Devuelve el valor mínimo de la expresión
MAX(expression) Devuelve el valor máximo de la expresión
SUM(expression) Devuelve el sumatorio de la expresión

La expression típica suele ser un campo, pero puede ser una operación con los campos.

SELECT SUM(salario) FROM datosFinancieros
SELECT SUM(salarioMensual*14) AS saldoAnual FROM datosFinancieros

2.13. GROUP BY

🔄

Agrupación de resultados

Agrupa los resultados que tienen los mismos valores en la columna especificada de agrupamiento. Siempre se utiliza junto a funciones de agregado, para obtener subtotales por grupo.

SELECT columnas FROM tabletabla WHERE condicion
GROUP BY Columna1, Columna2, …
SELECT COUNT(IDCliente), Pais FROM Clientes
GROUP BY Pais;

2.14. HAVING

🔍

Filtrado de grupos

Permite especificar una condición al resultado agrupado obtenido. La cláusula WHERE establece la condición que debe cumplir cada registro, la cláusula HAVING establece la condición que debe cumplir el valor una vez agrupado.

SELECT columnas FROM tabla WHERE condition
GROUP BY columna HAVING condición

2.15. INSERT INTO

➕

Inserción de datos

Permite insertar registros nuevos en la tabla

INSERT INTO table (columna1, columna2,…) VALUES (valor1, valor2, …)

2.16. UPDATE

🔄

Actualización de datos

Permite modificar registros existentes en la tabla que cumplan el criterio de la cláusula WHERE. Atención, si no se especifica una clausula WHERE se actualizará todo el contenido de la tabla.

UPDATE tabla SET columna1=valor1, columna2=valor2,… WHERE condición
UPDATE datosPersonales SET apellido1='Rodriguez' WHERE idPersonal=23452
UPDATE datosFinancieros SET salario=salario*1.01 WHERE nivel > 20

2.17. DELETE

❌

Eliminación de datos

Permite eliminar registros existentes en la tabla que cumplan el criterio de la cláusula WHERE. Atención, si no se especifica una clausula WHERE se borrará todo el contenido de la tabla.

DELETE FROM tabla where condicion
DELETE FROM clientes where idCliente=2342
DELETE FROM clientes where fechaUltimaCompra < '2005-12-31'

2.18. JOINS

🔗

Combinación de tablas

La clausula JOIN se utiliza para combinar filas de dos o más tablas basándose en las columnas relacionadas entre ellas.

Las relaciones entre tablas pueden estar especificadas y reforzadas dentro de la propia base de datos a través de las reglas de integridad referencial o pueden ser establecidas en la propia consulta SQL.

La relación más típica es la de igualdad. Dos registros de dos tablas distintas están relacionadas si tienen el mismo valor en el campo especificado.

Existen diferentes tipos de JOINs:

  • • (INNER) JOIN: JOIN interior
  • • OUTER JOINs: JOINS exteriores
    • ◦ LEFT (OUTER) JOIN
    • ◦ RIGHT (OUTER) JOIN
    • ◦ FULL (OUTER) JOIN

2.19. INNER JOIN

🔄

Unión interna

Selecciona sólo los registros coincidentes de ambas tablas, descarta todos los registros que no tienen su correspondencia en la otra tabla.

SELECT columnas FROM tabla1
INNER JOIN tabla2
ON tabla1.columna1 = table2.columna2;

-- Inner Join de dos tablas: Obtenemos el id de pedido y el
nombre de los clientes de los clientes que tienen pedidos (o de
los pedidos que tienen un cliente asociado suponiendo que
pudiera haber pedidos sin cliente asociado…)
SELECT Pedidos.IDPedido, Clientes.Nombre FROM Pedidos
INNER JOIN Clientes ON Pedidos.FKCliente = Clientes.IDCliente;

-- Inner Join de tres tablas: Obtenemos el id de pedido, nombre
de los clientes, y nombre del transportista de los clientes
que tienen pedidos con transportista ya asociado. Si, por
ejemplo, un pedido todavía no tiene transportista asociado no
aparecerá en el resultado
SELECT Pedidos.IDPedido, Clientes.Nombre, Transportistas.Nombre
FROM ((Pedido
INNER JOIN Clientes ON Pedidos.FKCliente = Clientes.IDCliente)
INNER JOIN Transportistas ON Pedidos.FKTransportista =
Transportistas.IDTransportista);

2.20. LEFT JOIN

⬅️

Unión izquierda

Selecciona todos los registros de la tabla izquierda y sólo los registros coincidentes de la tabla derecha.

SELECT columnas FROM tabla1
LEFT JOIN tabla2
ON tabla1.columna1 = table2.columna2;

-- Left Join de dos tablas: Obtenemos el id de pedido y el
nombre de TODOS los clientes incluyendo los que tienen pedidos
(si algún cliente no tiene pedidos aparecerá NULL en IDPedido)
SELECT Pedidos.IDPedido, Clientes.Nombre FROM Clientes
LEFT JOIN Pedidos ON Pedidos.FKCliente = Clientes.IDCliente;

2.21. RIGHT JOIN

➡️

Unión derecha

Selecciona todos los registros de la tabla derecha y sólo los registros coincidentes de la tabla izquierda.

SELECT columnas FROM tabla1
RIGHT JOIN tabla2
ON tabla1.columna1 = table2.columna2;

-- Right Join de dos tablas: Obtenemos el id de pedido y el
nombre de TODOS los clientes incluyendo los que tienen pedidos
(si algún cliente no tiene pedidos aparecerá NULL en IDPedido).
Atención: Se han cambiado de lugar el nombre de las tablas para
que ahora la de clientes esté a la derecha del JOIN
SELECT Pedidos.IDPedido, Clientes.Nombre FROM Pedidos
RIGHT JOIN Clientes ON Pedidos.FKCliente = Clientes.IDCliente;

2.22. FULL JOIN

↔️

Unión completa

Selecciona todos los registros de la tabla izquierda y todos los registros de la tabla derecha. Rellena a NULL los valores que no tienen correspondencia.

2.23. UNION

🔄

Combinación de resultados

Permite combinar resultados de dos o más tablas:

  • • Cada sentencia SELECT de la UNION tiene que tener el mismo número de columnas
  • • Las columnas tienen que tener tipos de datos similares
  • • Las columnas en el mismo SELECT tienen que tener el mismo orden
  • • UNION sólo valores DISTINCT, UNION ALL permite registros duplicados
SELECT columnas FROM tabla1
UNION | UNION ALL
SELECT columnas FROM tabla2;

🔍

Consultas anidadas

Una consulta puede ser utilizada en lugar de una tabla.

SELECT precio, nombre FROM productos WHERE precio >

2.25. EXISTS

🔍

Comprobación de existencia

Permite comprobar la existencia de un registro en una subconsulta. La ventaja es que en cuanto encuentra un registro que cumple la condición deja de buscar.

SELECT columnas FROM tabla1 WHERE EXISTS
(SELECT columna FROM tabla2 WHERE condicion);

-- Comprobamos si tenemos algún producto sin stock en el
inventario
SELECT nombre FROM productos WHERE EXISTS
(SELECT fkProducto FROM inventario WHERE productos.idProducto =
inventario.fkProducto AND cantidad = 0);

2.26. ANY/ALL

🔍

Comparación con rangos

Permiten comparar el valor de una columna con un rango de valores

SELECT columnas FROM tabla1 WHERE columna operador ANY
(SELECT columnas FROM tabla WHERE condicion);

SELECT columnas FROM tabla1 WHERE columna operador ALL
(SELECT columnas FROM tabla WHERE condicion);

2.27. INSERT INTO SELECT

➕

Inserción desde consulta

Permite copiar datos de una tabla en otra. Para ello requiere que los tipos de datos de la tabla destino coincidan con los de la tabla origen.

INSERT INTO tabla2
SELECT * FROM tabla1

INSERT INTO tabla2 (columna1, columna2, columna3, ...)

📋

Creación de tabla desde consulta

Permite copiar datos de una tabla en otra nueva. La propia sentencia crea la tabla infiriendo los tipos de datos de las columnas a partir de la tabla original

SELECT *
INTO nuevaTabla [IN bbdd]
FROM tabla1
WHERE condicion;

SELECT columna1, columna2, columna3, ...
INTO nuevaTabla [IN bbdd]
FROM tabla1
WHERE condicion;

2.30. TRIGGERS

⚡

Disparadores automáticos

Un trigger o disparador es un objeto que se asocia con tablas, se almacena en la base de datos y se ejecuta cuando sucede algún evento sobre las tablas a las que se encuentra asociado. Los eventos que desencadenan un trigger son las operaciones de inserción (INSERT), borrado (DELETE) o actualización (UPDATE). El SELECT no activa un trigger puesto que no modifica los datos de una tabla.

2.30.1. TIPOS DE TRIGGERS

  • • Before statement: Se ejecuta antes de ejecutar la sentencia de disparo.
  • • Before row: Se ejecuta antes de modificar cada fila afectada por la sentencia de disparo, y antes de chequear las restricciones de integridad apropiadas.
  • • After statement: Se ejecuta después de ejecutar la sentencia de disparo, y después de chequear las restricciones de integridad apropiadas.
  • • After row: Se ejecuta después de modificar cada fila afectada por la sentencia de disparo y posiblemente aplicando las restricciones de integridad apropiadas.
CREATE TRIGGER <Trigger name>
{BEFORE | AFTER} <trigger event> ON <Table name>
[ REFERENCING <old or new values alias list> ]
<triggered action>

<trigger event> ::=
INSERT |
DELETE |
UPDATE [ OF <trigger Column list> ]

<trigger Column list> ::= <Column name> [ {,<Column name>} ... ]

<old or new values alias list> ::=
<old or new values alias>...

<old or new values alias> ::=
OLD [ ROW ] [ AS ] old values <Correlation name> |
NEW [ ROW ] [ AS ] new values <Correlation name> |
OLD TABLE [ AS ] <old values Table alias> |
NEW TABLE [ AS ] <new values Table alias>

<old values Table alias> ::= <identifier>
<new values Table alias> ::= <identifier>

<triggered action> ::=
[ FOR EACH {ROW | STATEMENT} ] [ WHEN (search condition) ]
<triggered SQL statement>

<triggered SQL statement> ::=
SQL statement |
BEGIN ATOMIC {SQL statement;}... END

2.31. TRANSACCIONES

🔄

Operaciones atómicas

Una transacción en un sistema de gestión de bases de datos es un conjunto de órdenes que se ejecutan formando una unidad de trabajo, es decir, en forma indivisible o atómica.

Un SGBD se dice transaccional si es capaz de mantener la integridad de datos, haciendo que estas transacciones no puedan finalizar en un estado intermedio. Cuando por alguna causa el sistema debe cancelar la transacción, empieza a deshacer las órdenes ejecutadas hasta dejar la base de datos en su estado inicial (punto de integridad), como si la orden de la transacción nunca se hubiese realizado.

Una transacción debe contar con ACID (un acrónimo inglés) que quiere decir: Atomicidad, consistencia, aislamiento y durabilidad.

  • • Atomicidad (Atomicity): es la propiedad que asegura que la operación se ha realizado o no, y por lo tanto ante un fallo del sistema no puede quedar a medias.
  • • Consistencia (Consistency): es la propiedad que asegura que sólo se empieza aquello que se puede acabar. Por lo tanto, se ejecutan aquellas operaciones que no van a romper la reglas y directrices de integridad de la base de datos.
  • • Aislamiento (Isolation): es la propiedad que asegura que una operación no puede afectar a otras. Esto asegura que la realización de dos transacciones sobre la misma información nunca generará ningún tipo de error.
  • • Durabilidad (Durability): es la propiedad que asegura que una vez realizada la operación, ésta persistirá y no se podrá deshacer aunque falle el sistema.

El lenguaje de consulta de datos SQL provee los mecanismos para especificar que un conjunto de acciones deben constituir una transacción mediante el Lenguaje de control de transacciones (TCL Transaction Control Language).

  • • BEGIN TRANSACTION: Especifica que va a empezar una transacción.
  • • COMMIT TRANSACTION: Le indica al motor que puede considerar la transacción completada con éxito.
  • • ROLLBACK TRANSACTION: Indica que se ha alcanzado un fallo y que debe restablecer la base al punto de integridad.
  • • SAVEPOINT: Permite crear puntos de guardado para poder hacer rollback a ese punto en vez de tener que deshacer la transacción al completo.

En un sistema ideal, las transacciones deberían garantizar todas las propiedades ACID; en la práctica, a veces alguna de estas propiedades se simplifica o debilita con vistas a obtener un mejor rendimiento.
