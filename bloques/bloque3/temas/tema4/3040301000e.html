4. DDL (LENGUAJE DE DEFINICIÓN DE DATOS)

Se encarga de la modificación de la estructura de los objetos de la base de datos. Incluye órdenes para modificar, borrar o definir las tablas en las que se almacenan los datos de la base de datos. Existen cuatro operaciones básicas: CREATE, ALTER, DROP y TRUNCATE.

4.1. CREATE

Crea objetos de la base de datos. Se utiliza para crear bases de datos, tablas, vistas, procedimientos almacenados…

CREATE DATABASE nombreBBDD;
CREATE TABLE nombreTabla;

4.2. ALTER

Modifica objetos existentes de la base de datos. Se utiliza para modificar bases de datos, tablas, vistas, procedimientos almacenados…

ALTER DATABASE nombreBBDD;
ALTER TABLE nombreTabla;
ALTER TABLE clientes ADD movil varchar(50);

4.3. DROP

Elimina objetos existentes de la base de datos. Se utiliza para eliminar bases de datos, tablas, vistas, procedimientos almacenados…

DROP DATABASE nombreBBDD;
DROP TABLE nombreTabla;
DROP TABLE clientes;

4.4. TRUNCATE

Elimina todo el contenido de una tabla. Es mucho más rápido que la operación de DELETE. Básicamente TRUNCATE borra la tabla con un DROP y la vuelve a crear con un CREATE.

TRUNCATE TABLE nombreTabla;
TRUNCATE TABLE clientes;

4.5. CONSTRAINTS

Las constraints son restricciones utilizadas para especificar reglas que tengan que cumplir los datos contenidos en una tabla. Las constraints pueden ser especificadas durante la creación o modificación de una tabla (CREATE o ALTER)

CREATE TABLE nombreTabla (
    columna1 datatype constraint,
    columna2 datatype constraint,
    columna3 datatype constraint,
    ....
);

Las restricciones más utilizadas son:

  • NOT NULL: Especifica que el atributo (columna) no puede tener un valor nulo.
  • UNIQUE: Establece que todos los valores del atributo deben ser diferentes.
  • PRIMARY KEY: Combinación de NOT NULL y UNIQUE. Identifica inequívocamente un registro en una tabla.
  • FOREIGN KEY: Evita que ciertas acciones rompan relaciones entre tablas.
  • CHECK: Establece que los valores de una columna satisfice una determinada condición.
  • DEFAULT: Establece un valor por defecto si no se da un valor al atributo.

CREATE INDEX

Utilizado para convertir el atributo en un índice. Esto permite que las búsquedas y filtrados por el valor de ese atributo sean más rápidas.

CREATE INDEX index_name
ON table_name (column1, column2, ...);

CREATE UNIQUE INDEX index_name
ON table_name (column1, column2, ...);

4.6. ESQUEMAS

Un esquema en SQL es una colección de objetos de base de datos asociados con una base de datos. El nombre de usuario de una base de datos se denomina propietario de esquema (propietario de estructuras de datos agrupadas lógicamente). Cada esquema siempre pertenece a una sola base de datos, mientras que una base de datos puede tener uno o varios.

CREATE SCHEMA [schema_name] [AUTHORIZATION owner_name]
[DEFAULT CHARACTER SET char_set_name]
[PATH schema_name[, ...]]
[ ANSI CREATE statements [...] ]
[ ANSI GRANT statements [...] ];

5. TIPOS DE DATOS ANSI SQL

ANSI SQL define varios tipos de datos estándar. Diferentes sistemas de gestión de bases de datos pueden implementar estos tipos de datos de manera ligeramente diferente. Algunos de los tipos de datos ANSI SQL comunes incluyen:

  • CHARACTER, VARCHAR: Para cadenas de caracteres
  • NUMERIC, DECIMAL: Para números exactos
  • INTEGER, SMALLINT: Para números enteros
  • FLOAT, REAL, DOUBLE PRECISION: Para números de punto flotante
  • DATE, TIME, TIMESTAMP: Para fechas y horas
  • BOOLEAN: Para valores lógicos
  • BLOB, CLOB: Para datos binarios y caracteres largos

Es importante consultar la documentación específica de cada sistema de gestión de bases de datos para conocer los detalles de implementación de estos tipos de datos.
