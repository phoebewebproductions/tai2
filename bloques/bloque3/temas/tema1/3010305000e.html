3.5.1 AMPLIACIÓN DE WARD Y MELLOR

🔄

Ward y Mellor amplían la notación básica de los diagramas de flujo de datos para que se adapte a las siguientes a los sistemas de tiempo real:

  • • Flujo de información que es recogido o producido de forma continua en el tiempo.
  • • Información de control que pasa por el sistema y el procesamiento de control asociado.
  • • Ocurrencias múltiples de la misma transformación que se encuentran a menudo en situaciones de multitarea.
  • • Estados del sistema y mecanismos que producen transición de estados en el sistema

Es decir, se emplea en sistemas de tiempo real y se representa de la siguiente forma:

Elementos de la Ampliación de Ward y Mellor

Elemento Representa Características
Procesos de control
  • Representan: Procesamiento de señales de control.
  • Representan: Coordinación y sincronización de actividades de otros procesos.
  • Representan: Activación/desactivación de procesos.
  • Ward y Mellor, y Métrica v3.
  • Señales de control pueden ser: Entrada/salida
Procesos múltiples
  • Representan: Varias instancias de un mismo proceso.
  • Ward y Mellor.
Almacenes de control
  • Representan: Almacén de info./señal de control (del sistema).
  • Ward y Mellor.
Flujos de control
  • Representan: Transmisión de señales de control a procesos (salen de proceso origen para activar proceso destino).
  • Ward y Mellor, y Métrica v3.
  • Flujos de control = Eventos.
Flujos de datos continuos
  • Representan: Flujos de datos → Entran/salen de un proceso (de forma constante/continua).
  • Ward y Mellor.

3.5.2 TÉCNICAS ALTERNATIVAS O COMPLEMENTARIAS AL DFD

Existen otras técnicas complementarios o alternativas para la definición de los diagramas de flujo de datos que se presentan en la siguiente tabla:

Técnica Descripción Procedimiento
SRD (Structured Requirement Definition – Definición de Requisitos Estructurados) Método para completar conj. de entradas y salida de sist. de info.
  1. Definir DFD de nivel de usuario: Para cada usuario se registran en un DFD:
    • Entradas que produce el sistema.
    • Salidas que produce el sistema.
  2. Definir DFD de nivel de usuario combinado.
  3. Definir DFD de nivel de aplicación (diagrama del contexto – entradas y salidas externas).
  4. Definir funciones del nivel de aplicación (entradas y salidas del sistema para mostrar el orden de sucesos).
SADT (Structured Analisys & Design Technique – Técnica de Análisis y Diseño Estructurado)
  • Método para construir modelo del problema.
  • Método emplea notación gráfica para representación.
  • Método compuesto por jerarquía de diagramas.
  1. Obtener Jerarquía de diagramas:
    • Diagrama de contexto define problema de forma abstracta.
    • Caja representa acciones del problema.
    • Flecha representa interconexiones entre cajas (flechas entran por izqda./arriba/abajo; flechas salen por dcha.).
SASS (Structured Analisys & System Specification – Análisis Estructurado y Especificación del Sistema) Método que representa y refina continuamente diagrama de contexto.
  1. Obtener DFD físico actual (muestra flujos de datos producidos en la organización NO automatizada).
  2. Obtener equivalentes lógicos.
  3. Verificar modelo (por parte del cliente).
  4. Definir alternativas de automatización diferentes.
  5. Analizar alternativas de automatización (junto con el cliente).
  6. Seleccionar 1 de los DFD físicos para su implementación.
