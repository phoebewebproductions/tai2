3.4. DICCIONARIO DE DATOS

📚

El diccionario de datos (DD) es un elemento u obra de consulta con información sobre los datos (metadatos) creados por el analista de sistemas con base en los diagramas de flujo de datos; recopila y coordina términos de datos específicos, confirmando lo que cada término significa para distintas personas en la organización. Es decir, el diccionario de datos es un repositorio en el que se almacena información sobre todos los elementos de datos definidos en los diagramas de flujo de datos.

Una razón importante para tener un diccionario es con el fin de mantener limpios los datos; es decir, para conservarlos consistentes.

🔍

Por ejemplo, si se almacena datos sobre el sexo de un hombre como "M" en un registro, "Masculino" en un segundo registro y como el número "1" en un tercer registro, los datos no están "limpios". En este aspecto el diccionario de datos será muy útil.

💻

Los diccionarios de datos automatizados (parte de las herramientas CASE - Computer Aided Software Engineering) son valiosos por su capacidad de realizar referencias cruzadas con los elementos de datos para permitir los cambios necesarios en todos los programas que compartan un elemento común. Gracias a esta característica ya no hay necesidad de modificar los programas al azar ni esperar hasta que el programa no se ejecute debido a un cambio que no se implementó en todos los programas que compartan el elemento actualizado.

Para describir brevemente (para cada elemento representado en DFD) los datos utilizados se emplea la notación BNF (Backus-Naier Form).

Características Principales

Las características principales de los diccionarios de datos son:

🔄
Actúan como unión entre diferentes modelos (puntos de vista) (como: estático, dinámico, funcional).
📝
Definen todo elemento (mediante: descripción de elemento + conjunto de posibles valores).
🔍
Sólo describe los flujos de datos entre entidades en caso de existencia de almacenes de datos del DFD.

Símbolos BNF

El formato o símbolos BNF son los siguientes:

Símbolo Significado
= Está compuesto por
+ Y
{ } Iteración, repetición (cero o más veces)
[ ] Selección, alternativa (una de las opciones)
( ) Opcional (cero o una vez)
| O (separador de alternativas)
** Comentario

Ejemplo de Notación BNF

Por ejemplo:

Lista Empleados = { Codigo Empleado + Nombre + Dirección }
Nombre = Titulo Cortesia + NombrePila + Apellido
TituloCortesia = [ "Sr" | "Sra" ]
NombrePila = { Caracter }
Apellido = { Caracter }
Caracter = [ "A"-"Z" | "a"-"z" ]

3.4.1. HERRAMIENTAS CASE

Se puede definir a las herramientas CASE como un conjunto de programas y ayudas que dan asistencia a los analistas, ingenieros de software y desarrolladores, durante todos los pasos del ciclo de vida de desarrollo de un software (estudio preliminar, análisis, diseño, implementación e instalación).

CASE es también definido como el conjunto de métodos, utilidades y técnicas que facilitan el mejoramiento del ciclo de vida del desarrollo de sistemas de información, completamente o en alguna de sus fases.

Se puede ver al CASE como la unión de las herramientas automáticas de software y las metodologías de desarrollo de software formales.

Relación entre Diccionario de Datos y Herramientas CASE

  • • El diccionario de datos interactúa con herramientas CASE.
  • • Para cada entrada insertada en un diccionario de datos, la herramienta CASE inspecciona los DFDs y demás componentes para determinar CÓMO usan el dato los procesos.

Beneficios de las Herramientas CASE

Las herramientas CASE permiten:

⚙️
Automatizar aspectos principales de todo proceso de desarrollo de un sistema.
📊
Desarrollar el modelo de datos corporativo y esquemas conceptual y lógico.
🖥️
Desarrollar los prototipos de aplicaciones.
📝
Generar programas desde una especificación hasta nivel de diseño.

Tipos de Herramientas CASE

Tipo Definición Actividades que cubre
CASE de alto nivel Automatizan fases iniciales/superiores del ciclo de vida de desarrollo de sistemas.
  • Fase de planificación de sistemas.
  • Fase de análisis de sistemas.
  • Fase de diseño de sistemas.
CASE de bajo nivel Automatizan fases finales/inferiores del ciclo de vida de desarrollo de sistemas.
  • Fase de diseño detallado de sistemas.
  • Fase de implantación de sistemas.
  • Fase de soporte de sistemas.
CASE de ciclo de vida Apoya actividades producidas durante ciclo de vida de desarrollo de sistemas.
  • Gestión de proyectos.
  • Estimación de proyectos.
