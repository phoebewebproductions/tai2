7. NoSQL

🗄️

Las aplicaciones interactivas han evolucionado mucho en los últimos años, al igual que las necesidades de administración de bases de datos para esas aplicaciones. Hoy en día, un nuevo tipo de base de datos no relacional conocido como "NoSQL" está ganando terreno en la empresa como un modelo alternativo para la gestión de bases de datos.

Las principales diferencias entre los SGBDs NoSQL con los SGBDR son las siguientes:

  • 🔄 No usan SQL como lenguaje principal de consultas.
  • 📊 Los datos almacenados no requieren estructuras fijas como tablas.
  • 🔗 Normalmente no soportan operaciones JOIN.
  • 🔒 Normalmente no garantizan completamente ACID (atomicidad, consistencia, aislamiento y durabilidad).
  • 📈 Habitualmente escalan bien horizontalmente.

Los sistemas NoSQL se denominan a veces "no solo SQL" para subrayar el hecho de que también pueden soportar lenguajes de consulta de tipo SQL.

La adopción de la tecnología NoSQL está impulsada en gran medida por tres tendencias correlacionadas: computación en la nube, gran cantidad de usuarios (de millones a miles de millones) y big data.

7.1. VENTAJAS

  • 📈
    Estos sistemas responden a las necesidades de escalabilidad horizontal que tienen cada vez más empresas.
  • 📊
    Pueden manejar enormes cantidades de datos.
  • 🚫
    No generan cuellos de botella.
  • 📈
    Escalamiento sencillo.
  • 🔄
    Diferentes bases de datos NoSQL para diferentes proyectos.
  • 💻
    Se ejecutan en clusters de máquinas baratas.

7.2. DESVENTAJAS

Las bases de datos NoSQL al ser de código abierto poseen un soporte diferente al soporte que ofrecen las compañías comerciales a sus productos. Esto puede presentar algunas ventajas y también algunas desventajas:

  • ⚠️
    Algunos productos pueden no estar lo suficientemente maduros para algunas empresas.
  • 🔍
    A pesar de sus puestas en práctica en algunas grandes empresas, las bases de datos NoSQL aún se enfrentan a un problema de credibilidad importante con muchas empresas.
  • 📊
    Limitaciones de Inteligencia de Negocios: Existen dudas de si pueden proporcionar la clase de minería de datos rigurosos que las empresas utilizan con las SGBDR.
  • 👨‍💻
    Falta de experiencia: La novedad de NoSQL implica que no hay una gran cantidad de desarrolladores y administradores que conocen la tecnología.
  • 🔄
    Problemas de compatibilidad: A diferencia de las bases de datos relacionales, que comparten ciertos estándares, las bases de datos NoSQL tienen pocas normas en común.

7.3. TIPOS DE BBDD NoSQL

Las bases de datos NoSQL tienen diferentes tipos de modelos en comparación con las RDBMS. Los tipos de modelos pueden dividirse en cuatro grupos:

  • 🔑 BBDD Clave/Valor
  • 📊 BBDD basadas en columnas (multivalor)
  • 📄 BBDD basadas en documentos (documentales)
  • 🔄 BBDD basadas en grafos

7.3.1. BBDD BASADAS EN COLUMNAS

Las BBDDs trabajan creando una colección de una o más claves/valores que corresponden a un registro específico. También son conocidas como almacenes extensibles de valores o almacenes orientados a columnas o multivalor.

APACHE HBASE
  • • Se ejecuta sobre HDFS (Sistema de archivos distribuido de Hadoop).
  • • Es seguro, escalable, distribuido, seguro y ofrece alta disponibilidad.
  • • Capaz de manejar grandes tablas de datos que contienen millones de columnas y miles de millones de filas.
  • • La estructura de reducción/mapa de Hadoop es ideal para trabajos computacionales complejos o consultas que se asignan a cada nodo.
CASSANDRA

El proyecto Apache Cassandra surgió de Facebook en 2008. Actualmente es una herramienta de base de datos completamente madura utilizada por la mayoría de los grandes almacenes de datos.

  • • Ofrece alta disponibilidad, tolerancia a fallos y escalabilidad en infraestructura de nube, sistemas virtuales o hardware.
  • • El mecanismo de Cassandra proporciona una mezcla híbrida de un almacén de clave/valor con una base de datos orientada a columnas.
  • • Permite indexación de columnas, vistas materializadas y desnormalizadas y almacenamiento en caché incorporado.
HYPERTABLE

Hypertable sigue el modelo de Bigtable de Google.

  • • Utiliza una compresión de datos de bloque y prefijo clave y tiene una estructura de tabla plana.
  • • Los datos se representan en tablas de información en columnas y filas; Hypertable tiene poca semejanza con un RDBMS tradicional.
  • • Características notables incluyen escalado en "tiempo real" y control de versiones de celdas, espacios de nombres y calificadores de columna.

Otras BBDDs basadas en columnas incluyen: Accumulo, Amazon SimpleDB, Clouddata, Cloudera, HPCC, Apache Flink, Splice Machine.

7.3.2. BBDD BASADAS EN ALMACÉN DE DATOS DE DOCUMENTOS

Los valores de cada clave están encapsulados en JSON o documentos JSON. Cada clave debe ser única. También se conocen como BBDD Documentales.

COUCHDB
  • • Diseñado específicamente para las necesidades de bases de datos de aplicaciones web.
  • • Carece por completo de un esquema o estructura de datos predefinidos.
  • • Los datos se introducen en formato JSON de JavaScript, las consultas se escriben en JavaScript y los datos son devueltos en JSON.
  • • Admite aplicaciones móviles y web (CouchDB se puede usar offline en el background de las aplicaciones móviles).
  • • Ideal para acumular y cambiar ocasionalmente datos, sobre los cuales se ejecutarán consultas predefinidas.
MONGODB
  • • Base de datos de documentos de código abierto escrita en C++.
  • • Características tradicionales de NoSQL: formato de JavaScript, almacenamiento de valor/clave, replicación flexible para fragmentación.
  • • Utiliza control de concurrencia de múltiples versiones para mantener la coherencia en transacciones complejas.
  • • Ventajas principales: matrices y documentos integrados que reducen la necesidad de realizar costosos JOINs, esquema dinámico que admite polimorfismo articulado.

Otras BBDDs basadas en almacén de datos de documentos incluyen: Elasticsearch, Couchbase Server, RethinkDB, RavenDB, MarkLogic Server, NeDB, Terrastore, JasDB, RaptorDB, djondb, EJDB, Amisa Server, densodb, SisoDB, ThruDB.

7.3.3. BBDD BASADAS EN GRAFOS

Especializadas en la gestión de datos altamente enlazados mediante la utilización de grafos.

NEO4J
  • • Almacena las relaciones entre objetos mediante una estructura de grafos.
  • • Incluye varios algoritmos para analizar y buscar las relaciones.
  • • El uso de algoritmos de 'gráfico transversal' elimina el problema de perseguir punteros.
  • • Ideal para datos de estilo gráfico interconectados, ricos o complejos.

Otras BBDDs basadas en grafos incluyen: OrientDB, FlockDB, Infinite Graph, DEX, TITAN, InfoGrid, HyperGraphDB, GraphBase, Trinity.

7.3.4. BBDD BASADAS EN CLAVE-VALOR

Las BBDDs trabajan asociando claves con sus valores correspondientes. Algo parecido al mapeo que establecen las estructuras de diccionario. Sus ventajas principales son la eficiencia, rendimiento extremo y el fácil escalado.

REDIS
  • • Base de datos NoSQL de almacenamiento de datos clave-valor en memoria, en red, escrita en ANSI C.
  • • Características clave: rendimiento mejorado a través del almacenamiento en memoria, replicación maestro-esclavo y modelo de datos de diccionario asignados clave a valores.
  • • Proporciona clústeres de etapa alfa en plataformas PaaS e IaaS.
RIAK
  • • Base de datos distribuida y solución de almacenamiento en la nube.
  • • Orientada a ofrecer almacenamiento en la nube a cualquier escala tanto en nubes públicas como privadas.
  • • Proporciona consistencia final a los datos almacenados en una colección de nodos que pueden crecer en cualquier momento.
  • • Las consultas de mapa/reducción en Riak se pueden escribir en Erlang o JavaScript.

Otras BBDDs basadas en clave-valor incluyen: DynamoDB, LevelDB, Aerospike, FoundationDB, Berkeley DB, Oracle NoSQL Database, GenieDB, BangDB, Scalaris.
