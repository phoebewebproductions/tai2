6. BASES DE DATOS ORIENTADAS A OBJETOS

6.1. INTRODUCCIÓN A LAS BDOO

Un sistema de gestión de base de datos orientada a objetos (ODBMS, Object Database Management System) representa la información en forma de objetos, tal y como son utilizados en la programación orientada a objetos.

Podemos realizar la siguiente analogía entre una base de datos relacional y una base de datos orientada a objetos:

Base de datos relacional Ejemplo Relacional Base de datos orientada a objetos Ejemplo BBDD Orientada a Objetos
Tabla Tabla cliente Clase Clase Cliente
Registro Objeto Instancia de Cliente
Insert Crear un objeto de la clase Cliente clienteNuevo = new Cliente()
Update Modificar un objeto Cliente8.nombre="Juan"
Delete Eliminar un objeto
Select Obtener una lista de objetos

Un ODBMS integra las características de las bases de datos con las de un lenguaje de programación orientada a objetos, haciendo que los objetos de la base de datos se mapeen como objetos de los lenguajes de programación orientados a objetos a los que da soporte. A su vez, extiende de forma transparente los lenguajes orientados a objetos con las siguientes características:

  • Trabajar con datos persistentes.
  • Control de concurrencia
  • Recuperación y filtrado de datos
  • Consultas asociativas.

Actualmente los ODBMS trabajan con lenguajes orientados a objetos como Java, C++, C#, Visual Basic.net, Delphi, Ruby, Python, Perl, etc.

El ODMG (Object Database Management Group) es el grupo de trabajo encargado de proporcionar estándares sobre base de datos orientada a objetos.

6.2. CARACTERÍSTICAS DE LAS BDOO

Las principales características de las bases de datos orientadas a objetos se pueden dividir en tres grupos:

6.2.1. MANDATORIAS

Aquellas características que deben estar en la BDOO de forma obligatoria, es decir, los requisitos imprescindibles que el sistema debe tener:

  • Debe soportar objetos complejos.
  • Los objetos deben tener un identificador al margen de los valores de sus atributos.
  • Encapsulación, es decir, los datos e implementación de los métodos están ocultos en los objetos.
  • El esquema de la BDOO tiene un conjunto de clases.
  • Concurrencia.
  • Recuperación.
  • Persistencia y manejador de almacenamiento secundario.
  • Facilidad de consulta.

6.2.2. OPCIONALES

Características que no es necesario incluirlas, pero si la BDOO cuenta con ellas, hará que el sistema sea mejor, entre otras:

  • Herencia múltiple.
  • Diseño de transacciones y versiones.
  • Comprobación de clases e inferencia de la distribución.

6.2.3. ABIERTAS

Características que el diseñador puede implementar y que están relacionadas con la programación.

6.3. CONCEPTOS CLAVE DEL MODELO DE OBJETOS

Las BDOO cuentan con conceptos propios y clave del modelo de objetos, entre los que se encuentran estas propiedades:

  • Encapsulación: Oculta información al resto de objetos, de manera que pueden impedir los conflictos o los accesos incorrectos. Consiste en unir en la clase las variables (características) y los métodos (comportamientos), de manera que solo se tiene una unidad, de la que se conoce su comportamiento, pero no los detalles internos.
  • Herencia: Hace referencia a que los objetos heredan comportamientos dentro de una jerarquía de clases, es decir, una clase se deriva de otra de manera que extiende su funcionalidad. La clase de la que se hereda puede llamarse clase base, clase padre, superclase, clase ancestro, etc. (dependiendo del lenguaje de programación que se esté usando)
  • Polimorfismo: Propiedad que permite que una operación pueda aplicarse a objetos de distinta tipología.

6.4. VENTAJAS Y DESVENTAJAS

6.4.1. VENTAJAS

Entre las principales ventajas con las que cuentan las bases de datos orientadas a objetos tenemos las siguientes:

  • Son las más adecuadas si trabajamos con lenguajes de programación orientados a objetos, puesto que los objetos del código fuente se pueden integrar fácilmente en la base de datos.
  • Permiten manipular conjuntos de datos complejos de manera más rápida, tanto para guardarse como para su consulta. A cada objeto se le asigna de forma automática un código de identificación.
  • Alto nivel de confiabilidad en la ejecución de transacciones ACID, es decir, las transacciones se completan solo cuando no existen conflictos con los datos.
  • Cuentan con un mecanismo de almacenamiento en caché que crea réplicas parciales de la base de datos, lo que mejora su rendimiento.
  • Son capaces de manejar grandes volúmenes de datos.

6.4.2. DESVENTAJAS

  • El uso de las BDOO está poco extendido aún por lo que todavía no hay criterios claros de estandarización.
  • Existe poca documentación sobre los proyectos que las han implementado.

6.5. ESTRUCTURA Y FUNCIONAMIENTO

6.5.1. ESTRUCTURA

La estructura de una base de datos orientada a objetos se basa en encapsular los datos y el código relacionado con cada objeto en una sola unidad. Las interacciones entre los objetos y el resto del sistema se realizan mediante una interfaz que se define mediante un conjunto de mensajes permitidos.

Los objetos están asociados a conjuntos de variables con los datos del objeto, de mensajes a los que responde (con o sin parámetros) y de métodos (que con el código que implementa un mensaje).

La estructura de estas BDOO se diseña a partir de una serie de diagramas:

  • Diagrama de clases: Presenta las clases con sus respectivas relaciones estructurales y de herencia
  • Diagrama de objetos (opcional): Ayuda a clarificar las instancias de las clases.
  • Diagrama de secuencias: Presenta las interacciones entre los objetos organizados en una secuencia temporal y describe cómo colaboran.
  • Diagrama de estado: Muestra los posibles estados en los que pueden estar un objeto y las transacciones que pueden realizar.

6.5.2. FUNCIONAMIENTO

La base de datos orientada a objetos se fundamenta en agrupar la información en paquetes relacionados entre sí.

  • Los datos de cada registro se combinan en un solo objeto y a su vez se incluyen todos sus atributos.
  • A diferencia de lo que ocurre con la distribución en tablas de otras bases de datos, en las BDOO toda la información está disponible en el objeto y no repartida en filas y columnas.
  • Los métodos, es decir el conjunto de acciones que pueden llevarse a cabo en cada objeto, también se pueden agrupar.
  • Los objetos a su vez se dividen en clases, creando así una jerarquía de clases y subclases, en la que las subclases heredan las propiedades de las clases superiores y las complementan con sus propios atributos.
  • Esta jerarquía no es estricta, puesto que los objetos de una clase pueden relacionarse con otras clases, formando redes.
  • Los objetos simples pueden combinarse para crear objetos más complejos.
  • El sistema de gestión de base de datos orientadas a objetos asigna de forma automática un código de identificación único e inmutable a cada registro, permitiendo así recuperar los objetos cuando estos se han guardado y realizar consultas.
  • En estas bases de datos, los objetos tienen relaciones de varios a varios, en las que los indicadores son los encargados de establecer dichas relaciones entre objetos.
  • Las BDOO no emplean lenguaje SQL, sino lenguajes de programación.

6.6. CARACTERÍSTICAS ADICIONALES

  • La mayoría de bases de datos orientadas a objetos incluyen algún tipo de lenguaje para realizar consultas, lo cual permite que los objetos sean encontrados utilizando un enfoque de programación declarativa.
  • En una base de datos orientada a objetos, el acceso a los datos es más rápido debido a que los Joins casi nunca son necesarios, a diferencia de lo que ocurre con las bases de datos relacionales. Un objeto puede ser recuperado directamente sin una búsqueda, simplemente siguiendo los punteros.
  • Un área en la que los diferentes productos pueden variar es la forma en la que el esquema de la base de datos es definido. Sin embargo, una característica general es que el lenguaje de programación y el esquema de la base de datos utilizan la misma definición de tipos.
  • Las aplicaciones multimedia se agilizan debido a que los métodos de clase asociados con los datos son responsables de una correcta interpretación.
  • Muchas bases de datos orientadas a objetos ofrecen soporte para control de versiones. Un objeto puede ser visto como un conjunto de todas sus versiones. También las versiones de objetos pueden ser tratadas como objetos por derecho propio.
  • Algunas bases de datos orientadas a objetos también proporcionan soporte sistemático para triggers y restricciones.
  • La eficiencia de una base de datos orientada a objetos también ha mejorado considerablemente en áreas en las cuales se requieren cantidades masivas de datos sobre un elemento. Por ejemplo, una entidad bancaria podría obtener la información de la cuenta de un usuario y proporcionarle eficientemente información muy extensa conteniendo todas las transacciones, todas las entradas con información de la cuenta, etc.
  • Una base de datos orientada a objetos almacena datos complejos y relaciones entre datos directamente, sin asignar filas y columnas, y esto hace que sean más adecuadas para aplicaciones que tratan con datos muy complejos.
  • Otro beneficio adicional de una base de datos orientada a objetos es que puede ser programada con pequeñas diferencias de procedimientos sin afectar a todo el sistema.
