2.1 MODELO RELACIONAL

🗃️

El modelo relacional para el modelado y la gestión de bases de datos es un modelo de datos basado en la lógica de predicados, el álgebra relacional y la teoría de conjuntos. Fue propuesto por E.F Codd en los laboratorios de IBM en California y actualmente es el modelo más utilizado para modelar problemas reales y administrar datos dinámicamente.

2.1.1. CONCEPTOS

Se basa en el concepto matemático de Relación. Una relación R, de n conjuntos, es un subconjunto del producto cartesiano de los conjuntos A1, A2, A3, …., An

Estas relaciones son consideradas en forma lógica como conjuntos de datos llamados tuplas. Habitualmente es más fácil entender el concepto de relación equiparándolo a una tabla compuesta por registros donde:

📋
Tupla: Cada fila de la tabla (también llamado registro)
📊
Campos: Las columnas de la tabla.

2.1.2 TABLA O RELACIÓN: ATRIBUTOS Y DOMINIOS

  • 📑 Una tabla o relación es una matriz rectangular que almacena líneas con una estructura determinada.
  • 🔝 La primera fila de una tabla no se considera una tupla. Nos marca la estructura de la tabla mediante la definición de las columnas o atributos que la componen.
  • 🔢 Cada atributo tiene un dominio de valores que puede aceptar (tipo de datos) y debe ser atómico.
  • 📝 El resto de filas de la tabla o relación es un conjunto de tuplas donde cada una de ellas corresponde a un registro de la tabla.
  • 📄 Cada tupla corresponde a la descripción de una entidad particular o a la descripción de una relación particular entre varias entidades particulares.
  • 📏 El grado de una tabla es el número de campos que posee. Es independiente del momento de observación de la tabla (salvo que se modifique)
  • 🔢 La cardinalidad es el número de tuplas que almacena. No es independiente del momento de observación

2.1.3 RESTRICCIONES

  • 🔍 Cada atributo debe tomar un valor perteneciente a su dominio asociado.
  • 🚫 No se permite la repetición de tuplas en una misma tabla.
  • 🔀 Las tuplas no tienen un orden determinado.
  • 🔑 Cada tabla debe contener una clave principal o primaria (PK: Primary Key)
  • 🆔 Una clave principal es un atributo o conjunto de atributos cuyo valor es único y diferente en cada tupla.
  • 🔑 Una clave candidata es un atributo o conjunto de atributos que cumple las condiciones para ser clave principal. Generalmente una tabla puede tener varias claves candidatas aunque sólo se elige una como clave principal.
  • 🔗 Una clave foránea (FK: Foreign Key) o clave ajena es una columna o conjunto de columnas que es clave principal en una tabla relacionada.

La clave principal se suele representar en negrita, subrayada o con el icono de una llave (key) a la izquierda

2.1.3.1. REGLA DE INTEGRIDAD DE ENTIDAD

Incluye dos reglas:

🔒
Regla de integridad de unicidad de la clave primaria: La clave primaria elegida para una relación no debe tener valores repetidos. Si la clave primaria es compuesta, la combinación de campos también debe ser única.
⛔
Regla de integridad de entidad no nula: La clave primaria de una relación no puede contener valores nulos.

Integridad de entidad: Si la clave primaria es compuesta, ningún campo de la combinación puede ser nulo.

2.1.3.2. REGLA DE INTEGRIDAD REFERENCIAL

Está relacionada con el concepto de clave foránea.

Todos los valores que toma una clave foránea deben ser valores nulos o valores que existen en la clave primaria referenciada.

Si la clave primaria es compuesta, la clave primaria compuesta referenciada debe existir

2.1.4. REGLA DE INTEGRIDAD DE DOMINIO

Establece la validez de las restricciones que debe cumplir una determinada columna de la tabla.

📝
Datos Requeridos: establece que una columna tenga un valor no NULL. Se define efectuando la declaración de una columna es NOT NULL cuando la tabla que contiene las columnas se crea por primera vez, como parte de la sentencia CREATE TABLE.
✅
Chequeo de Validez: cuando se crea una tabla cada columna tiene un tipo de datos y el DBMS asegura que solamente los datos del tipo especificado sean ingresados en la tabla

2.1.5 RESTRICCIONES DE LA BASE DE DATOS

  • 🔍
    Restricciones de atributo: Permiten acotar los valores del dominio de un atributo. Por ejemplo el dominio del atributo Fecha de nacimiento puede ser una fecha válida, pero en la base de datos puede no tener sentido que la fecha sea anterior al 1900 o posterior al día de la fecha. A su vez el descuento de un producto no puede ser superior al 100%.
  • 📋
    Restricciones de tupla: Permiten comprobar que los valores de algunos atributos de una misma tupla son consistentes entre sí. Por ejemplo si el cliente ha puesto que no tiene niños a su cargo no puede solicitar la ayuda para guardería
  • 📑
    Restricciones de tabla: Establecen restricciones que engloban a todas o parte de las tuplas de una misma tabla. Por ejemplo en una tabla que almacenase los encuentros de una liga se debería evitar que un mismo equipo jugase contra dos equipos contrarios el mismo día en dos lugares distintos.
  • 🗃️
    Restricciones de base de datos: Establecen restricciones que engloban a todas o parte de las tuplas de una o distintas tablas de la misma base de datos. Por ejemplo, no debemos anotar un pedido en la tabla de pedidos si un producto comprado está agotado en la tabla de inventario.
  • 👤
    Restricciones de usuario: Suelen realizarse a través de permisos de usuario sobre las tablas.
